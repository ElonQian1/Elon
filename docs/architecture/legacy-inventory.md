# Legacy 代码清单

本清单将“仍在使用的兼容实现”和“可以退役的历史实现”分开。没有完成入口、调用、数据和回滚审计前，不得批量删除。

## 当前仍有运行责任的代码

| 路径/入口 | 责任 | 当前状态 | 处理原则 |
|---|---|---|---|
| `server/src/assets/web_page.html` | 移动 Web/PWA 壳和移动端页面 | 仍在 `/`、`/web` 使用 | 只在移动 Web 任务中修改 |
| `server/src/assets/project_plaza.js/css` | 移动 Web 项目广场 | 仍由移动 Web 壳加载 | 等移动 Web 功能对照完成后再退役 |
| `server/src/assets/project_home.js/css` | 移动 Web 项目页 | 仍由移动 Web 壳加载 | 同上 |
| `android/` | Android 原生客户端 | 生产客户端 | 不作为旧代码删除 |
| `server/src/*_migration.rs` | 数据库/协议兼容迁移 | 可能影响存量数据 | 迁移完成并验证后再清理 |

## 已退出主路径的代码

| 路径/入口 | 状态 | 处理原则 |
|---|---|---|
| 旧 `server/src/assets/pc_*.html/js/css` | 源码已删除 | 不恢复，不新增同名实现 |
| `/pc-legacy` | 发布时从历史提交生成只读快照 | 只保留回退周期，之后单独下线 |
| `/pc-next` | 新 PC 的兼容别名 | 不视为第二套前端，最终可在兼容周期后移除 |

## 退役条件

某项 legacy 代码只有同时满足以下条件才能删除：

1. 新入口功能对照表为完成。
2. 新入口有自动化测试和至少一次用户可见验收。
3. 服务端路由、前端引用、Android 合约测试和发布脚本不再依赖它。
4. 线上访问/错误日志确认没有有效用户依赖。
5. 已保留可回滚的发布产物和数据库恢复方案。
6. 删除后完成全量构建、端到端冒烟和回退演练。
