# 社交聊天三端能力整改方案

## 目标与根因

用户希望 Windows 群聊和私聊可以像完整社交聊天软件一样完成日常消息操作。对照真实源码，APK 的 MainActionPopups、MainFriendChatActions、MainGroupChatActions 已连接许多社交动作；Windows FriendsPage 仍复用 AI MessageActions，缺少社交动作编排和附件发送。群聊编辑审计已发布，但独立内联按钮缺少统一右键入口。此差异源于客户端能力覆盖不齐，不是 Windows 平台不支持。

APK 也不是全部完备：提醒、从当前听为占位；群聊“删除”实际调用撤回；引用是 Markdown 文本；收藏为本地存储。不得把占位当作已完成能力照搬。

## 能力矩阵与优先级

| 能力 | 当前事实 | 本轮交付 | 后续协议工作 |
|---|---|---|---|
| 消息菜单 | APK 长按；Win 使用 AI 操作栏 | 右键、键盘与常显更多；社交菜单 | 三端合同回归防漂移 |
| 引用 | APK 插入短文本引用；后端无 reply_to | 保留现有草稿，带作者、版本的可读引用预览与取消，发送为兼容 Markdown | 稳定消息 ID、被引用版本快照、跨端跳转原文 |
| 编辑/修改记录 | 群聊已有审计 API，私聊无 | 群聊菜单入口及已编辑标记，复用完整历史和冲突检查 | 私聊追加式修订表与统一接口 |
| 撤回 | 两类消息均有 API，服务端窗口 60 秒 | 仅本人且时限内可撤回，确认后执行；服务端最终裁决 | 统一各端文案及可配置规则 |
| 删除/隐藏 | APK 社交删除其实是撤回 | 明确“仅本机隐藏”，可恢复；不调用撤回 API | 按用户隐藏状态跨设备同步 |
| 转发/多选 | APK 可转发正文/附件 | 选择目标、预览确认、顺序发送，成功项不重复重试 | 服务端批量幂等及出处结构 |
| 收藏 | APK 为本机收藏 | 本机收藏、列表、取消，账号隔离及退出清理 | 服务端收藏同步、撤回可见性规范 |
| 图片/语音/文件 | Win 已可接收浏览，但不能上传 | 选择/粘贴/拖入附件，上传阶段及失败保留；音频文件发送 | 原生录音权限、编解码及设备验收 |
| 群成员 @ | APK 使用成员目录和 @名字 文本 | 成员目录选择与 @发送者，复用相同语法 | 稳定成员 ID 的结构化提及 |
| 查找与总结 | 群检索、总结 API 已有 | 当前消息过滤、群历史检索、置顶总结暗色查看 | 私聊完整历史搜索、游标分页 |
| 可靠性 | 前轮已发布缓存/超时/恢复同步 | 保留原能力；切换不串消息/附件；操作失败可恢复 | 服务端 client_message_id 去重和持久发件箱 |

## 本轮操作与数据规则

- 私聊和群聊共用操作模型，群聊编辑保持原作者、历史、附件及服务器 revision 约束。不能编辑他人、待发、已撤回或文章/项目专用卡片。
- 菜单必须支持可发现的按钮、右键、Esc、方向键和焦点返回；表单/弹窗沿用暗色样式。不要向真人聊天展示 AI 点赞/点踩或重新生成按钮。
- 引用不覆盖用户已写草稿；引用是当时文字的兼容快照，注明作者与版本。新协议发布前不宣称点击能定位完整历史原文。
- 转发是新的消息，明确目标和来源；不自动发送给任何人。多选有上限，部分成功后只处理未发送项；结果不假装全成功。
- 撤回与本机隐藏必须分开。隐藏不改变服务端或其他成员消息，可在本机恢复。已撤回消息不再提供引用、转发或正文收藏。
- 收藏和隐藏按服务地址、一龙账号隔离，数量有界；存储异常给出可恢复反馈；退出清理。收藏不宣称跨设备同步。
- 附件使用手机既有 chat-attachments 端点，不滥用项目附件。最多六个、每个不超过 12 MiB；发送采用结构化附件，上传/发送失败保留待发信息，切换会话不会把附件发给别的会话。
- 群目录、群检索与总结来自服务器，错误/权限拒绝可见。查找已加载私聊时必须标注范围，不伪装全历史搜索。
- 本轮不改 APK、后端数据库、群 AI 模型设置或并行文章系统。文章卡片专用编辑/复制边界必须保留。

## 验收和发布

真实 React 浏览器交互验证：本人/他人/撤回/待发/卡片权限，菜单键盘和边缘定位，引用与草稿，编辑冲突及历史，撤回失败，多选转发部分失败，收藏与隐藏恢复，附件选择/粘贴/拖入/上传失败，切换隔离，群目录/查找/总结，窄窗暗色布局。所有测试用隔离数据和拦截接口，不写生产聊天。

保留前轮缓存/同步、媒体、编辑审计、文章卡片回归；通过 TypeScript、变更范围 lint、生产构建及资源门禁。发布只走正式 PC 前端入口，最终提交含方案和证据再发布，并直接执行 PcFrontend 收尾；发布后不追加未部署的回执提交。

## 后续纵向切片的完成条件

1. 私聊编辑审计：原文和每次修订追加保存，作者与会话权限校验、revision 冲突、撤回边界、三端历史界面与迁移测试同时交付。
2. 引用与历史：消息 ID + 游标分页 + reply_to_revision 快照；引用源被撤回时按统一规则显示，不能把引用当作当前原文；跨端返回同一结果。
3. 离线发件箱：客户端生成稳定 ID，服务端唯一约束去重，确认状态区分发送中/已确认/结果待确认；自动重试必须使用同一 ID，不能重发为新消息。
4. 云收藏/隐藏：每用户隔离的服务端记录、分页、同步版本和退出清理；明确删除本机与删除收藏的不同语义。
5. 原生语音：Windows 设备枚举、授权、录音取消、音频上传与播放闭环；不能为录音降低 HTTPS/浏览器安全设置。语音/视频通话、免打扰、举报与群治理按独立需求接入，并分别测试权限及系统集成。
