# Windows 客户端 Defender 误报处理

## 现象

Windows 安全中心可能把一龙 Win 端报告为 `Behavior:Win32/Persistence.A!ml`，并隔离 `%LOCALAPPDATA%\ElonNode\一龙开发平台.exe`。这不是网页端访问地址被普通网络拦截，而是 Defender 的机器学习规则认为客户端安装和修复行为像“持久化”。

浏览器显示“已阻止不安全的下载”是另一类问题：HTTPS 页面跳转到 HTTP 下载地址时，即使文件本身没有病毒、即使把 ZIP 换成 EXE，也可能被浏览器拦截。公开下载必须使用浏览器信任的 HTTPS 证书；自签名 HTTPS 只适合已经统一下发根证书的受管内网电脑，不适合普通公网用户。HTTPS 解决传输来源问题，受信任的 Authenticode 代码签名解决 Windows 的“未知发布者”与 SmartScreen 信誉问题，两者不能互相替代。

## 用户侧处理

如果用户确认下载来源是官方一龙地址，可以在 Windows 安全中心的保护历史记录里只还原或允许这一个 `一龙开发平台.exe` 文件，然后重新打开 `http://127.0.0.1:7799/api/status` 检查本机接口。

不要默认建议用户把整个 `%LOCALAPPDATA%\ElonNode` 目录加入白名单；目录白名单会扩大风险面。

## 产品侧处理原则

- 开机自动守护保留“开机就能用”的体验，但必须有一次明确授权：首次安装、首次进入 PC 工作台或节点设置页让用户开启。
- 自启动注册使用当前用户计划任务启动安装目录中的 `一龙开发平台.exe --watchdog`，不再把主路径写入 `HKCU\...\Run`。
- 安装和修复不会在未开启时新增自启动；如果用户已经开启过，修复只会保留并迁移为当前用户计划任务。
- 修复客户端入口只恢复主程序、卸载程序、开始菜单和网页唤起协议。
- 发布清单写入 SHA256；客户端下载更新包后先校验哈希，再替换本地文件。
- 首次安装入口发布单文件 `Elon-Windows-Setup.exe`；ZIP 只保留为客户端自动更新载荷。
- 正式发行需要代码签名证书，并向 Microsoft Security Intelligence 提交误报样本。

## 自启动产品口径

不要把“避免 Defender 误报”解释成“用户以后都要手动启动”。正确口径是：

1. 用户开启一次“开机守护”后，Windows 登录时会由当前用户计划任务拉起后台 watchdog。
2. watchdog 只负责恢复本机节点和本地 `/pc` 管理接口，不主动打开浏览器标签。
3. 修复和更新只保留已有选择，不借修复流程静默创建新的持久化入口。
4. 旧版 `Run` Key 或旧计划任务会在修复/更新时迁移到当前用户计划任务。

## 客服排查口径

1. 确认报毒名称是否为 `Behavior:Win32/Persistence.A!ml`。
2. 确认受影响文件是否为 `%LOCALAPPDATA%\ElonNode\一龙开发平台.exe`。
3. 让用户只还原该文件，不白名单整个目录。
4. 让用户重新检测本机接口或导出诊断文件。
