# 多 AI 代理并行开发——防冲突工作流说明

## 背景与挑战

本项目同一台 PC 上同时运行多个 AI 代理（Copilot、Claude 等），它们会并发修改同一个 Git 仓库。如果没有规则约束，极易发生：

- A 代理的未提交改动被 B 代理的构建打包进去
- 两个代理同时写 versionCode，互相覆盖
- 某代理直接在主工作区构建，导致 `git status` 污染

下面的规则体系用来解决这些问题。

---

## 一、三大核心原则

| 原则 | 含义 |
|---|---|
| **先 pull 再改** | 每次任务开始必须 `git pull --rebase`，避免 push 时冲突 |
| **commit 即 push** | 每次 commit 后立即 push，永不在本地堆积 commit |
| **构建必须隔离** | 编译/打包只在「临时工作树」或发布脚本内进行，不污染主工作区 |

---

## 二、任务开始——状态检查决策树

每个 AI 代理接到任务后，**动代码前**强制执行：

```powershell
cd d:\rust\active-projects\bb64a
git pull --rebase origin master
git status --short
```

根据结果走不同路径：

```
git status --short
        │
        ├─ 干净（无改动）─────────────────────► ✅ 主工作区直接改代码
        │
        ├─ 只有本 AI 自己已改的文件────────────► ✅ 继续，提交时只 add 自己的文件
        │
        └─ 有【其他 AI】未提交的改动──────────► ⚠️ 必须创建独立工作树（见第三节）
```

---

## 三、并发隔离——独立工作树方案

当检测到主工作区已有其他代理的未提交文件时，**禁止**在主工作区继续改代码，而是：

```powershell
# 1. 创建本会话专属工作树（基于 master 最新提交）
git worktree add ..\bb64a-session-<id> -b ai/session-<id> master

# 2. 在独立工作树中修改代码（完全隔离，不干扰主工作区）
Set-Location ..\bb64a-session-<id>
# ... 修改文件 ...

# 3. 提交本会话的改动
git add -p   # 按 hunk 精确挑选，不夹带他人改动
git commit -m "feat(session-<id>): 描述"

# 4. 回到主仓库 cherry-pick 集成，然后 push
Set-Location ..\bb64a
git cherry-pick <session_commit_sha>
git push origin master
```

**为什么用独立工作树而不是新分支？**  
因为 `git add -p` 只能按 hunk 粒度选择，当两个代理的改动在同一文件同一区域时无法安全拆分。独立工作树从文件系统层面彻底隔离，是唯一可靠方案。

---

## 四、构建部署——临时工作树隔离

代码提交到远程后，**编译和部署步骤必须在临时工作树中进行**，原因是：

- 避免构建产物（`target/`、`build/` 等）污染主工作区的 `git status`
- 确保构建基于明确的 commit SHA，不含任何未提交改动
- 多个代理可以同时用不同 SHA 创建各自的临时工作树并行构建

```powershell
# 提交后获取 SHA，创建临时工作树
$sha = git rev-parse --short HEAD
$tmp = "..\bb64a-deploy-temp-$sha"
git worktree add --detach $tmp HEAD   # detached HEAD，不创建新分支

# 在临时工作树里编译（例如后端）
Push-Location "$tmp\backend"
cargo zigbuild --release --target x86_64-unknown-linux-musl
Pop-Location

# 部署完成后必须清理
git worktree remove $tmp --force
```

> **例外**：`bb64a-build-windows` 是持久工作树（保留增量编译缓存），**禁止手动删除**。

## 五、Android 版本号——脚本原子递增

Android 的 `versionCode` 是整数，必须全局单调递增，多代理并发时最容易冲突。解决方案：

**由 publish-apk.ps1 脚本负责自动 +1**，流程如下：

```
代理 A 提交代码改动 (commit #1)
    └─► 运行 publish-apk.ps1
            ├─ 读取当前 versionCode（比如 42）
            ├─ 写入 build.gradle.kts: versionCode = 43
            ├─ 编译 + 打包 + 上传 APK
            └─ 提交版本号变动 (commit #2) → push
```

**并发冲突防护**：  
若代理 A 和代理 B 同时运行发布脚本，后 push 的一方会收到 `non-fast-forward` 错误。  
**正确做法**：`git pull --rebase` → **再次运行** publish-apk.ps1（重新 +1），不允许 `git push --force`。

```
代理 A: versionCode 42 → 43, push 成功
代理 B: versionCode 42 → 43, push 被拒 (non-fast-forward)
  ↓
代理 B: git pull --rebase → 再次运行脚本 → versionCode 43 → 44, push 成功
```

## 六、完整流程图（一次典型任务）

```
任务开始
  │
  ├─ git pull --rebase
  ├─ git status --short
  │       │
  │       ├─ 干净 ──────► 主工作区改代码
  │       └─ 有他人改动 ─► 创建 session 工作树改代码
  │
  ├─ 修改代码
  ├─ rustfmt（仅本次改动的 .rs 文件）
  ├─ git add（仅自己的文件）
  ├─ git commit
  ├─ git push origin master    ◄── 必须立即 push
  │
  ├─ [后端/前端] 创建 deploy-temp-$sha 工作树
  │       ├─ 编译
  │       ├─ scp 上传
  │       ├─ ssh 重启服务
  │       ├─ 验证健康检查
  │       └─ git worktree remove 清理
  │
  └─ [Android] 运行 publish-apk.ps1（主工作区）
          ├─ versionCode +1
          ├─ 编译 Rust + Kotlin → APK
          ├─ scp 上传 + 生成 version.json
          └─ git commit + push 版本号变动
```

## 七、任务结束清理（防残档）

每次会话结束前必须确认：

```powershell
# 1. 临时工作树已全部清理
git worktree list
# 不应出现 bb64a-session-* 或 bb64a-deploy-*

# 2. 临时分支已删除
git branch -a | Select-String "session|copilot"
# 应为空

# 3. 清理遗留终端进程（防止内存泄漏）
$selfPid = $PID
Get-WmiObject Win32_Process -Filter "Name='pwsh.exe'" |
  Where-Object { $_.CommandLine -match '-noexit' -and $_.ProcessId -ne $selfPid } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force -ErrorAction SilentlyContinue }
```

## 八、关键规则速查

| 规则 | 原因 |
|---|---|
| 任务前必须 `git pull --rebase` | 避免 push 时遇到 non-fast-forward |
| 有他人未提交改动→独立工作树 | 文件级隔离，防止 add 时夹带无关改动 |
| 构建必须在临时工作树 | 防止构建产物污染主工作区 |
| commit 后立即 push | 本地 commit = 无备份，磁盘故障即丢失 |
| Android 并发发布失败→重新运行脚本 | 脚本会再次 +1，保证 versionCode 单调递增 |
| 禁止 `git push --force` | 会覆盖他人已推送的提交 |
| 禁止 `cargo fmt`（无参数） | 会格式化 486+ 历史文件，产生大量无关 diff |
