# ESK 正式额度与卖回进度跨 APK 只读交付 V1

## 用户目标与当前基线

用户在独立量化 APK 发起查看，经主 APK 当前账户逐次明确同意，看到本次账户的正式
ESK 总量、卖回占用、可申请量和一页卖回申请进度。用户能分辨数据来源和是否兑付。
主项目已经具备正式卖回账本及原生页面；量化旧正式协议只显示总量/登记笔数。
本功能补齐跨 APK 只读展示，不重复实现后端或替换既有账本。
2026-09-05 用户明确取消旧版兼容要求：新版是量化唯一原生 ESK 入口，退役旧
Paper 17 字段及正式总量 21 字段的原生跨 APK 提供端、消费者和专属代码。
旧包不再受支持；旧包/历史提交仅作发布溯源，不作为用户回退方案。

运行依赖：[正式卖回需求](esk-platform-sellback-requests-v1.md)。
[旧正式提供端](esk-platform-native-provider-v1.md)仅为历史参考，不是新版运行依赖。
跨仓合同见 [Android 进度协议](../contracts/esk-platform-android-progress-v1.md)。
量化独立仓库中的同名需求和字节一致的 Kotlin 合同共同约束消费者。

## 范围与授权

- 主端只读已有本人 `GET /api/me/assets/esk/platform/sellback-requests?limit=20`；
  cursor 非空时仅追加已验证的原游标。一次响应提供同快照额度、计数和申请页。
- 主提供端为独立显式 Activity，官方量化包、当前单签、最低版本 5、精确非别名
  `com.elon.quant.assets.progress.EskPlatformProgressActivity` 才能调用。
- 主当前登录账户在安全连接检查后读取，每页显示账户并明确确认；会话替换、退出、
  到期、遮挡触摸、后台、旋转、重复或迟到响应全部取消并清理。
- 保持既有 HTTPS-before-token 私有读取边界；公共主 HTTP 不改、无凭据降级和网页代理。
- 量化只显示“本次主项目确认账户”，不绑定量化网页登录身份；无持久化或跨页拼接。
- 量化每次首页/下一页请求先清旧显示，使用新随机 nonce；主端每页重新明确同意。
  游标或快照失效只提示重新发起首页，绝不自动去掉游标重试。
- 120 秒请求窗口、最长 60 秒显示，主会话剩余有效期更短时进一步缩短。

## 展示与数据边界

- 总量、占用、可申请量均为规范六位 ESK 数量及精确微单位，满足总量=占用+可申请量。
- 显示总申请数、未取消数和本页范围；最多 20 条，逐条仅投影申请 ID、金额、状态、
  创建/取消时间。状态限 `submitted` / `canceled`；明确“已提交/已取消，未兑付”。
- 页面标注正式平台登记、尚未上链、非模拟、非实时临时摘要；零必须来自有效响应。
- “可申请量”不是可提现金额，不承诺价格、回报、兑付时间或保本。没有兑换、
  订阅、提交、取消、支付、签名或迁移操作；全部跨 APK 写能力为 false。
- 不传账户标识、昵称、登录凭据、付款证明、幂等键、政策正文、政策写摘要、
  原始 HTTP JSON 或写请求。不得进入 WebView、日志、剪贴板、磁盘、saved state。
- 原生同意/身份验证不可在网页模拟；网页正式资产入口继续现有独立登录与私有读取。
  本功能不更改共享页面布局或主题，不新增网页财务授权弹窗。

## 新版替换与模块边界

- 不保留旧 Paper 17 / 正式 21 字段原生接口、组件或别名；测试以固定旧载荷验证
  新版拒绝旧协议，不为运行这些测试保留旧生产实现。
- 量化只保留“我的 ESK”原生入口，展示正式总量、占用、可申请量和申请进度。
  旧正式页的审核登记笔数及完整审核历史仍在主个人资产页，申请数不得冒充登记数。
  Paper 模拟跨 APK 展示被主动退役，不迁移、混算或删除 Paper 账本。
- 主个人正式资产、登记历史、申请/取消、会话组件以及所有后端账本、公共行情和
  Paper 研究功能保持原样；删除仅限审计确认的旧原生桥、消费页面和专属资源。
- 新 `yilong.esk.platform_android_progress.v1` 使用独立 action、组件和纯 Kotlin 合同。
  Map 合同不冒充 OS 身份、实际 Bundle 类型、用户同意或会话验证。
- 主模块分 Caller/Wire/ConsentActivity/View；复用 SessionStore/RequestGate 和严格
  SellbackClient.page/parser。量化独立 Identity/Wire/Session/Activity/View。
- 主 APK 和量化 APK 分别验证、提交、发布；量化不得使用主发布脚本。
  主最低可用版本在正式分配版本后写入量化；不得伪造工件来源或上传回执。

## 验收标准

1. 从量化可见入口进入正式进度页，显式主账户确认后展示同快照额度与真实申请页。
2. 严格字段/类型/大小/精度/数值守恒、时间、排序、重复、范围和 cursor 绑定回归通过；
   未知来源、额外字段、21 条、溢出、过期和旧协议不能进入显示。
3. 逐页清空、不拼接、nonce 一次性、409 不自动退页、A→B→A 会话替换、生命周期、
   当前官方签名和精确组件身份校验分别有证据；无真实数据进入测试。
4. HTTP 在凭据读取之前拒绝；只调用 GET page，不扩展财务政策或真实余额。
5. 两仓新版共享合同及测试逐字节相同；旧组件/别名/入口不存在，旧载荷仍被拒绝。
   以源码缺席断言和构建证明退役，构建与发布来源可追溯。
6. 代码、离线/集成验证、主发布、子发布、真实双 APK 本人验收分轴记录；未具备
   安全连接/合法发布凭据/本人数据的环节明示待验收，不宣称用户已可用。
