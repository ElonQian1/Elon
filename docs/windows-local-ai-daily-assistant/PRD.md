# Windows 本地 AI 工作日报助手 MVP PRD

最后更新：2026-07-09

## 1. 结论

MVP 先做“本地个人工作记录 + AI 日报生成”，不做团队版、云同步、老板后台或强监控能力。

这个边界最稳妥：能验证用户是否真的愿意让工具帮自己写日报，同时把隐私、合规、开发量和发布风险压到最低。

## 2. 背景

很多人的日报难点不是不会写，而是工作过程太碎：

- 上午写代码，下午开会，中间穿插微信、浏览器、文档、终端。
- 到下班时只能凭记忆补日报，容易漏掉细节。
- 直接上监控软件又会让用户有被监视感。

本项目要做的是“用户自己的工作记忆助手”，不是公司监控系统。工具只服务本机用户，默认所有记录由用户本人查看、修正和导出。

## 3. 目标用户

MVP 目标用户：

- 程序员、产品经理、运营、设计、自由职业者。
- 需要每天提交日报、周报或项目进展记录的人。
- 愿意在本机授权截图，但要求可暂停、可排除隐私应用的人。

暂不服务：

- 公司管理员远程查看员工屏幕。
- 多人团队考勤统计。
- 强审计、强合规行业。

## 4. 核心用户故事

### 4.1 自动记录工作

作为用户，我希望打开工具后，它能在后台定时记录我的工作状态，这样我不需要手动记每件小事。

验收标准：

- 用户可以设置截图间隔：30 秒、1 分钟、5 分钟。
- 用户可以随时暂停和恢复记录。
- 用户可以看到当前是否正在记录。
- 用户可以设置不记录的应用，例如微信、密码管理器、银行、浏览器隐私窗口。

### 4.2 前台应用记录

作为用户，我希望工具知道我当时主要在用哪个应用，这样 AI 不只靠截图猜。

验收标准：

- 每次采集同时记录前台应用名称。
- 每次采集同时记录窗口标题。
- 应用切换后可以统计应用使用时长。
- 无法读取窗口标题时，记录为未知，不影响主流程。

### 4.3 AI 分析工作内容

作为用户，我希望 AI 把截图和应用信息转换成工作事项，而不是保存一堆图片。

验收标准：

- AI 输出包含：时间、应用、工作分类、摘要、置信度、是否可能含隐私。
- 工作分类至少包含：开发、会议、沟通、文档、测试、设计、运维、数据分析、学习、管理、产品、生活/非工作。
- 同一任务连续出现时，系统能合并成一个时间段。
- 低置信度内容需要在时间线上标记，方便用户修正。

### 4.4 时间线查看和修正

作为用户，我希望能看到一天的工作时间线，并能改掉 AI 识别错的地方。

验收标准：

- 按日期展示时间线。
- 每条记录显示时间段、应用、分类、摘要。
- 用户可以编辑摘要、分类、是否计入日报。
- 用户可以删除某条记录。
- 删除记录后，导出的日报不再包含该内容。

### 4.5 Markdown 日报导出

作为用户，我希望一键生成 Markdown 日报，这样可以直接粘贴到飞书、企业微信、Notion 或项目系统里。

验收标准：

- 支持选择日期生成日报。
- 日报包含：今日概览、主要工作、时间线、应用使用统计、待办/风险。
- 支持复制到剪贴板。
- 支持保存为 `.md` 文件。
- 生成前必须允许用户预览和编辑。

## 5. MVP 范围

必须做：

- Windows 桌面端。
- 定时截图。
- 前台应用和窗口标题采集。
- 本地 SQLite 存储。
- AI Vision 分析截图。
- 工作分类和时间线。
- Markdown 日报导出。
- 暂停记录、排除应用、删除记录。
- 隐私提示和首次授权说明。

暂不做：

- macOS 支持。
- 手机端。
- 团队后台。
- 云端同步。
- 自动发日报到企业微信/飞书。
- 录屏。
- 键盘记录。
- 鼠标轨迹记录。
- 远程管理。

## 6. 非目标

本项目不是员工监控软件，不做以下能力：

- 老板远程看员工屏幕。
- 后台静默运行且无法退出。
- 绕过用户授权采集屏幕。
- 记录键盘输入、密码、聊天原文。
- 上传完整截图长期保存。

## 7. 隐私与合规原则

默认原则：

- 用户必须明确知道工具正在记录。
- 用户必须能暂停。
- 用户必须能删除。
- 用户必须能排除应用。
- 默认不做云端同步。
- 截图默认只作为 AI 分析输入，不长期保存原图。

需要在产品界面里明确提示：

- 如果使用云端多模态模型，截图内容会被发送给 AI 服务商分析。
- 排除应用只能降低风险，不能保证所有敏感内容都被自动识别。
- 用户应避免在处理密码、支付、客户隐私、医疗、法律等敏感内容时开启记录。

## 8. 项目影响

如果作为独立项目：

- 不影响一龙 APK。
- 不影响一龙服务器。
- 不影响现有 PC 节点。
- 不影响当前线上用户。
- 可以后续作为一龙平台的“本地工具类子项目”接入。

如果未来并入一龙平台：

- 会影响 PC 节点能力边界。
- 会增加本机权限申请和隐私说明。
- 可能需要新的用户授权协议。
- 可能需要区分“个人本地助手”和“平台任务执行节点”。

## 9. MVP 验收标准

MVP 完成时，应能演示以下闭环：

1. 用户启动 Windows 应用。
2. 用户开启记录。
3. 工具每 1 分钟采集一次截图、应用名、窗口标题。
4. AI 分析截图并生成结构化记录。
5. 用户打开当天时间线。
6. 用户修改一条识别错误的记录。
7. 用户生成并编辑 Markdown 日报。
8. 用户保存或复制日报。
9. 用户可以删除当天所有本地数据。

## 10. 需要负责人拍板的问题

必须拍板：

- MVP 是否只做 Windows。
- AI 模型用云端 API 还是先预留本地模型接口。
- 截图原图是否允许短暂缓存，还是分析后立即删除。
- 是否允许保存缩略图用于用户回看。
- 项目是否完全独立，还是预留一龙平台接入。

推荐决策：

- Windows only。
- 第一版使用云端 Vision API，但保留本地模型接口。
- 原图默认分析后删除。
- 不保存缩略图，先只保存文字化时间线。
- 项目独立开发，后续再接入一龙。
