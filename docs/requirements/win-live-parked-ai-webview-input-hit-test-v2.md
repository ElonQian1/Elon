# Win 活跃后台官方 AI WebView 输入命中隔离 V2

## 用户问题

V1 完全隐藏官方 WebView 后，原生输入框可以获得焦点，但真实发送时官网会话恢复被暂停，
消息被安全回滚到输入框。旧实现保持 WebView 可见又会形成覆盖原生 UI 的透明命中层。

## 目标

- 官方 WebView 后台时保留同一个 WebView2 Profile、页面、脚本与会话实例。
- 后台控制器继续运行，但不得覆盖主窗口任何可见交互区域。
- 原生输入框、“新对话”和其他一龙 UI 可正常点击、输入和发送。
- 用户主动显示官网时恢复原有嵌入区域、尺寸、可见性和焦点。

## 实现约束

- 后台控制器缩为 1×1 物理像素。
- 停放坐标取主窗口当前物理宽高，使该 1×1 控制器位于父窗口可见边界之外。
- 后台保持 `show` 以维持官网脚本和会话恢复；前台 `present` 继续重设正常位置与尺寸。
- 不修改 PWA、Android、聊天布局或官方页面 DOM 适配器。

## 验收标准

1. 静态合同证明后台停放使用父窗口物理边界、1×1 尺寸并保持官网脚本活跃。
2. Win 用户浏览器合同、Rust 定向测试和 PC 生产构建通过。
3. 发布后官方 WebView 不再覆盖原生输入框，测试文字可正常输入。
4. 真实发送后停留在原生聊天 UI，消息不被会话恢复回滚。
5. Google 官方回复可继续同步回原生聊天 UI。
