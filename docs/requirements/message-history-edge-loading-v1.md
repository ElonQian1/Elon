# 聊天顶部自动加载历史消息

用户反馈 APK 上翻到已加载窗口顶部后停住，需要核对 PWA 与 Win。
当前三端只提供手动“加载更早消息”按钮，滚动事件没有触发历史分页。
本修复复用已发布的统一时间线接口，不修改数据库、分页协议或消息窗口上限。

## 范围与验收

- APK、PWA、Win 的好友和群聊：用户向上翻到列表顶部附近时自动取下一页。
- 初次打开和程序恢复阅读位置不自动遍历全部历史；无历史时停止读取。
- 同一页面只允许一个读取请求；轮询/推送不能覆盖已请求的历史页。
- 加载前后保留可见消息身份与相对位置，仍遵守 APK/PWA 150、Win 300 条窗口。
- 保留“加载更早消息”作为手动与无障碍入口；失败保留消息，允许重试。
- 切换会话、关闭页面和切换账号时，旧监听和迟到响应不得操作新会话。
- 真实手势/滚轮、连续翻页、读取中重复触发、失败重试及读取尽头应有回归证据。

## 边界

本次不实现多书签，也不迁移个人 AI/项目频道页面。消息分页是已有能力，
本次修复各客户端的触发、排队和阅读位置维护。上线、装机与真实用户验收分别记录。
