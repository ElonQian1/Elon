# 通用 ERP 蓝图 V1 验收标准

## 蓝图与实例

- 维护者可把一个现有项目登记为官方 ERP 蓝图，并登记不可变版本。
- 商户可基于已发布版本创建独立平台项目实例，而不是共享同一数据库或工作区。
- 维护者可把自己有编辑权的现有商户项目显式纳入实例；登记不会复制、覆盖、改名或清理该项目。
- 系统项目、蓝图维护项目自身、无编辑权限项目和已绑定实例的项目必须拒绝纳入。
- 咖啡店和最小零售实例使用同一蓝图内核，但主题与插件不同。
- 实例只保存私有扩展的标识、版本和边界，不向平台上传源码。
- 蓝图定义使用乐观修订号追加；旧修订不能覆盖新修订。
- 商户能力目录固定到实例版本，新定义只有进入已发布版本后才可用。
- 首个版本发布前，草稿能力只显示为未发布标识，不能被 AI 当作可调用能力。
- 实例配置修改必须由所属商户项目确认，并使用配置修订号防止并发覆盖。
- 完全相同的配置写入不会制造无意义的新修订；配置 MCP 工具必须标记为高风险写操作。

## AI 需求处理

- AI 可检索能力目录并返回直接复用、组合实现、私有扩展或通用候选四类结论。
- 未知需求范围必须被拒绝，不能静默降级为私有扩展。
- 未授权时不得提交需求信号；提交内容经过字段白名单和敏感键检查。
- 相同 `need_key` 按不同商户实例去重，不允许单一商户重复请求制造虚假共识。
- 弱关键词重合不能冒充已有能力；只有强匹配才判定复用或组合。
- AI 只能生成候选提案；只有蓝图维护者能接受提案并创建 Matter。
- 提案 Matter 与提案状态原子关联；重复请求返回同一 Matter。

## 发布与升级

- 发布清单包含 Git 提交、模块版本、能力、迁移、兼容范围和回滚说明。
- 兼容检查能够识别缺失模块、版本不兼容、扩展点移除和私有扩展冲突。
- 只有通过检查的实例可进入准备状态；只有商户项目能采用或回滚。
- 采用前必须确认真实开发、迁移和验证已完成，并记录验证摘要和可选 Git 提交。
- 兼容检查后实例配置发生变化时，旧升级活动必须拒绝采用。
- 回滚恢复原固定版本、主题、启用模块和插件，且前后私有扩展清单一致。

## 接口与界面

- HTTP 和 MCP 均可读取蓝图总览、能力目录并解析需求。
- 受控接口支持登记蓝图/版本/实例、提交信号、维护提案和准备升级。
- PC 工作台提供 ERP 蓝图页，能查看实例、能力、提案和升级状态，不展示密钥或原始经营数据。
- PC 工作台支持结构化追加蓝图定义、商户配置、私有扩展、初始化 Matter 和带证据的升级采用。
- 初始化 Matter 携带当前实例修订的机器合同；执行提示能够读取合同并明确要求的 Artifact 证据。
- 现有项目的物化合同包含 `existing_project` 来源，要求 AI 先盘点能力差异并禁止用空白模板覆盖已有代码。
- 物化状态从 Matter、Assignment 和 Artifact 派生，能区分未规划、待批准、执行中、失败可恢复、待证据、待验收和已验收证据完整等状态。
- 旧合同、失败 Assignment、缺失或不匹配证据必须显示阻塞和恢复动作，不能被标记为已发布。
- 带机器执行合同的 Matter 未经项目成员批准时，直接启动或自动派发必须失败。
- 自动化测试覆盖权限、现有项目纳入、失败不清理、脱敏、去重、版本目录、修订冲突、Matter 幂等、兼容性和完整配置回滚。
