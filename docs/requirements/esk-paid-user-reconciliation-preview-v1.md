# ESK 历史付款与用户映射对账预演 V1

## 已有能力与本轮缺口

现有 [Paper 批量登记](esk-paper-first-user-allocation-operations-v1.md) 已支持服务端
dry-run、用户存在检查、原子提交和幂等重放。本轮不重写该能力；它的输入已经是
用户 ID 与 ESK 数量，不能用来核实付款或阻止同付款更换人工幂等键后的重复登记。

本功能提供独立本地对账预演：把运营提供的付款记录、用途确认、脱敏用户映射、
销售条款和历史付款指纹快照进行一致性检查，输出确定、逐项可追溯的复核清单。
它是 [首批用户路线图](esk-first-user-delivery-roadmap-v1.md) 的历史用户交付切片。

## 合同与算法

- 一个输入文件只对应一个明确的付款来源：namespace、network、USDT 资产定位、
  精度和外部引用编码。付款身份由规范化来源、外部交易/信用记录引用、事件序号
  计算 SHA-256，不含人工 batch ID、行号、用户或数量，因此换批次、改用户和金额
  不能避开同一来源下的重复识别。相同交易的不同转账事件可以独立处理。
- 历史快照绑定相同来源摘要，列明已使用的付款指纹及覆盖完整性。明确的 `as_of`
  是本次预演时间；快照超过 24 小时、不完整、晚于该时间均阻止进入待复核清单。
  日期是输入声明，不是可信时钟证明；任何实际入账须重新取得当前权威快照。
- 用户仅通过脱敏主体到脱敏目标用户的一对一映射，不猜姓名、邮箱、聊天或钱包归属。
  重复主体、一个目标对应多个主体、同付款多行、历史已用付款均明确标出冲突。
- 金额使用十进制字符串和 BigInt；USDT 精度由来源声明（0..18），ESK 固定 6 位。
  ESK 拟登记数量须等于销售批次的精确比例，不能自行假定 1:1、四舍五入或推断价格。
  每条及每用户拟登记 ESK 不得超出主项目 i64 base units 范围。
- 同付款只选一个用途：`esk_purchase`、`service_purchase` 或 `quant_subscription`。
  未确认用途阻止处理；后两者只路由到对应流程，不算入 ESK 拟登记合计。
- 确认状态、披露、同意和审批摘要只做字段与绑定一致性检查，不认证付款、身份、
  条款、签名、准入或审批本身。没有审批或同意仍可预演，但行必须带明确缺口。

## 安全与输出

CLI 只从标准输入读取不超过 1 MiB 的 UTF-8 JSON，不联网、不读环境凭据、不写文件、
不创建用户、余额或链上 claim；拒绝重复 JSON 键、未知字段、过深内容及超过 1000 行。
输入文件和输出不得进入 Git；仓库只提交完全合成 fixture。
输出只包含摘要、行号、来源指纹、脱敏用户及数额，不回显外部付款引用、来源原文
或完整输入；错误为固定代码，不包含原始值。

行状态为 `review_ready`、`blocked`、`routed_elsewhere`。`review_ready` 仅表示
输入在给定快照范围内一致且可人工复核。报告始终为
`funds_moved=false`、`balances_written=false`、`commit_eligible=false`、
`payment_authenticity_verified=false`，不输出现有 Paper 提交接口可直接使用的文件。
批次失败时不会把其他行冒充已入账；成功预演也不是付款验证或发币授权。

## 验收与文件计划

新建 `scripts/esk-paid-reconciliation/` 的合同、付款身份和预演模块（各小于 350 行），
标准输入 CLI、独立离线回归、合成 fixture 和使用手册；旧 API、数据库、APK 不改动。
根代理负责预演与集成测试，独立代理负责严格输入合同和规范化；文件所有权分离。

测试必须覆盖重复事件（批内和历史）、同交易不同事件、大小写/0x 规范化、数量/用户
变化不改变付款键、映射缺失/歧义、用途隔离、成交比例不符、不可整除、精度/溢出、
不完整/过期/来源不符快照、无同意/审批、未知/敏感字段、重复 JSON 键、UTF-8 和
响应脱敏，并确认没有网络或业务写入。旧 ESK 合同测试继续通过。

代码可作为工具切片交付；真实用户数据验收、可信付款来源适配、历史快照导出、
地址证明、正式入账事务与链上分配属于后续独立功能，不靠这一预演自动开放。
