# AI 原生开放商业网络 V1 架构决策

## 决策状态

本决策定义第一版可运行架构。它接受并细化
`open-commerce-network-principles.md`，但不代表长期协议、品牌、支付方式或治理组织已经确定。

## 第一版目标

第一版只证明一条项目级纵向闭环：

```text
项目成员创建商户节点
  → 发布结构化商业能力
  → 调用方发现商户和能力
  → 公开能力直接调用 / 受限能力校验授权
  → 记录幂等调用、计量结果与审计事件
  → 用户在 PC 工作台和 MCP 中看到同一事实
```

第一版成功标准不是商户数量，也不是替代现有平台，而是两个不同调用方可以通过同一契约发现并调用同一商户能力，且权限、计量和审计结果一致。

## 复用一龙现有底座

第一版作为一龙项目的一个领域模块实现，不新建独立服务器：

- 身份：复用一龙账号和 Bearer 会话；
- 项目边界：复用项目成员、角色和编辑权限；
- 存储：复用服务端 SQLite 迁移体系；
- API：复用 Axum 路由和统一错误格式；
- MCP：提供厂商无关的 Streamable HTTP MCP；
- PC：复用项目详情页，增加“开放商业”管理视图；
- 文档：继续由项目知识架构、讨论图和治理视图维护。

## 领域边界

### 商户节点

商户节点是项目拥有和管理的商业身份。第一版保存：

- 展示名称、稳定 slug、简介和公开资料；
- 托管模式；
- 启用状态；
- 所属项目与创建者；
- 创建和更新时间。

一个项目可以管理多个商户节点。商户节点不能跨项目隐式共享写权限。

### 商业能力

能力是 AI 或 App 可以发现和调用的结构化操作。第一版保存：

- 稳定能力键和展示说明；
- `query` 或 `action` 类型；
- `public`、`authorized` 或 `owner_only` 访问级别；
- 输入、输出 JSON Schema；
- 新鲜度、单位价格和币种；
- 第一方处理器类型及其配置；
- 启用状态和版本。

V1 只允许受控的第一方处理器，不允许商户填写任意 URL 后由平台直接请求，以避免 SSRF、密钥泄漏和不可审计执行。

### 授权

授权把一个调用方 App 与商户节点、能力范围、用途和期限绑定。授权必须：

- 由可编辑项目成员创建；
- 使用明确 scope，支持 `*` 或具体能力键；
- 包含用途；
- 可以过期和撤销；
- 撤销后立即阻止新调用；
- 保留审计历史，不物理删除。

### 调用、计量与审计

每次调用必须绑定：

- 调用者用户和 App；
- 商户节点与能力；
- 可选授权；
- 调用幂等键；
- 请求摘要哈希，而不是默认保存原始敏感输入；
- 状态、计量单位、单位价格和金额；
- 时间与失败原因。

第一版只记录微单位价格和应计金额，固定返回
`recorded_not_charged`；不扣用户余额、不向商户分账，也不宣称完成真实结算。

## 访问规则

| 能力级别 | V1 规则 |
|---|---|
| `public` | 已登录调用方可直接调用，仍需审计和限量 |
| `authorized` | 必须提供当前有效、未撤销且 scope 匹配的授权 |
| `owner_only` | 仅商户所属项目的 owner/admin/editor 可调用 |

商户节点和能力的创建、修改、停用以及授权创建/撤销，均要求项目编辑权限。

## API 与 MCP 是同一服务层

HTTP API、MCP 和 PC 工作台必须调用同一服务函数，不能各自实现权限或计量逻辑。这样可以保证：

- PC 看到的能力与 AI 发现的能力一致；
- MCP 不能绕过 HTTP 权限；
- 审计记录不因入口不同而缺失；
- 后续 SDK 只需复用稳定服务契约。

## V1 明确不做

- 不连接或抓取美团、微信、抖音等未授权接口；
- 不保存消费者完整画像或商户完整客户名单；
- 不执行商户提供的任意远程 HTTP；
- 不实现真实支付、退款、清结算或资金托管；
- 不建立公开评价、广告竞价、推荐排名和配送网络；
- 不引入区块链、Filecoin、Arweave 或闲置算力市场；
- 不把静态演示能力描述成实时库存或生产订单能力。

## 向后演进

V1 稳定后按证据推进：

1. 增加经过审核的 POS、库存、预约等连接器；
2. 增加消费者可查看和撤销的授权中心；
3. 接入真实计费预授权、扣款、退款和分账；
4. 开放 SDK、沙盒和第三方处理器认证；
5. 增加多排序器、可信商户目录和争议处理；
6. 网络规模成立后再讨论联邦治理与可选可信存证。
