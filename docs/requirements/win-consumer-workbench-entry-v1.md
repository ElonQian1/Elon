# Windows 消费者工作台入口与恢复 V1

## 用户结果与权威边界

一龙 Windows 客户端面向消费者。正常打开时进入现有 `/ai` 工作台，提供聊天、工作、项目、
消息和账号入口；页面由本机或云端提供，不决定用户进入哪一种产品界面。

本合同取代 [Win 本地模式生产 AI 入口 V1](win-local-mode-production-ai-entry-v1.md)
中“根路由默认本机任务”及本机开发工具占主导航的决定。旧文档保留其发布历史；现有
`AiHomePage`、`AiChatPage`、官网会话、缓存和消息渲染链路继续复用，不创建第二套聊天产品。

用户明确要求：右侧“全站用户”保持默认展开，不因本次改造默认折叠或删除。
本合同只约束 Windows/PC 工作台，不引入 Android/PWA 移动设计规范。

## 入口与状态

| 场景 | 必须呈现的行为 |
|---|---|
| 普通冷启动、重复打开、托盘打开、升级后启动 | 无明确业务目标时进入 `/ai`；已打开的工作台保持当前上下文 |
| 本机 `smart` 或 `local_workbench` 托管 | 快速加载本机 `/pc`，由前端进入相同消费者工作台；不等待远端探测才显示窗口 |
| 首次使用或账号未登录 | 在工作台提供清楚的登录/开始使用入口；按实际支持情况允许官网访客聊天 |
| 登录成功 | 无明确回跳目标时回到 `/ai`；保留有效、受支持的业务深链 |
| 云端暂不可达 | 保留工作台、已有内容、可恢复草稿和本机能力；具体在线功能说明暂不可用及恢复操作 |
| 云端恢复 | 在原页面恢复可用服务与同步，不要求“返回云端”或换站点，不清空当前会话 |
| 本机服务异常 | 在相关功能提示重试或诊断；其他仍可用的功能继续使用 |
| 页面崩溃或未知路由 | 提供重试和“返回工作台”；返回默认 `/ai`，不把消费者带到开发任务页 |
| 用户主动打开本机任务或开发深链 | 保留原路由和权限检查，不能以默认首页规则覆盖明确目标 |

本机托管、云端连接、一龙账号、本机节点、第三方 AI 会话是不同状态，不复用一个
`localMode` 布尔值决定全部导航与账号行为。云端服务是否启动由真实连接和身份条件控制。
健康连接不需要全宽技术横幅；异常只显示用户可理解的影响和可执行恢复入口。
不在消费者首屏展示 IP、端口、SHA、队列租约或内部项目标识。

断网不等于本机 AI 可离线回答。平台 AI、第三方官网和共享资源仍遵守各自网络、
登录与授权边界；已接受任务的 journal、结果及用量恢复继续遵守
[PC 本机节点离线韧性](../pc-node-offline-resilience.md)。

## 功能层级与保留项

- 主导航优先呈现 AI 工作台、项目、消息及账号等消费者任务；全站用户默认展开。
- 本机任务、Codex 控制台、Git 和官方会话检查归入可发现的开发工具入口；明确深链继续可用。
- 发布租约、更新技术信息、自进化队列和原始诊断只在开发工具或高级诊断展示。
- 本次只调整入口、层级和连接恢复，不删除已有能力、改变目录授权、自动发起任务或恢复已暂停的后台自进化。
- 官网会话继续使用既有宿主与生命周期；登录、验证或地区限制按当前合同显示官方页。
- 不自动清空草稿、登录凭据、项目绑定、任务 journal、侧栏选择或用户已保存的布局偏好。

## 验收标准

1. 本机和云端托管下，根路径、默认登录回跳、未知路由及错误恢复均指向 `/ai`。
2. 普通启动不自动进入 `/local-tasks`；明确本机任务/开发工具目标仍可访问。
3. 本机加载且云端可用时，账号、通知、在线状态和项目服务按现有身份规则正常启用。
4. 断网及恢复只改变能力状态；不重建整个工作台、不强制导航、不丢失会话与草稿。
5. 缺登录、节点异常、官网会话未就绪分别呈现各自状态，不互相推断失败。
6. 全站用户保持默认展开；聊天、工作、输入框、历史和项目入口复用现有页面。
7. 开发工具和诊断可找到，消费者正常首屏不暴露内部执行字段。
8. 定向路由/状态/导航回归、严格类型检查、lint 和生产构建通过；安装后回读节点及桌面精确发布身份。
9. 对真实 Windows 冷启动、重复打开、异常恢复和布局记录现场证据；未执行的断网、崩溃或第三方登录场景明确列为未验证，不用静态测试冒充。

## 依赖与实现范围

依赖现有 PC 路由与认证、loopback 节点、连接状态探测、Tauri 生命周期和生产 AI 工作台。
主要范围：`pc-frontend/src/App.tsx`、`api/runtime.ts`、`features/auth`、`features/shell`、
对应 PC 回归脚本，以及 `scripts/node-agent-launcher/node-agent.env.example` 的配置说明。
启动器保留本机 `/pc` 快速加载；本次不要求新增后端 API 或改写安装身份。

Windows 发布按 `publish-node-agent.ps1` 与既有精确版本更新验收执行；云端 PC 资源按
`publish-pc-frontend.ps1` 的服务端兼容门禁发布。版本验证与功能验收分别报告。
