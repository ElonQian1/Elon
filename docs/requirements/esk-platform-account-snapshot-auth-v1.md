# 正式 ESK 摘要与会话同快照读取 V1

## 用户结果与现状

主 APK 正式资产页及量化端授权摘要必须只显示当前有效本人会话可读取的正式登记。
已有 `platform_account.v1` 的响应与客户端合同保持不变，不再在读取前丢弃会话凭据。

基线 `a4fd333061f898895974cc845d5453d274e39087` 中，HTTP 入口先验证用户会话，
再调用仅接收用户 ID 的 `esk_platform_account`；后者事务只检查用户 active。
因此会话在两步之间撤销、到期或重新绑定时，第二步没有会话复核。
既有 `esk_platform_history` 已在一个 SQLite 只读事务内复核会话、政策及完整账本。
本需求复用其已实现验证，不复制第三套账本汇总器。

## 实现边界

- 摘要 Store 方法必须显式接收 user ID 与本次 session token；不得保留生产无会话捷径。
- 在建立读取快照时，验证真实 active 用户、匹配用户的未撤销且未过期会话。
  虚拟 owner、空凭据、跨用户会话、停用/不存在用户均失败关闭。
- 同一快照内检查政策完整性、全部正式登记及其审批关联，计算账户总额和前 N 条。
  页面外损坏不能被截断隐藏；有政策但无本人登记时也不能忽略政策损坏。
- 使用已有历史读取的第一页投影为旧 `PlatformAccount`，不暴露游标或新字段，
  不更改 `platform_account.v1`、ESK 精度、来源、状态、capabilities 或双 APK 合同。
- 公共 HTTP 参数校验保持原样；Store 的既有前 N 条上限规范化可保留。
  身份验证发生于账本扫描之前，错误响应继续无缓存且不含账户或会话细节。
- 该保证以 SQLite 读取快照建立时为线性化点；不宣称可追回已经开始或发出的响应，
  客户端已有换号、退出、后台及过期清理仍须继续保留。
- 摘要 Store 读取不改写记录、审批、用户、会话、政策或 Paper；HTTP 入口既有的
  登录活跃时间节流维护保留，不新增或修改会话权限、归属、撤销状态或期限。
  不加入数据库迁移、资金操作、
  卖回占用、生产开关、链上证明或新网络信任来源。

## 验收标准

1. 先成功鉴权，再撤销/过期/改变 session 归属，实际摘要 Store 读取拒绝，
   并保留基线可复现证据；不得仅以源码字符串断言作为竞态证明。
2. 当前有效会话可读；其他用户、虚拟 owner、缺失/停用用户、错误及空 token 拒绝。
3. 摘要与 history 第一页在空、单笔、分页、多用户及 off-page 验证上相同，
   全账户总额/笔数不是前 N 条小计，Paper 数量与持久记录保持不变。
4. 真实生产 Router 验证旧响应字段、标志、空值与 no-store；撤销和跨用户条件拒绝。
   账户读取的重复调用不产生任何正式分录、审批或资金变化。
5. 既有账本 harness、完整正式 Router 回归、生产构建、源码推送、发布身份与
   未登录线上只读 smoke 分别留证，不能以 harness 替代生产路由。
