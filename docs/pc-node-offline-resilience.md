# PC 本机节点离线韧性

本文定义一龙服务器暂时不可用时，PC 本机节点的执行、恢复、授权与用量边界。

## 产品目标

- 已由本机节点接受的任务不因云端 WebSocket 中断而丢失结果。
- 节点把终态和 token 用量先持久化，重连后幂等补传并等待服务器确认。
- 本机 owner 可以在本地工作台继续使用自己未受云端保险箱托管的 Codex。
- 平台 AI、远程节点和朋友共享的云端托管凭据在服务器离线时保持不可用。
- 共享凭据必须持续联网；控制连接断开时节点取消仍在运行的共享任务。已经产生的终态只可在原租约和预留预算内幂等结算，不能离线续租或继续计算。

## 状态模型

`online` 表示云端控制面可用；`local_degraded` 表示仅开放 owner 的本机资源；`syncing` 表示正在补传本地任务与用量；`blocked` 表示所选路线必须联网。

本机托盘工作台的 `/pc/local-tasks` 是离线入口。页面只允许选择已经在本机授予 `full_access` 的真实项目和目录，并展示执行进度、工具审批、取消、token 用量及待同步状态。频道可以留空；云端恢复后由服务器在该项目中解析真实的 AI 开发频道。

本地模式不建立云端消息 WebSocket，不拉取通知、在线状态或预热项目。工作台只会用短超时探测云端健康状态，以便在恢复时提示用户；探测失败不影响本机任务。

## 断线执行与恢复

- 使用 owner 自有本地凭据、且已派发到本机的 CLI 任务不会因为 WebSocket 断开而停止本机进程。
- 使用云端保险箱或朋友共享凭据的任务必须保持控制连接；连接断开时会被取消，不进入离线持续执行。
- 服务器默认保留原请求接收器 120 秒，等待同一节点重连并回放终态；可用 `ELON_PC_CLI_RECOVERY_GRACE_SECS` 调整为 10–900 秒。
- 超过等待窗口时，服务器停止等待并把界面标成“通信自动恢复超时”，但这不表示本机进程已被终止。
- 本机任务完成后仍会写入 durable outbox；即使节点进程重启，重连后也会补传真实终态，并可纠正通信产生的临时失败。
- 用户主动取消和真实业务失败属于最终状态，离线补传不能覆盖。

## 可靠补传

节点完成任务时必须先把终态、模型和 token 用量写入 SQLite durable outbox，再尝试发送。数据库使用 WAL 与 `synchronous=FULL`；同一个 `event_id` 或 `req_id` 不能被不同内容复用。每条记录还冻结 `owner_user_id + agent_id + install_id`，补传扫描和 ACK 都要求三者与当前会话完全一致；节点退出账号、换绑账号或重装后，旧记录不会被新身份解释或删除。

服务器在接收记录前再次核对 WebSocket 鉴权的 owner、节点和安装身份，再按稳定执行 ID 在事务中幂等写入 completion receipt、任务结果、频道结果、用量和结算。后台重试使用 receipt 中已经冻结的身份，不重新读取后来换绑的账号。服务器返回同时绑定 `event_id` 与 `req_id` 的 ACK；节点只清理精确匹配且属于当前生产者身份的记录。损坏记录进入 dead letter，不阻塞后续正常记录。实际序列化 payload 会压缩到 900 KiB 以内，为服务器 1 MiB 上限保留余量。

云端 `/api/me/node/exec` 直连本人节点时，也必须在下发前建立 `pc_agent_cli:<req_id>` 计算运行并冻结 `own_codex + allow_offline` 补传策略。这样同步 HTTP 请求即使先断开，节点 outbox 中的终态仍有可匹配的服务端运行，可以结算并收到 ACK，不会成为永久 pending 记录。

## 安全和计费边界

- `own_codex` 与 `user_api_key`：记录用量，不扣一龙平台余额。
- `shared_codex`：必须有在线签发的租约、预留预算和持续控制连接；断线时取消运行中任务，不创建新任务、不续租。断线前已经持久化的终态可在原授权内补记账。
- `platform`、远程 AI 和远程节点：服务器离线时不可用。
- 本机普通 task journal 只用于恢复展示，不作为财务账本。
- 本机 `full_access` 授权同时绑定 owner、节点凭证和安装 ID；退出、换绑或复制旧授权文件都不能让另一个身份继承目录权限。
- 云端派发 Codex 时会冻结凭据来源。无租约任务只允许使用未托管的本地 `CODEX_HOME`；共享任务必须使用 marker 中完全相同且未过期的 lease。marker 缺失、损坏、被替换或租约过期都在启动前 fail closed。

需要云控的派发还会携带服务器冻结的绝对授权截止时间、签发时间和剩余 TTL。服务器在实际发送前启动自己的单调时钟取消器；节点取服务器截止时间、TTL 与 managed marker 租约到期时间的较早者，并冻结本机单调时钟截止点。墙钟或单调时钟任一个先到都会取消任务，因此本机系统时间被回拨也不能延长共享资源使用。任务控制句柄注册后会再次检查连接和截止时间，字段缺失、协议过旧、断线竞态或已经到期都会拒绝启动；运行中的本人账号若自动切换到托管/朋友账号，也必须原子升级为云控句柄、复查连接并安装同样的双截止取消器。

同一 consumer 与节点同时只允许一个有效 emergency lease。租约的最晚到期时间由事务内重新读取的 grant 最大时长和 grant 自身到期时间共同裁剪，不能使用 API 预读的旧授权值。签发新 lease、用户主动清除 lease 或提供方撤销 grant 时，服务器都会在同一事务中先把旧 lease 绑定运行的 replay deadline 收紧到当前时间，再使 lease 失效；事务提交后对在线节点发送精确 Cancel。lease 签发和 compute run 绑定使用 compare-and-set，实际下发使用的 provider、lease 与账本冻结值必须完全一致，旧 lease 不能在清除新 lease 后“复活”。数据库升级清理遗留过期、撤销或重复 lease 时也会同步收紧关联运行的补传截止时间。租约失效只终止继续执行，不丢弃已经产生的账：迟到终态只有在 compute run、lease、allowance、token event、节点交易及各方身份全部精确匹配时，才可幂等写回已失效租约。

计费上下文在服务器派发时冻结，补传不能通过切换本机当前账号改变计费来源。`own_codex` 的 token 只记账不扣平台余额；共享或平台资源必须绑定原执行、节点、用户、短期租约和有效预算预留，服务器离线时一律不能新借、续借或扩大额度。共享/平台任务在首次发送给节点之前，会把有限金额的普通短期预留转成 durable dispatch hold；普通超时清理和对象析构都不能退款，只有能够证明从未发给节点的失败或管理员核验才可显式释放。这样服务器离线超过普通预留 TTL 时，节点 outbox 中尚未补传的未知消耗也不会先被错误退款。结算事务会核对原 allowance ID、冻结金额和服务器定价后的实际费用；错配或超额整体回滚。计价和节点收益只使用服务端运行中冻结的 model，忽略 completion 自报的 model。取消/超时会先排空 CLI 缓冲区并解析已产生的 token；共享/平台终态缺少 usage 时，dispatch hold 会转为 verification hold，运行进入待核验状态且不会按零消耗完成或 ACK，直至可信 durable 用量或人工处置。

## 首次绑定与端点故障

首次注册节点必须联网，因为服务器需要签发节点身份。已经绑定的节点凭据会留在本机，云端暂时不可达不会取消本机离线能力。

错误中的目标地址如果是：

```text
http://127.0.0.1:9/api/me/nodes/register
```

这不是普通的“真实服务器拒绝连接”：它证明当次注册使用的有效目标已变成回环地址的 9 端口。9 端口通常被测试、代理或启动器当作丢弃/阻断目标，本机没有一龙注册服务监听它。先检查本机节点 `/api/status` 返回的 `cloud_http_url`、安装目录 `_internal/node-agent.env`，以及启动进程的 `NODE_CLOUD_URL`、`NODE_CLOUD_HTTP_URL`；也要排除旧启动器或旧网页保留的本机端口参数。恢复真实一龙服务器地址、升级到能够探测实际本机节点端口的版本并重启后再注册。节点现在会对明确的 `127.0.0.1:9` 云端配置给出诊断，不再只显示底层 `error sending request`。

## 运维边界

协议、服务器和 Windows 节点同时更新时必须先发布服务器，再发布节点。服务器发布同时更新线上 `/pc`；节点发布把同一前端打包到本机工作台，并在协议兼容后通知在线节点升级重连。
