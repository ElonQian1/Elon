# 群聊 AI 选区、分享与私人续聊

本文件描述当前代码边界，不把规划或离线测试当作真机验收。

## 已实现的纵向链路

1. 群聊长按“AI回复”，或“多选 → AI 分析”，明确选中 1 至 100 条文字消息。
2. 确认界面允许补充问题，并明确回答会发到当前群。不自动上传附件。
3. 服务端按当前成员权限、群 ID、消息 ID 和 revision 重新取数，按真实时间顺序构造提示词。
4. 选区请求使用 `context_scope=selected`，不混入最近 30 条窗口，不自动进入旧工作 AI 回退。
5. 严格选区保留临时空白会话隔离；本批新增明确勾选加入本群长期项目的路径，私有发送和模型档位复用。长期路径的发布/验收状态见下方专项记录。
6. 服务端 dispatch 只发一次许可；结果不确定时不重新发送。完成时再次核验选区版本和权限。
7. 新产生的精选 AI 回答下方显示来源记录卡片，保留分析时的文字、Markdown、附件与时间；ChatGPT 回答气泡末尾提供“使用 ChatGPT 继续讨论”。发起人也可继续使用长按“转发”和原有分享卡片。
8. 群成员点卡片，以已有原生只读聊天 UI 阅读，Markdown 和代码正文保留；重新打开和继续讨论均重新鉴权。
9. 发起人可在分析确认页或回答的分享设置中允许群成员继续讨论，默认未授权。续聊打开查看者自己的 ChatGPT 空白会话，确认新会话、路由与草稿为空后才填入选段草稿。必须由用户按发送，不自动写回群。
10. 返回键回原群；未发送的私人草稿需要确认放弃，不能带到群输入框。旧回答无法获取精选上下文时仍可选择仅转发正文。

## 数据与隐私边界

- 身份 Cookie、运行时令牌继续留在设备 WebView，不进入群聊服务端或分享卡片。
- `group_ai_selected_sources` 固定消息版本。编辑、撤回、退群后拒绝派发或完成。V304 起同时保存分析时的来源快照：完成后的编辑不会改写来源记录；已撤回的来源隐藏正文及附件，退群拒绝访问。
- 继续讨论权限独立保存，只有原发起人可修改，并用版本号拒绝过期覆盖。关闭不删除别人已经保存的内容。旧版未保存快照的回答只保留原发起人原有导出能力，不能追溯开放他人权限。
- 完整选区超出 20,000 UTF-16 单位会拒绝，不静默截断。
- 同一 operation 不可改群、改用户、改选区或问题；不同成员可以各自分析同一条消息。
- 已显式发布的卡片是独立快照，原消息后续编辑不会重写快照；撤回分享仍走已有快照权限流程。
- 分享给其他群需要用户在预览中明确选目标。不会自动创建任何公开 ChatGPT 链接。
- 当前群聊分析执行器只返回文字；富文本 Markdown 保留，但本批未接通图片附件输入或结构化生成图片输出。
- 私人续聊当前只准备文字及完整写作/代码块；图片保留在卡片阅读页，不会自动上传或声称已交给模型。

## 项目生命周期后续合同

2026-09-23 用户再次确认：正式目标不是每次临时分析，而是**每个账号内，每群独立项目和长期会话**。当前临时执行器是未补齐的实现，不是用户改变了方案。“仅所选消息”隔离保留为独立可选模式，不应以它代替长期群聊模式。接入账号与项目绑定必须分别展示真实完成状态。

- 绑定主键应为一龙用户 + 厂商账号及 workspace 指纹 + 不可变 group_id；群名仅作显示。
- 每个绑定有 generation、project_id、状态及创建操作租约。后端只存映射和无凭证回执。
- 创建前在设备同源身份层验证账号/workspace；服务端租约防止多个设备重复发起创建。
- 超时、401、403、限流、目录未加载不等于删除。只有经确认的缺失才允许显式重建。
- 创建结果未知时不能盲目重放 POST；先核对已创建对象，再提交绑定。
- 项目记忆和“仅所选消息”是不同模式。严格选区默认保持隔离，不能悄悄读取其他项目聊天。
- 项目内以主题 ID 绑定 conversation_id；私聊续聊不能复用群发布请求或自动发布结果。
- 当前公开资源已确认创建请求体和响应处理，并实现版本化传输；手机真实创建/复用仍待验证。详见 [项目长期会话专项记录](reports/group-chatgpt-project-20260923.md)。

### 2026-09-21 群回复失败反馈

- 在已解锁的 1788 上重走两条合成消息的多选分析：出现 `start → page_started → page_error → failed_before_authorize`，约 31.7 秒，没有进入 `authorize/send`。这次不是回答生成后漏发群消息，也不是前一版临时 URL 判断问题的验证通过。
- 同期 APK 内探测群聊后端 TCP 正常，ChatGPT/Google HTTPS 都在 5 秒连接超时；当前网络仅 Wi-Fi、无 VPN。不能把群聊网络通畅等同于厂商网络通畅，已请求恢复加速连接后继续验收。
- 原来发送前失败仅短暂 Toast 并取消选区请求，用户无法分清“正在回答”和“没有发出”。现在保留失败确认窗口；未授权发送时可重试同一个选区请求及幂等操作，不需要重新多选。主动取消仍取消请求，不悄悄换成工作 AI。
- 授权后的结果不确定禁止重试，也不再提示“稍后查看群消息”暗示回答一定会到达。回答写入群消息仍使用已有 `complete` 接口与实时刷新，增加有界 `deliver_started/completed/failed` 回执，不记录正文。
- 网络恢复后的真实 AI 回答和完整分享链路仍待验收；本段不代表端到端通过。
- 定向 Android 回归 19 项通过，XML 核验零失败、零错误、零跳过：failure 3、session policy 3、diagnostics 3、feature 3、Google/group 7；源码规模与文档模块化门禁通过。启动异常也走明确失败反馈，不伪装成用户主动取消。

### 网络恢复后的模型配置阻塞

- 用户恢复加速连接后，APK 探测 ChatGPT 首页 HTTP 200，耗时 973 ms，网络同时具有 Wi-Fi 与 VPN。随后 1788 的真实多选分析进入 `ready=true → configure_model`，但 60 秒后仍在发送授权前超时。不能继续归因于网络，也不能把它称为已回答。
- 代码审计发现群聊独立文档漏接 `WebTouchRequest`。私有模型目录无法直接完成时，共享适配器会请求打开官网模型控件并等待 Android 收集菜单；个人聊天已有处理器，群聊未接线，因而一直等不到下一步。
- 群聊复用 `ChatGptWebTouchRequestHandler` 和已有触摸分发器，只允许模型菜单读取、子菜单、模型选择与收起；导航、语音、工具和通用控件请求不放行。菜单出现后补读档位控件，关闭会话后取消收集任务。
- 模型目录明确返回失败时终止准备并保留选区重试，不再空等全部超时时间，也不忽略用户档位强行发送。暂时没有目录内容不等于厂商没有功能。
