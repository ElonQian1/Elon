# PWA 消息引用与图片操作

日期：2026-09-30。范围：PWA 好友、群聊消息；不修改 APK、Win 或 ChatGPT 私有传输。

## 已实现

- 图片、文字共用长按、右键、键盘菜单及可见的消息操作入口，包含引用、复制、转发、多选；图片另保留二维码识别。
- 单击图片仍打开大图；滑动超过阈值取消长按，长按结束不再误开大图。
- 引用显示在输入框下方，包含作者、两行摘要、图片缩略图和取消按钮；正文不插入 Markdown 引用。
- 发送只提交 `quote_source.message_id/revision`，复用服务器同会话、成员权限、撤回和修订检查。服务器创建引用快照。
- 引用取消不改草稿；发送失败恢复未被替换的草稿；原消息变化拒绝发送；切换会话或账号清除当前引用和多选。
- 转发文字和原附件到用户确认的群聊或好友。原文件以流式读取限制为 12 MiB，重新上传到当前账号与目标会话，不把源附件地址当成已转发文件。
- 多选最多 20 条，按聊天顺序逐条转发。已确认条数可见，发送结果不明停止，不自动重发；取消上传不继续发消息。
- 复制图片交给浏览器 ClipboardItem；JPEG/WebP 在浏览器不支持原格式时转换为 PNG 图片，原图转发仍保留原字节。过大图片、不支持的格式、权限或图文组合明确提示改用转发，不静默只复制文件名/链接。

## 模块边界

| 文件 | 责任 |
|---|---|
| `social_message_actions.js` | 手势、菜单、多选、引用及生命周期 |
| `social_message_transfer.js` | 有界原文件读取、剪贴板、确认后转发 |
| `social_message_actions.css` | V2 语义颜色、窄屏、安全区及可访问操作 |
| `social_chat_view.js` / `social_chat_recovery.js` | 渲染挂接、发送引用字段 |
| `web_page.html` / `social_assets.rs` | 页面和静态资源组装，不承担新业务逻辑 |

## 验证证据

- `scripts/test-pwa-message-actions.cjs`：Chromium、WebKit 各 22 项通过（含 HTTP 附件地址映射到当前 PWA 入口，避免 HTTPS/端口不一致）。
- 覆盖图片长按、单击查看、右键与 Escape、焦点恢复、滑动取消、群聊/好友引用取消与发送、失败恢复、图片原字节转发、多选顺序、未知发送状态防重试、图片 ClipboardItem 内容与不支持提示、修订冲突、会话隔离。
- 浅色/深色 × 320/390/1024 像素页面截图；320 浅色、390 深色人工图像检查，输入与引用无重叠。
- 原图片预览 Chromium 18 场景回归通过；旧二维码快捷键现在进入统一消息菜单，再选择二维码。
- 原附件 Chromium 21 场景通过，覆盖图片、文档、音视频、真实浏览器生成的合成麦克风音频、取消、失败和身份变化。
- V2 规范自测 12 项及治理检查通过；治理检查不等同于设备验收。
- 测试服务只在 loopback，使用合成消息、图片、录音；未读取或写入生产群内容。剪贴板测试检查真实 ClipboardItem 内容，但剪贴板写入端使用替身，不宣称物理系统剪贴板验收。

## 明确边界

- 此次对齐消息操作，不添加 PWA 的 ChatGPT 登录宿主、私有 AI 回复执行或 APK 本地收藏库；不存在这些能力时不提供伪可用按钮，也不偷偷改用工作 AI。
- PWA 复制图片受 HTTPS、浏览器权限和格式支持限制；原图转发与下载不依赖剪贴板。实体 iPhone/Android 已安装 PWA 的系统剪贴板与分享环境仍待设备验收。
- 多选为逐条转发，不是新建合并聊天记录卡片；不重做原有记录卡片协议。

## 交付

使用正式 `publish-server.ps1 -SkipPcFrontend` 发布静态路由，再用 `publish-mobile-pwa-static.ps1` 原子发布自包含 PWA。候选 Git 身份、服务版本、部署结果和线上模板哈希以这次脚本生成的发布收据为准；本报告不把待执行的发布写成已成功。
