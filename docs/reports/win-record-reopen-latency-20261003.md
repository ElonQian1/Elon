# Win 聊天记录再次打开延迟

## 根因与范围

现有附件缓存已经避免重复下载图片，但 `ChatRecordReader` 每次打开先清空正文并等待网络，之后才挂载附件组件。本地命中仍被慢正文请求挡住；任意正文异常还会清除所有附件缓存，短暂断网之后再次打开又要下载。

本批仅修改 PC/Win React 阅读器和定向测试，不改 ZIP 导入、服务端权限、图片质量、Android 或移动 PWA。保留既有原图预览、视频播放、卡片、拖动、引用菜单及嵌套记录。

## 缓存规则

- 复用 Android 已采用的 5 分钟短期权限窗口：成功读取的正文在窗口内先显示，本次打开仍后台发起条件请求；超过窗口不能直接显示本地正文。时间从服务器成功响应起算，本地读取不续期，时钟回退不视为新鲜。
- 正文按服务器、账号、记录及登录会话指纹隔离。只存单向摘要，不把 Cookie、token 或请求头写入缓存。正文最多 4 MiB 内存、8 MiB 磁盘、16 条；到期在读写时淘汰。
- 复用现有图片原始 Blob 缓存：32 MiB 内存、128 MiB 磁盘、128 项，最长 7 天；不二次压缩，不缓存 ZIP 替代附件。总磁盘上限为正文与媒体合计 136 MiB。
- 正文请求最长 8 秒。网络失败、超时、5xx 不删除图片；仅在短期窗口内保留旧正文。明确 401/403/404、主动撤回、退出或切换登录会话会清除相关缓存，迟到响应不能恢复被清内容。
- 阅读器停留期间在租约到期前做一次有界续验；成功续期，失败在到期时隐藏旧正文并提供重试。关闭阅读器取消请求和定时器，不在后台无限轮询。
- 核验结果未变化时保留原列表及媒体实例，不重置滚动位置。现有“清理本条记录的附件缓存”同时失效本条正文短期租约，清理不删除群消息或登录态。
- 短期窗口不是远端撤回瞬间同步保证；离线最多使用尚未到期的已验证内容，明确拒绝访问到达后立即隐藏。此策略与永久离线访问不同。

## 验证入口

- `scripts/test-record-reopen-latency.cjs`：真实环回 HTTP，实际 React 阅读器，两张合成图片，禁用附件 HTTP 缓存。阻塞正文回复后仍须显示两图；重载验证 IndexedDB；5xx 保留缓存；403 清除；时钟推进验证过期；新会话不可继承原租约。
- 修复前同一测试在第二次打开的 1500 ms 等待断言失败。修复后分别记录桌面及窄屏图片显示耗时和附件下载计数；这些是合成数据，不能当作用户群中两张私人图片的 Win 现场测速。
- 复用 `scripts/test-chat-record-cache-browser.cjs` 的图文、视频、嵌套、拖动、手动清理及 PWA HTTP 缓存回归；复用 `pc-frontend/scripts/test-record-media-cache.cjs` 的并发取消、LRU、账号隔离与迟到响应验证。

构建、发布、本机 Win 更新状态以本批日志、正式回执和 MCP 版本复核为准，不以测试入口存在推定完成。
