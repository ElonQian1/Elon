# 商户业务调用证据 V1 验收

## 已实现

- 使用现有 `open_commerce_invocation_terminal_events` 顺序读取商户终态调用，不维护第二套状态机。
- HTTP 列表和详情校验当前用户的项目成员关系及商户归属。
- MCP 提供项目内商户证据列表和详情工具，共用相同服务。
- 列表返回结果 SHA-256，不返回原始调用输入；详情只在商户项目范围返回现有结果。
- 商户运行时可选返回严格的 `_yilong_business_receipt`；版本、标识、时间和整数金额不合法时失败关闭。
- 历史非法回执只标记 `invalid_legacy`，不会成为结构化订单事实。
- 当前项目有 ERP 实例时返回实例键和配置修订；没有实例时明确为空。
- 所有证据固定 `funds_moved=false`，PC 工作台显示“未扣真实资金”和“仍需适配器明确入库”。

## 验证范围

- Rust 测试覆盖标准回执、金额币种原子性、终态投影、摘要、详情和 MCP 读取。
- PC 契约测试覆盖商户工作台入口、未扣款文案、结果摘要和只读 MCP 工具。
- Rust 格式化、开放商业测试、PC ESLint 与生产构建通过后方可发布。

## 未完成边界

- 没有自动把证据写入 ERP 订单、库存、财务或 CRM。
- 没有验证商户回执对应的真实支付、履约、退款或外部平台订单。
- 没有外部 Webhook、跨运营方导入或联邦证据互认。
- `cofficethinking` 等商户运行时需要按自身业务逐项采用标准回执，不能由平台替它猜测结果字段。
