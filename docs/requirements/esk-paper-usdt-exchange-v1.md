# ESK / USDT Paper 双向兑换与手续费结算 V1

## 用户目标

登录用户在一龙主项目的 ESK 资产区看到本人 ESK 与 USDT Paper 余额，选择 `USDT → ESK` 或 `ESK → USDT`，先取得一份有期限、可核对的精确报价，再明确确认兑换。报价和成交回执必须逐项显示输入、兑换前毛额、手续费、预计到账、价格、有效期和交易流水号。

本功能先解决产品交互、金额算法、原子账本、手续费和审计闭环。V1 不接收、托管、监听或移动真实 USDT，不生成钱包地址，不持有私钥，不连接主网、测试网或交易所，也不把数据库记录描述成链上成交。

## 与现有 ESK 账本的关系

- 主项目仍是 ESK Paper 余额唯一真源；现有管理员登记、卖回占用和量化占用语义不变。
- 兑换产生独立追加式 ESK 调整分录，并由现有 ESK 账户聚合读取；量化项目继续只读同一主项目投影，不能维护第二份 ESK 余额。
- `ESK → USDT` 只能消耗扣除卖回和量化占用后的可用 ESK；并发操作不得造成负余额或占用超过总余额。
- USDT V1 是独立 Paper 余额，只能由管理员以明确确认文本登记测试额，不能由客户端、链上交易哈希或付款截图自动入账。

## 模式与生产失败关闭

`ESK_PAPER_EXCHANGE_MODE` 只允许：

- `disabled` 或未设置：只读账户可返回，但报价、兑换和管理员 USDT Paper 登记全部拒绝；
- `paper`：启用本需求定义的模拟兑换；
- 其他值：配置无效，所有写入失败关闭。

Paper 报价还要求：

- `ESK_PAPER_USDT_PER_ESK`：一枚 ESK 对应的 USDT 精确正数价格，最多六位小数；
- `ESK_PAPER_EXCHANGE_FEE_BPS`：`0..1000` 的整数手续费基点；
- 任一配置缺失、格式错误或超界时不得产生报价或成交。

所有账户、报价、成交和登记响应固定包含 `simulated=true`、`funds_moved=false`、`on_chain_settlement=false`、`trading_mode=paper`。服务端不得存在可由上述环境变量切换到真实资金移动的 `live` 分支。

## 精确金额与报价

- ESK 和 USDT 都使用六位小数与有符号 64 位基础单位；API 金额使用固定六位十进制字符串，同时返回基础单位字符串。
- 禁止浮点金额、指数格式、负数、零、尾随小数点和超过六位小数。
- 价格表示为“一枚 ESK 对应多少 USDT”，同样使用六位小数和基础单位。
- `USDT → ESK` 毛额为 `floor(input_usdt_units × 1_000_000 / price_units)`。
- `ESK → USDT` 毛额为 `floor(input_esk_units × price_units / 1_000_000)`。
- 手续费从目标资产毛额扣除，按 `ceil(gross_output_units × fee_bps / 10_000)` 计算；净到账必须大于零。
- 报价固定 60 秒有效，绑定用户、方向、输入金额、价格修订、手续费率和全部计算结果；过期、篡改或已使用报价必须拒绝。

## 原子结算与幂等

1. 创建报价只持久化不可变报价，不改变余额。
2. 确认兑换必须携带报价 ID、用户级幂等键和确认文本 `CONFIRM PAPER ESK USDT EXCHANGE`。
3. 同一事务内重新校验模式、报价归属、期限、未使用状态和最新余额，再追加来源资产借方、目标资产净额贷方、平台手续费分录和成交回执。
4. 任一步失败全部回滚；不得出现只扣款、只到账或漏记手续费。
5. 相同幂等键和相同请求返回原成交并标记 `replayed=true`；相同键漂移到其他报价或金额返回冲突。
6. 每个报价最多成交一次；两个并发确认最多一个创建新成交，另一个只能得到幂等重放或冲突。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/me/assets/esk/exchange-account` | 本人 ESK/USDT Paper 可兑换余额、价格和费率状态 |
| `POST` | `/api/me/assets/esk/exchange-quotes` | 创建本人 60 秒精确报价 |
| `POST` | `/api/me/assets/esk/exchanges` | 原子确认报价并写入模拟成交 |
| `GET` | `/api/me/assets/esk/exchanges?limit=20` | 本人兑换流水 |
| `POST` | `/api/admin/assets/usdt/paper-credits` | 管理员登记测试 USDT；必须显式确认且幂等 |

所有本人接口必须登录且只读写本人数据。管理员接口复用既有管理员令牌，同时要求确认文本 `RECORD PAPER USDT CREDIT`。

## 用户界面

- Android APK、移动 Web 和 PC 资产卡都显示 Paper USDT 可用额、当前 Paper 价格和手续费率。
- 用户选择方向和金额后，界面必须先显示服务端报价的输入、手续费和净到账；只有第二次明确确认才能提交成交。
- 成功后刷新 ESK/USDT 余额并显示成交回执；失败、过期或余额不足时不乐观修改本地余额。
- 每个兑换入口醒目标注“Paper 模拟”“未上链”“不移动真实资金”，不得出现固定收益、保本、钱包地址、链上入金或真实提现表述。

## 验收标准

1. 精确整数算法覆盖两个方向、向下取整、手续费向上取整、溢出和净额为零拒绝，不使用浮点数。
2. 存储测试证明两种兑换都守恒、手续费单独入账、ESK 占用不可被兑换、账本不可更新或删除。
3. API 测试证明鉴权、模式/配置失败关闭、报价过期、篡改、幂等漂移、重复报价使用和并发余额竞争均被正确处理。
4. Android、移动 Web 和 PC 均消费同一版本化协议，报价前后状态清晰，并显示全部 Paper 安全边界。
5. 原有 ESK 登记、卖回申请、量化占用和跨项目投影回归继续通过。
6. 发布只启用 Paper 配置；生产接口与页面实测仍返回 `funds_moved=false`、`on_chain_settlement=false`，且不存在真实 USDT 地址或资金移动能力。

## 真实 USDT 后续准入门槛

真实入金、兑换或提现必须另立需求与独立安全评审，至少完成适用司法辖区确认、牌照/注册判断、KYC/AML 与制裁筛查、托管和密钥隔离、链与合约白名单、确认数与重组处理、Travel Rule、冷热钱包、限额、双人审批、逐笔与日终对账、异常冻结、退款/争议、审计和事件响应。未全部满足前不得复用 Paper 模式上线真实资金。
