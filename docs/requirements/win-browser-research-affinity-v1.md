# 浏览器研究会话的 Win 实例归属

## 问题与范围

量化高级网格研究实际遇到资源读取成功后下一请求返回 session_not_found。
当前多个 Win 实例按同一本机队列竞争领取，而研究会话和 WebView 宿主位于各进程内。
使用真实前端执行器的离线双实例实验已复现：非所属实例先领取时失败，所属实例先领取时成功。
这证明当前分配缺陷，不等于已取得每个线上请求的进程归因。

本批只修通用研究桥接，不增加交易执行、请求重放或任意脚本能力。
沿用项目、当前主应用用户、站点的登录隔离和资料存储。保留 Chrome 与 Win 登录窗口。
量化 APK 的产品 UI 和主 APK 托管合同保持既定归属。

## 合同

- 原生进程提供生命周期内稳定、不同进程和用户不共用的实例标识，以及当前用户实际拥有的宿主会话摘要。
- 本机节点按短租约登记实例。会话请求绑定项目、会话及实例，领取时在同一锁内复核；旧版无实例身份客户端不能抢领。
- 无会话命令可指定实例；只有唯一合适实例时自动选择。多实例歧义提供结构化错误及有界发现入口，不任意选错登录环境。
- 前端刷新不改变原生实例身份；原生重启后新实例不能冒充旧宿主，过期租约不能转移已有操作。
- 节点重启后从仍运行的原生宿主重新登记归属；磁盘历史不能冒充当前实例拥有的活动 WebView。
- 领取仍是执行至多一次边界；仅重试相同回执投递，不重放原生操作。用户变化丢弃旧用户结果。
- 所有队列、宿主及映射均有数量和有效期限制；诊断不保存网页登录凭据、正文或账户资金。

## 验收

1. 两实例按任意轮询顺序读取同一会话，只有所属实例可领取并执行；跨项目、用户和显式错误实例拒绝。
2. 旧客户端、过期实例、重启新身份、重复领取、回执迟到/重试、用户变化均有覆盖；结果未知不重发。
3. MCP 可发现实例并显式选择，Win 页面使用自己的实例；原有站点、列表、源码、网络采集与分片读取合同保持。
4. 真实源码回归、Rust/前端构建、发布版本及当前 Win 只读读取证据分开记录。未发布或未现场验证不得声称已修复用户环境。

## 交付顺序

先交付队列与消费者及原生身份的完整切片，再使用稳定链路继续量化高级能力研究。
需要加载新原生程序时先完成可核验安装工件，保留登录资料并遵守已有窗口重启授权边界。
本需求为商业网格 Goal 的前置修复，不替代剩余产品、发布和人工交易验收清单。
