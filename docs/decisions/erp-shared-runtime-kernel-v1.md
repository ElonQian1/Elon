# ADR：ERP 公共运行时内核 V1

## 背景

现有 ERP 蓝图能够描述公共模块、主题、插件、私有扩展、物化 Matter 和升级证据，但模块主要是治理元数据。若每个商户项目仍由 AI 分别重写库存、采购和订单规则，就会继续产生重复实现、修复漂移和数据一致性风险。

## 决策

1. 在 `sdk/merchant-erp-kernel` 提供框架无关、无 UI 的 Node 运行时包。
2. 公共内核只拥有领域规则和存储端口；经营数据保留在商户选择的存储适配器中。
3. V1 公共能力为门店列表、商品搜索、库存查询、采购入库、平衡采购分录、未付款订单创建和订单状态。
4. 商户差异继续分层：存储适配器负责数据库，主题负责 UI，插件负责受限扩展，私有源码留在商户项目。
5. 消费者 AI 的 `catalog.search`、`inventory.query`、`order.create` 和 `order.status` 直接映射同一内核；映射不绕过开放商业授权、动作确认、计量和商户运行时边界。
6. ERP 发布清单可选携带 `runtime` 绑定。绑定进入物化合同，让 Assignment 知道应复用的包及版本；蓝图服务仍不自动改写商户工作区。

## 结果

新商户可以从公共领域代码开始，只开发存储、界面和私有差异。已有项目需要先做差距盘点和适配，不能因为发布清单出现运行时绑定就宣称迁移完成。
