# AI Rules

最后更新：2026-07-09

## 最高优先级

本项目涉及屏幕截图。隐私保护优先级高于功能完整度、开发速度和演示效果。

## 禁止事项

AI 代理和代码实现都禁止：

- 未经用户明确开启就截图。
- 在用户暂停后继续采集。
- 命中排除应用后仍然截图或上传。
- 默认长期保存截图原图。
- 记录键盘输入。
- 录屏。
- 收集密码、验证码、Token、身份证号等敏感原文。
- 把截图、数据库、日志、API key 提交到 Git。
- 把云端 AI 上传包装成“完全本地”。
- 做老板远程查看员工屏幕的功能。
- 做无法退出或难以发现的后台常驻。

## 代码规则

- 新模块职责要小，避免单文件超过 500 行。
- 截图、隐私判断、AI 上传、数据库写入必须分模块。
- 所有 AI 输出必须经过 schema 校验。
- 所有删除动作必须删除真实数据，不只是 UI 隐藏。
- 所有后台任务必须支持取消。
- 所有用户可见的隐私开关必须有可测试状态。
- 默认使用 Mock AI Provider 做开发和测试。

## 文档规则

- 改截图、AI、隐私、数据删除前，必须同步更新对应 `docs/*.md`。
- 新增功能必须写清楚是否进入 MVP。
- 涉及云端上传必须写清楚上传内容、触发条件、关闭方式。
- 涉及数据保留必须写清楚保留多久、在哪里、如何删除。

## 负责人拍板规则

以下事项不能由 AI 自行决定：

- 是否启用云端 Vision API。
- 是否保存原图或缩略图。
- 是否开机自启。
- 是否自动发送日报到第三方平台。
- 是否加入团队管理或远程查看。
- 是否改变默认截图间隔。

## 最终回复要求

AI 完成任务后必须说明：

- 改了什么。
- 是否影响截图、上传、数据库、隐私、后台常驻。
- 跑了哪些验证。
- 哪些风险仍存在。
- 是否需要负责人继续拍板。
