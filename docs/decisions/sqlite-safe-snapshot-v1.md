# ADR：商户 SQLite 一致性备份与离线恢复 V1

## 背景

通用 ERP SQLite 适配器和商户运行时幂等 SQLite 存储都使用 WAL。直接复制主文件可能遗漏 WAL 中已提交的数据，而且两个包分别实现文件复制、摘要和恢复会产生不同安全语义。当前也不能把“存储可重启”误写成“生产灾备已完成”。

## 决策

1. 新增独立 `sdk/sqlite-safe-snapshot`，两个业务存储共用同一在线备份、验证和离线恢复原语，业务 schema 仍归各自包所有。
2. 创建快照必须使用 Node SQLite backup API；不允许普通文件复制主数据库。
3. 每个工件必须经过 `PRAGMA quick_check`，并可绑定 `user_version` 和必需表集合。
4. 快照回执只包含 SHA-256、字节数、版本、表名、复制页数和时间，不包含绝对路径或经营数据。
5. 恢复必须提供预期 SHA-256，只能写入不存在的新文件；SDK 不提供覆盖、原地替换或自动配置切换。
6. 临时文件与目标位于同一目录，经验证和刷盘后用硬链接原子发布；并发发布由文件系统 `EEXIST` 决定唯一胜者。
7. 直接符号链接、符号链接目标目录、损坏数据库、摘要漂移、版本不符和缺表失败关闭。

## 结果

商户项目可以在单机 SQLite 继续服务时生成一致快照，并在停机后把审核过的工件恢复为新数据库文件。生产环境仍须另外负责备份加密、上传、保留、监控、停机切换、业务 smoke 和回滚演练；本决定不构成多机高可用或生产恢复验收。
