# APK 媒体卡片打开方式

## 交互合同

- 微信视频号、抖音、小红书、B站共用封面、标题、平台/作者及底部双入口布局，不再单独缩窄或隐藏视频号标题。
- 卡片点击按该平台默认方式打开；初始偏好为 App 优先。底部固定左侧对应 App、右侧“在一龙内打开”；点击既保存该平台偏好，也执行打开，不交换位置。
- 当前生效项显示“默认”。未安装或不可用时左项禁用并说明状态，卡片站内打开；底层保留原偏好，不把临时兜底写成新默认。用户改选后返回可撤销最近一次变更。
- 偏好仅存本机，按一龙服务器/账号及稳定平台 key 隔离；不保存链接、分享参数、Cookie 或凭证。安装/卸载后返回重新检查；其他已显示卡片同步默认标记。
- 大字体/窄卡片时双入口上下排列，仍保持 App 在前；至少 48dp 热区。长按、多选、复制、转发及聊天记录内的卡片入口继续可用。

## 打开策略

平台规则从 HTTPS 原链接主机识别，不相信展示标签。只向白名单包发送显式 ACTION_VIEW，不发送网页 Intent extras、不打开应用市场或把 App 首页当作内容直达。通过包管理器检查内容处理 Activity，仍捕获实际启动失败。

- 抖音：优先保留原分享短链；桌面视频 URL 按已观察到的 Android 分享页路由转换，保留 query。
- 小红书：保留长链接的完整分享参数；短链需要时仅跟随同平台 HTTPS 重定向。
- B站：保留分享链接及分 P/时间点；必要时解析同平台短链。
- 微信视频号：复用新鲜跳转接口和同内容、格式、过期时间验证，不缓存临时跳转链接。

短链解析最多四跳、6.5 秒，不执行页面脚本、不共享凭证；普通 App 直达不创建 WebView。同一个待处理链接不重复发起解析；切后台、账号变化或选择另一方式后旧请求不能拉起界面。失败用原链接站内打开，不反复弹确认。

站内阅读保持既有播放器、浮窗、画中画与回填；网页自动拉起 App 被阻止。用户明确点网页/阅读器的“App 打开”入口仍可转出，微信异步页面按钮可用阅读器原生“微信打开”补足。

## 范围与证据

这是 APK 的已安装应用路由与卡片交互改动，不修改 Win/PWA 的能力探测，也不向浏览器暴露 Android 包列表。Win/PWA 仍保留原文阅读/平台入口；不能把 Android 安装检测能力复制成网页假按钮。

实现：`SocialMediaOpenPolicy`、`SocialMediaOpenPreferences`、`SocialMediaAppLauncher`、`SocialMediaCardAction`、`SocialMediaOpenBar`。定向测试为 `SocialMediaOpeningTest`，调试专用验收页为 `SocialMediaCardsPreviewActivity`，正式 APK 不包含它。

系统路由依据：[Android 包可见性与 URL 打开](https://developer.android.com/training/package-visibility/use-cases)。发布与运行证据单独登记，启动被系统接受不等于第三方已加载成功。

本次实现及验证状态：[交付记录](android-media-card-opening-delivery.md)。
