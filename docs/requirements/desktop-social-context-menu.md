# 桌面聊天右键交互整改

用户需要直接对一条消息执行复制、引用、转发、编辑等操作。当前菜单虽已接入业务，但所有类型使用相同长列表，常驻更多按钮、技术化文案及媒体能力缺失影响桌面聊天体验。

## 交互规则

- 群聊、好友聊天共享紧凑深色菜单；右键消息内容在鼠标位置打开；更多按钮仅悬停、键盘聚焦或触摸时显示，编辑标记始终可见。
- 菜单常用操作在前，编辑及历史居中，低频详情和本机隐藏在后，分组分隔；收藏与隐藏仍明确仅此设备，不能伪装为云同步或全员删除。
- 选中文字时复制对应选区；普通文字可复制全文，格式化文字保留富文本复制。右键别的消息不复制旧选区。
- 图片提供查看、复制图片及保存；语音提供播放/暂停及保存；文件提供下载。多附件消息以右键命中的附件为准。失败可理解且可重试。
- 编辑仅显示服务端已支持的本人群文字消息入口；历史继续保留原文和每个版本。撤回仍受服务端一分钟权限约束。特殊卡片、撤回及待发消息不暴露不适用的操作。
- 同时只开一个菜单；连续右键、点击外部、滚动、切换会话、窗口失焦都正确关闭；Escape 返回原消息或更多按钮。支持 Shift+F10、方向键、Home/End、Enter，菜单不得被窗口裁切。
- 不拦截输入框的原生编辑菜单，不使预览弹窗的右键触发背后消息菜单。

## 验收与边界

运行真实 React 聊天页面的隔离 API 回归，覆盖复制选区、不同媒体、权限、原有编辑/引用/转发链路、连续菜单切换、焦点、缩放和截图。运行类型检查、构建和受影响 lint。发布 PC 静态前端，核对线上来源 SHA。

不更换 Tauri 外壳、不扩展尚无后端支持的好友消息编辑、不改消息历史和权限协议；真实用户会话不写测试消息。浏览器验收与 Windows 实机验收分别报告。
