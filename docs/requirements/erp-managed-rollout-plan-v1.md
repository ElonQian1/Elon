# ERP 商户托管发布计划 V1

## 目标

为已经纳入通用 ERP 且绑定开放商业商户身份的实例生成不可变、可审计、无秘密值的托管发布计划。计划把当前 ERP 配置修订、已固定蓝图版本、商户身份、托管实例合同、Rust 原生边缘路由和候选 Runtime Binding 绑定到同一 SHA-256，供后续托管节点预演、候选验证、激活和回滚流程复用。

本阶段只建立发布控制面的事实起点，不执行 SSH、建库、迁移、systemd 安装、DNS、证书签发或 Runtime Binding 切换。

## 用户工作流

1. 项目编辑者选择当前项目内的 ERP 实例并确认商户已同意生成托管计划。
2. 平台从数据库重新读取 ERP 实例、固定蓝图版本和开放商业商户绑定，不接受客户端代填这些身份。
3. 平台校验目标节点标识的输入格式，以及系统用户、端口、公开路径、配置来源、秘密文件来源、运行密钥引用、候选地址和能力清单摘要；目标节点的归属和在线状态留给后续机器任务核验。
4. 平台生成托管实例合同、边缘路由片段和候选 Runtime Binding，并将三者与来源修订绑定成不可变计划。
5. 相同实例、来源修订和参数重复提交时返回同一计划；任一参数变化产生新计划，不覆盖历史记录。
6. 项目成员可读取本项目、本实例的有界计划列表和单条详情，为后续节点任务提供稳定输入。

## 安全边界

- 只有项目 owner、admin 或 editor 可以创建计划；项目成员只允许读取自己有权访问的项目。
- 创建请求必须携带当前 `configuration_revision`，过期页面不能为已经变化的实例生成计划。
- ERP 实例必须处于 active，必须属于当前项目，并已经稳定绑定当前项目中的开放商业商户。
- 发布计划只保存秘密引用和受控文件来源，不允许出现密码、Token、Cookie、私钥或数据库连接值。
- `public_base_path` 必须与实例标识一致；候选 Runtime 地址的路径必须与公开路径一致。
- 计划中的目标节点只是待核验标识；计划生成不等于节点归属已确认、节点已预演、候选已安装、健康已验证、绑定已激活或生产已发布。
- 后续执行器必须按计划摘要领取任务并提交机器回执，不能将本阶段的用户确认冒充节点执行证明。

## V1 验收标准

1. 提供 `yilong.erp.managed_rollout_plan.v1` JSON Schema，明确来源、部署合同、边缘路由、Runtime 候选和边界字段。
2. 服务端从当前 ERP、蓝图版本和商户真源编译计划，拒绝跨项目、未绑定商户、归档实例和配置修订漂移。
3. 校验实例标识、系统用户、UUID、Linux 绝对路径、端口、运行密钥引用、目标节点标识格式、公开路径、受控候选地址和 SHA-256。
4. 计划正文使用稳定字段顺序序列化并计算 SHA-256；数据库保存并回读相同摘要。
5. 相同输入幂等返回原计划，不同输入保留为独立历史，任何计划均不可原地改写。
6. HTTP API 支持创建、列表和单条读取，并沿用项目访问控制；响应不包含秘密值。
7. 全新 SQLite 测试覆盖正常生成、幂等重放、修订漂移、身份错配、路径/地址错配和跨项目读取失败。
8. 文档与功能登记明确 V1 尚未执行远程预演、建库迁移、候选健康验证、Runtime Binding 原子切换或回滚。

## 非目标

- 不连接真实 Linux 商户服务器，不申请证书或修改防火墙。
- 不保存或传输数据库密码、Runtime Secret、SSH 私钥和第三方平台凭据。
- 不自动创建 PostgreSQL 数据库或运行商户迁移。
- 不把计划状态标记为 deployed、active 或 verified。
- 不替代后续节点身份、任务租约、机器签名回执和双向健康验证。
