# 群聊文字编辑与修改记录

## 用户需求与范围

用户明确要求直接实现 APK、Windows 和网页三端：本人发错的群聊文字可以编辑，群友能看到修改标记，并查看上一版及更早的完整文字。适用于现有群聊；保留消息、附件、回复、置顶、转发和通知能力。

## 产品规则

- 群成员可以编辑自己尚未撤回的文字，不设发送后的时间截止；不支持替换附件或编辑项目卡片。
- 第一次发送为第 1 版，每次有效编辑追加一版，旧版本不可由普通编辑接口改写或删除。无内容变化的重复保存不增加版本。
- 消息保留原 ID、发送时间和排序，显示“已编辑 · N 次”；点击可查看完整版本、修改时间及相邻版本的变化。历史分页加载直至原文。
- 只有当前有权查看群消息的成员可以读取历史。撤回后按现有撤回规则隐藏正文和公开历史，审计记录仍保留在服务端。
- 保存时核对版本号，多设备冲突拒绝覆盖并保留草稿。用户必须核对最新版本后再次提交。
- 编辑使用独立输入框，保留普通聊天草稿；网络失败保留编辑内容，明确提示重试。
- 同群其他端原位更新消息并展示修改标记，不重复播放新消息提示音，不因编辑新增 AI 回复。
- 每条消息最多 4000 个 Unicode 字符，每分钟最多 30 次有效编辑。
- 编辑和历史弹窗沿用暗色主题，正文清晰可读，可滚动查看长文本，支持返回或关闭。

## 验收标准

1. 三端均能编辑本人消息，其他成员无法通过界面或接口修改他人消息。
2. 连续两次编辑后能查看第 1、2、3 版；包含中文、换行和表情的原文完整保留。
3. 编辑不改变发送时间、附件和排序，刷新及重进群后标记和内容仍正确。
4. 并发编辑只有符合当前版本的保存成功，冲突、断网及服务端写入失败不丢失既有历史。
5. 非成员、跨群消息 ID、撤回消息和项目卡片受到服务端限制。
6. 历史只能追加，事务失败整体回滚，重复提交幂等；客户端正确显示接口错误。
7. 修改通知不重复响铃或触发 AI；原有发送、媒体、下载和群聊操作回归通过。
8. 完成后端、PC 前端及 APK 构建验证和发布；设备验收与源码/构建验收分别报告。
