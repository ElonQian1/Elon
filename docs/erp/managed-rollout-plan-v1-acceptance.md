# ERP 商户托管发布计划 V1 验收

## 结论

主项目已能从当前 ERP 实例、固定蓝图版本和开放商业商户绑定编译不可变托管发布计划。计划把托管实例合同、Rust 原生边缘路由片段和候选 Runtime Binding 绑定到同一 SHA-256，并只保存秘密引用，不保存密码、Token、Cookie、私钥或数据库连接值。

该能力是发布控制面的事实起点，不是远程部署器。它不会连接目标节点、创建数据库、运行迁移、安装 systemd 服务、申请证书、切换 Runtime Binding 或修改线上流量。

## 已交付

- `contracts/erp/managed-merchant-rollout-plan-v1.schema.json`：固定发布计划字段和五项未完成边界；
- `server/src/erp_blueprint/managed_rollout/`：计划模型、输入校验、编译、持久化、访问控制和定向测试；
- SQLite V280：保存 planned-only 历史，并以实例和计划摘要保证相同输入幂等；
- HTTP 创建、列表和详情接口：沿用项目成员读取、编辑者创建的权限边界；
- Feature Registry 条目 `erp-managed-rollout-plan-v1`：供其他 AI 发现、认领和检查漂移。

## 关键约束

1. 来源实例、配置修订、固定蓝图版本和商户绑定由服务端重读，客户端不能代填。
2. 同一计划重复提交返回原记录；任一已编入合同的输入变化都会产生新摘要和新记录。
3. 回读同时核对数据库来源修订、蓝图版本、实例、商户、状态和正文摘要，任一不一致均失败关闭。
4. `target_node_id` 当前只校验格式，不证明节点属于当前用户、在线或具备容量；计划正文明确记录该边界。
5. 候选 Runtime 只形成待验证配置，不激活现有绑定，也不声明支付和外部平台适配器可用。

## 验证范围

定向测试覆盖计划生成、重复提交、输入变化、秘密不回显、正文和来源列篡改、过期配置修订、未确认、路径及地址错配、跨项目访问，以及进程内 Axum 的未登录拒绝、创建、列表和详情读取。

合同 JSON 解析、Rust 格式化和 Git 差异检查已通过。Rust 定向测试命令已执行，验证指纹为 `bedbb48820f7ec063ef3e875a1d3a0ab55e7fb1b87baa97211361de82df190d1`；本功能先前暴露的编译问题已经消失，但整个 `elon-server` 测试目标仍被分布式算力并行模块的 25 个既有编译错误阻断，尚未进入本模块测试执行阶段。因此本功能保持 `implemented`，不能升级为 `verified`。

## 下一阶段

1. 用目标节点的机器身份、项目归属和容量检查领取计划，并返回绑定计划摘要的脱敏预演回执。
2. 将建库和迁移拆成显式批准、短租约、可恢复且有备份依据的节点任务。
3. 安装候选版本后执行双向健康检查，不直接覆盖当前 Runtime Binding。
4. 健康通过后原子激活新绑定；失败或人工回退时恢复上一绑定和版本。
5. 完成真实 Linux、DNS、443、CA 和单商户回滚演练后，再开放商户自助发布入口。
