# ADR：开放商业接入器任务领取与租约 V1

## 背景

平台已经能够从终态业务证据派生 ERP/CRM 待衔接队列，也允许接入器使用只写机器凭据提交回执。但只写凭据无法主动获得待处理任务，若多个适配器自行轮询项目接口，还会扩大读取权限并可能重复处理同一业务结果。

## 决策

1. 现有机器凭据继续默认只有 `business_handoff.write`。项目编辑者只有在签发或轮换时显式开启任务领取，凭据才增加 `business_handoff.claim`；旧凭据不会自动扩权。
2. 领取入口从 Bearer 凭据派生项目、商户、接入器和凭据版本，不接受客户端另行指定这些边界。每次最多领取一条成功、带有效标准业务回执且尚未解决的终态结果。
3. 任务结果只随成功领取返回，不提供整库查询或任意 Invocation 读取。租约为 60–900 秒，一次性租约密钥只显示一次，服务端只保存 SHA-256。活动租约可使用同一密钥按 60–900 秒续租，但绝对期限固定为首次领取后 1 小时，续租不能突破该期限。
4. 数据库对同一 Invocation 建立“最多一个活动租约”的部分唯一索引。领取使用立即事务，先把超时租约置为 `expired`，再原子创建下一次尝试。
5. 完成入口必须同时提交有效机器 Token、租约 ID 和租约密钥。回执插入与租约改为 `completed` 在同一立即事务内完成，并把租约 ID 固化到回执；同结果重放返回原回执，不产生第二条记录。
6. `rejected` 回执继续进入可重试状态，但按尝试次数采用 30、60、120、240、480 秒，之后最高 900 秒的有界指数退避；领取顺序优先从未尝试和最久未尝试任务开始，避免单条失败任务长期阻塞后续任务。第 6 次拒绝后暂停自动重试并标记“需人工处理”，项目编辑者明确确认重新排队后才能产生下一次尝试。活动租约超时后也可重新领取。
7. 接入器还可使用当前租约密钥主动释放任务，原因只允许停机、容量不足、临时故障或人工释放；释放不创建业务回执，任务立即可重新领取。
8. 凭据轮换、撤销、到期或接入停用后，旧租约不能完成或释放。
9. 项目成员可在 PC 工作台查看最近租约的处理中、退避中、可重试、需人工处理、已回执、已释放和已超时状态，但看不到租约密钥或原始 Token。重新排队只恢复协议内重试，不证明故障已修复，也不移动资金。
10. PC 与项目内 AI 使用同一领域服务读取租约；AI 恢复暂停任务同样要求项目编辑权限和 `confirmed_by_user=true`，不能绕过人工确认。

## 边界

- 当前不自动调用任何美团、抖音、京东、淘宝闪购或生产 ERP 接口。
- 领取结果来自一龙平台已经保存的商户能力终态结果，不等于平台独立核验外部订单、库存、支付或履约。
- V1 不提供超过 1 小时的租约、批量领取、可配置优先级、可配置死信策略或跨运营方任务总线；当前只采用受硬期限约束的续租、固定的第 6 次拒绝暂停与编辑者人工恢复。处理时间超过 1 小时的适配器必须拆分任务。主动释放始终可重试，不代表永久拒绝或外部处理结果。
- `adapter_token_authenticated` 仍表示机器身份来源；新增 `adapter_claim_id` 只证明该回执绑定了有效租约，不提升外部事实权威。
