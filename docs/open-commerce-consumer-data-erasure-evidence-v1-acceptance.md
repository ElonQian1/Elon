# 开放商业消费者删除请求外部证明 V1 验收

## 当前状态

`verified_local_http_pc_build`

## 已形成代码

- V160 新增追加式外部删除证明账本，单个删除请求可记录多个外部系统证明。
- 只有商户已声明完成的请求可附加证明，且只有商户项目编辑者可提交。
- 提交字段包含证明类型、外部系统、回执编号、回执 SHA-256、摘要和显式未核验确认。
- 相同请求、外部系统和 SHA-256 重复提交返回既有记录，不重复写审计。
- 消费者查询按本人项目和本人账号隔离；商户查询按项目与商户隔离。
- PC 商户端可在完成请求下追加证明，消费者端可查看证明摘要和固定来源边界。
- 响应固定返回 `merchant_supplied_unverified` 与 `platform_verified: false`，不冒充外部平台核验。

## 已验证

- V160 可重复执行；证明类型、64 位小写 SHA-256、业务唯一约束和删除请求外键级联由真实 SQLite 验证。
- 未登录、跨项目、未完成请求、只读项目成员、未确认“平台未核验”和错误商户均失败关闭。
- 相同请求、外部系统和摘要重放返回同一证明且只写一次审计；不同摘要形成追加记录。
- 商户普通成员可读取但不能提交；消费者只能读取本人项目和账号关联证明，无关消费者项目返回空列表。
- HTTP 响应不暴露提交者用户 ID、消费者账号或消费者项目，并固定返回 `merchant_supplied_unverified` 与 `platform_verified: false`。
- 可携带包 Rust 专项通过，覆盖当前删除证明投影及兼容读取路径。
- PC 开放商业静态契约、TypeScript 检查和 Vite 正式构建通过。

## 后续边界

- 外部适配器可在获得官方授权后自动提交回执，但必须保留来源身份和验证结果。
- 原始回执文件、签名验证、可信时间戳和可选链上摘要应作为独立版本设计。
- 删除证明已进入 V5 可携带数据包，当前 Rust 专项已通过；版本与兼容边界见 `docs/decisions/open-commerce-consumer-portability-exports-v5.md`。真实下载文件、跨运营方传输和浏览器验证仍未执行。
