# 币安首次列表上下文缺失恢复

范围遵循[主 APK 会话服务 V2](../requirements/android-exchange-session-host-v2.md)：只改主 APK 托管会话，不迁移量化产品 UI，不新增私有端点或交易权限。

## 故障证据

手机量化 0.7.6 停在网格连接页，显示“自动连接尚未就绪”。主 APK 1.1.1632 的 MCP 回读为文档 finished、适配器已绑定、主会话有效，但 identity/list 请求和响应计数都为 0，列表未验证；无创建或管理确认页。

量化重试仍然超时。通过现有只读 `binance_manage_read/reload` 重载官网文档，再由量化刷新，恢复一条新鲜网格，量化进程未重启，登录保留。此次证据没有解释网站首次未形成请求的底层原因，不归因于升级或网络代理。

源码确认适配器在没有观测到原始列表请求上下文时返回 `refresh() == false`；主会话此前忽略返回值，因此反复恢复始终没有可重发的读请求。

## 修复边界

- `BinanceHostRuntime` 的恢复和连续授权恢复共用读取回调，`BinanceReadRecovery` 管理受限重载预算。
- 原文档至少加载 10 秒且返回明确的 false，才考虑一次官网重载。true 或适配器不存在不会触发。
- 回调必须仍属于原 WebView 和文档、有效会话、网格路径；列表尚未新鲜，WebView 未附着于用户页面，没有创建/管理观察控制器。
- 与创建/管理共用互斥槽；占用时不抢占、不耗尽恢复预算。只重载页面，不提交或重放业务命令。
- 重载产生的新页面事件不重置预算；只有经验证的新列表开启下一次恢复机会。会话失效后旧回调不能作用于新文档。
- MCP 新增进程内恢复次数和本轮预算状态，不输出账号、策略、金额或凭据。

既有 JavaScript 只读适配器 19 项断言、会话 22 项测试、诊断 6 项测试通过。Release 网格 Kotlin 回归 106 项全部通过，包含新增恢复策略 9 项；源码和文档增量门禁通过。

正式主 APK **1.1.1633 (1633)** 已经官方发布入口构建、签名、发布，并通过 `adb install -r` 覆盖安装。源码为 `ed7b5234ca935b93753af592e45f12ee0d3bb284`；本地及线上 APK SHA-256 一致：`c8b72d58066e00b5dfe58bc2093969c0ec63bc4dd86fa8d288f7206fe3049ea7`。APK 签名校验通过，MCP 回读安装版本一致。

量化 0.7.6 原进程重新进入前台后，连续授权自动恢复到 `read_v2`，显示一条新鲜网格、收益摘要和可见创建/刷新入口；没有重新登录、重新授权或重启量化进程。主端回读当前子账户、有效会话、已验证列表一条，创建确认与管理页面均未打开。

本次安装后的官网首次加载直接成功，`read_recovery.reload_count=0`。新增自动重载分支通过纯策略测试及旧版手工只读重载恢复证据支持，**尚未进行真机受控故障注入**，不能宣称已实测自动重载。它只修复明确返回 false 的首次请求上下文缺失，不保证网站登录挑战、网络失败或 Android 杀进程后始终可用。

手工只读重载成功不等于新增自动恢复分支已经通过真机故障注入；两类证据必须分开。没有创建、修改、终止网格或清理登录资料。
