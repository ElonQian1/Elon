# 本人币安网格人工创建 V1

## 已接受范围

用户要求实际搭建创建链路，并由本人执行下单测试。本功能独立于既有只读授权：量化 APK
提供入口，正式主 APK 托管官方会话和原生参数确认页。仅本人自有资金技术测试，不承接
团队资产公示、用户募资、代客交易、无人值守下单或承诺收益。用户主动测试的请求可由
主 APK 在本机官方页面会话中发送；AI、MCP、后台任务与 ContentProvider 无提交入口。

本需求接受对本人网站私有创建接口的显式适配；不修改 Paper/sandbox 后端或添加全局
live 开关。旧读取 grant 不升级为交易 grant。主/子账号可互换，最终确认始终绑定当前
实际认证 UID；以往的预算、设备名称或父子关系不能代替本次账号和参数确认。

## 垂直链路

1. 量化正式签名 Activity 发起带随机 nonce 的专用主 APK Activity；双方核验包、签名、
   调用组件、结果版本和 nonce，不经 URL 传递参数或凭据。
2. 主 APK 原生表单明确展示方向、标的、保证金、杠杆、价格区间、格数、间距及终止处理。
   使用十进制精确计算 gridInitialValue；不将请求名义金额冒充投入保证金。
3. 单独检查当前会话及参数。身份、页面、参数变化使准备结果失效。最终由用户在主 APK
   可见确认页点击提交；拒绝遮挡点击，不提供 AI/MCP 的交易按钮动作。
4. 固定创建路径、方法及类型化字段；网站凭据仅留在同页闭包，禁止 Cookie/CSRF/token
   出页面、IPC、日志或测试 fixture。禁止任意 URL、脚本、方法覆盖、跳转重放和自动重试。
5. 写前落地本机小型状态记录。未确认结果、进程终止或页面丢失按“结果未知”恢复，绝不
   自动补发。用户可查看官网并人工结束核对；此操作不宣称服务端不存在策略。
6. 成功响应只表示受理。保留 strategyId、原始状态、clientStrategyId，固定 GET 查询详情
   时核对账号和策略身份。运行状态不代表资金、所有挂单或仓位已对账。
7. 关闭页面返回严格版本化结果；量化页显示受理、拒绝、未知或未提交，并可重新授权读取。

## 参数与发现边界

已观察路径及源码来源见 ../reports/binance-grid-runtime-contract-20260907.md。15 字段样本
不是完整服务端 schema。首轮只支持静态 USD-M 基础网格；不自动修改持仓模式、不启用
追踪、自动加保证金或抄单。服务端准入和交易规则不得靠重试或账户设置变更绕过。
未知字段语义或必要动态配置缺失时停止准备，保留官网入口。

  错误、超时和迟到回执；fixture 只使用合成账号与金额。
- 主 APK 与量化 APK 构建、签名、安装版本和源码分别留证；只读回归保持通过。
- 用户实际提交前的检查可由工具验证，工具不得点击最终提交或调用交易端点。
- 用户真实创建后再记录本账号策略详情和运行结果；未经人工测试维持
  acceptance_status=user_action_required，不能宣称创建已实盘验收。
