# 消费者可携带数据包 V5 删除证明验收

## 当前状态

`implementation_partially_verified`

## 已形成代码

- 新导出 Schema 升级为 V5，V4 常量保留为历史兼容版本。
- V5 在同一快照事务中读取当前用户的删除请求和关联外部证明。
- 可携带证明不含提交者账号和原始回执，仍固定为商户提供且平台未核验。
- 服务端验证证明 ID 唯一、请求存在且已完成、商户一致、字段边界、摘要格式和 RFC3339 时间。
- V1-V4 缺失新字段时保持空值不序列化；旧版本显式夹带 V5 字段时失败关闭。
- 导出与导入摘要增加删除证明数量，PC 列表显示该数量。
- 导入仍为隔离快照，不把证明合并到当前数据请求、关系或 ERP。

## 已验证

- 真实 Store 与服务链生成的 V5 包可包含一条已完成请求的商户未核验删除证明；重复幂等请求复用同一导出，摘要可重算，且负载不含证明提交人内部身份。
- 没有证明时 `data_erasure_evidence` 保持空集合且不进入规范 JSON，包仍可通过完整性复核。
- 重新计算摘要后，`platform_verified=true`、关联请求非完成、重复证明 ID、超过 5000 条和 V4 显式夹带 V5 证明均失败关闭。
- 普通 V5 包可幂等写入当前用户和目标项目独享的隔离快照，完整保留关系、已完成删除请求和证明；导入前后关系、Grant、删除请求和删除证明业务主表计数不变。
- 来源运营方 RSA 签名可在目标项目的消费者信任公钥下验证并形成可信快照；密钥撤销后不能用于新的签名导入。
- 相同 V5 信封不能从既有来源运营方改标为另一运营方，失败后原隔离快照仍保持未信任且不含签名。
- V5 父模块定向验证指纹为 `99ec0df9e0e912a0b7ad08dfb5d11598a5cda84c16c191c1c213a8b482ef3d07`，结果为 6 项通过、0 项失败；其中导入子模块单独验证指纹为 `f7039619eff22376447db4a5c7de96f4e20c0aa0996350f75ce66e57d0e1ae9e`，结果为 3 项通过、0 项失败。

## 仍需统一回归

1. 运行 PC 严格类型检查与生产构建，复核 TypeScript 类型和下载展示边界。
2. 固定 V1、V2、V3、V4 历史样本，验证规范 JSON 和 SHA-256 逐字节不变。
3. 创建含多条证明和恰好 5000 条证明的 V5 包，验证稳定排序与边界值可接受。
4. 继续篡改请求 ID、商户 ID、证明类型、来源、摘要和时间，确认各字段失败关闭。
5. 在客户端解密加密 V5 归档后上传服务端，确认仍只形成隔离快照并保留原包。
6. 验证 V1-V3 显式夹带 `data_erasure_evidence` 时被拒绝。
7. 验证 PC 下载前摘要复核、导入计数和历史包展示。

## 未验证边界

本批没有运行客户端加密 V5 归档解密上传、PC 构建、浏览器下载或 V1-V4 固定历史摘要样本。服务端普通及来源签名 V5 导入已验证，但仍不能证明 PC/SDK 加密归档全链路、跨运营方公共网络或生产信任治理已经成立。
