# 微信导出聊天记录接入

## 范围

用户主动在微信选择消息并通过系统分享导出 ZIP。一龙接收后本地解析、预览，由用户选择群聊并确认发送。群成员在 Android、PC 和 PWA 中阅读嵌套记录及附件，返回时保留群聊现场。

不读取微信数据库、不获取其他聊天历史、不伪造微信账号 ID/头像。未导出的图片、文章正文、视频号媒体及原始富文本格式不能凭空恢复。此功能不自动把导入记录发送给 AI。

## 用户确认后分析

Windows 卡片提供“AI 分析记录”和右键/多选入口；Android 长按卡片选择“AI分析记录”或多选后的“AI 分析”。确认后复用群 ChatGPT 私有上传、发送和幂等回群链路。

服务端从所选群消息的持久化绑定读取记录全文，保留顺序、发言者、时间和 `parent_id`，不把摘要或卡片 JSON 当正文。已导出的图片及支持文件通过带群权限校验的媒体地址下载，再私有上传至 ChatGPT；平台凭证只发往平台，不交给 ChatGPT 或外站。

音视频、未导出的媒体和链接指向的网页正文不在本次读取范围，提示词显式注明。当前沿用选区 20,000 UTF-16 字符、最多 9 个文件、每文件 8 MiB 的发送上限；超限整体停止，不自动截断、降级为摘要或重发。撤回记录、退出群聊、账号变化会阻止继续发送。

包含记录的多选不提供普通纯文字复制/转发，以免泄漏内部卡片数据；阅读器原有复制/转发不变。开放继续讨论时携带完整记录文本、问题和答案，但不自动再次上传原附件。PWA 暂无群 ChatGPT 执行器，保持原有阅读功能。

实现和验收状态见 [微信记录群 AI 分析](reports/wechat-record-group-ai-20260929.md)。

## 数据合同

- 版本：`chat_record_bundle_v1`。Android 位于 `chatrecords`；后端位于 `store/articles/chat_records`；PC 位于 `friends/chat-records`。
- `messages` 为保序数组，以 `parent_id` 表达转发层级。保留发送者显示名、导出时间字符串、正文、来源类型、附件文件名及受权限保护的附件 ID。
- 不按时间重新排序、不合并重复正文、不从文件名推断消息时间。`raw_text` 保留完整导出文本。
- 群消息只包含 `【一龙聊天记录】` 卡片引用及摘要，不复制整个文档。服务器读取文档及附件均核验群成员资格；附件不是公开地址。Android 最近验证的本地缓存使用下述短期权限窗口。
- `operation` 为导入草稿的稳定标识；同用户、同群、同操作和同内容只生成一次群消息。内容冲突返回 409；撤回、删除后不能通过同操作重发。

## 输入与限制

Android 同时接收 `ACTION_SEND` 和 `ACTION_SEND_MULTIPLE` 的 ZIP。实际微信样本即使只有一个 ZIP 也使用后者。增加 `application/zip`、`application/x-zip-compressed` 和通用二进制 MIME 的入口，收到文件后仍需验证格式。

每次一份 ZIP；压缩文件和已读取解压内容上限 64 MiB，目录项上限 256。TXT 上限 1 MiB，文档上限 2 MiB，消息上限 2000，嵌套最多 8 层，附件最多 64 个、单个 12 MiB。后端还限制每用户文档和媒体存储量。

拒绝路径穿越、绝对路径、重复 ZIP 路径、压缩比异常及 CRC 错误；解包附件使用本地生成文件名。附件按精确路径或唯一 basename 匹配，同名歧义和缺失文件显示提示，不擅自选择。未知消息格式保留原文阅读。

## 恢复与权限

导入在后台线程执行，草稿采用 AtomicFile 保存，用户未确认前不上传。发布前固定群、文档和操作标识；响应丢失后可重试同一记录。账号变化停止请求，禁止把旧账号草稿交给新账号发送。普通文字/图片/PDF 分享链路保持原样。

服务端将发布记录与群消息写入同一事务，单独存储附件并去重。仅发布者可撤回；退群及撤回后不能读取正文、附件。已被群成员另行保存的内容无法远程收回。

## 验证入口

阅读器交互与缓存修复见 [聊天记录阅读器修复](reports/wechat-record-reader-cache-20260928.md)。群里发送的始终是结构化记录引用，不是每次打开重新下载、解压 ZIP。

群聊启用长按后文字区域吞点击的回归及真实触摸验收见 [记录卡片点击修复](reports/wechat-record-card-tap-20261003.md)。

特殊卡片的菜单采用增量组合，通用引用、多选、书签等不因展示类型被替换；见 [聊天记录消息菜单](reports/wechat-record-message-menu-20261003.md)。

Android 二次打开采用 [近期缓存先显示与本地管理](reports/wechat-record-cache-reopen-20260929.md)：5 分钟验证窗口、正文与媒体分队列、关闭即取消、128 MiB/7 天回收及手动清理。该策略替代旧报告中 Android 每次等待网络复核的规则。

PC/Win 使用 [附件本地缓存](reports/win-record-media-cache-20261003.md) 与 [正文近期缓存先显示](reports/win-record-reopen-latency-20261003.md)：最近 5 分钟验证过的正文先显示，再后台复核；过期先核验。附件复用 32 MiB 内存与 128 MiB/7 天磁盘缓存；更多菜单可清理本条缓存。PWA 保留 HTTP 条件缓存策略。

头像、导出标签折叠、卡片复制/转发和视频缩略图见 [阅读体验与验证](reports/wechat-record-reader-presentation-20260929.md)。这些是展示层规则，`raw_text` 和原始链接保持完整。

- Android：`WechatImportTest`，包含缩进层级、顺序、重复内容、缺附件、同名附件、路径穿越、体积限制。
- 私人样本只通过进程环境 `ELON_WECHAT_TEST_SAMPLES` 指向本地 ZIP，不提交样本、原文或日志正文。
- 后端：`store::articles::chat_records::tests`，覆盖幂等、群权限、撤回、删除、媒体绑定和保留原文。
- PWA 阅读：`scripts/test-chat-records-reader.cjs`，通过 `PLAYWRIGHT_MODULE` 指定已有 Playwright；合成数据测试桌面/手机、嵌套返回、图片、原文、注入文本和账号切换。

- Rust 后端 4 项测试，覆盖层级、原文、幂等、群权限、附件绑定、撤回、删除及伪造卡片拒绝。
- PC TypeScript 类型检查及 3 项请求合同测试通过。
- PWA 在 1280 和 390 宽度通过阅读交互测试，包含图片、嵌套返回、原文、注入文本及切换账号关闭。
- 源码体积、文档模块化和 Git diff 检查通过。

用户入口：微信多选记录 → 转发到其他应用 → 一龙 → 预览记录 → 选择群聊并确认。群成员点击卡片阅读；嵌套记录逐层进入、返回。

发布和安装结果以正式发布脚本、版本回读及任务收尾记录为准。真实微信分享面板点按、实际视频播放尚未做物理设备交互验收，不以编译或模拟测试替代该结论。
