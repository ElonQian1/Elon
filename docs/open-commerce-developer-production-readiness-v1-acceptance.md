# 开放商业开发者 App 生产就绪总览 V1 验收

## 当前状态

`implementation_compiled_local_projection_verified`

生产就绪模块已随 Rust `elon-server` 测试目标完成编译；五项 SQLite 专项测试已直接验证八步依赖顺序、完整阻断列表、稳定下一步、生产调用与生产 Webhook 的独立结论、双开关组合、准入暂停后的失败关闭，以及资料、域名、准入、凭据和 Webhook 状态矩阵。三项进程内 Axum 测试又验证登录、项目与 App 管理边界、响应脱敏、App 存在性隐藏，以及停用和重新启用后的当前状态读取；当前生产就绪专项共 `8 passed, 0 failed`。

## 已形成代码

- App 级生产就绪 API，复用项目编辑权限和 App 管理归属边界。
- 八个固定步骤、稳定阻断码、按依赖顺序返回的下一步，以及完整阻断列表。
- 生产调用和生产 Webhook 两个独立就绪结论，避免“有凭据”等同于“通知已配置”。
- 当前资料修订与域名、准入、凭据绑定检查，以及生产双开关和活动生产订阅检查。
- PC 独立总览组件，可选择 App、刷新状态并把内部阻断码显示为明确操作提示。
- 全部状态只读派生，不新增数据库迁移，不自动改变 App、审核、准入、凭据或订阅。
- 测试通过仅在 `cfg(test)` 下的显式开关输入验证投影，不修改进程环境变量，也不启用真实生产入口。

## 已验证子集

- 新建活动 App 按 `app`、`manifest`、`domain`、`admission`、`credential_gateway`、`credential`、`webhook_gateway`、`webhook` 固定顺序返回步骤，首个动作稳定指向资料审核。
- 当前资料、域名、准入、凭据和活动生产 Webhook 均满足时，双开关关闭、仅凭据开关开启和双开关开启分别产生“全部阻断”“仅调用就绪”和“调用及通知均就绪”。
- 准入暂停后，投影立即回退到准入、凭据和活动 Webhook 三项阻断；当前凭据与活动生产订阅均归零。
- 资料退回、域名失败、域名旧修订和准入旧修订分别按依赖顺序返回稳定阻断，不会被后续凭据或 Webhook 状态掩盖。
- 已过期或已撤销的生产凭据均不计为当前凭据；只有已验证且活动的生产 Webhook 计入通知就绪，待验证或手动停用订阅均保持失败关闭。
- 未登录、非项目成员、只读成员、非 App 所有者的普通编辑者及跨项目 App 路径均失败关闭；App 所有者编辑者、项目 `admin` 和 `owner` 可读取。
- 跨项目 App 路径与不存在 App 返回相同失败响应，不向有权访问项目的调用方泄露其他项目 App 是否存在。
- App 停用后下一步立即回退为 `app_inactive`，重新启用后的下一次请求立即读取活动状态并回到资料审核阻断，不依赖路由缓存。
- HTTP 响应不包含 App 所有者 ID、测试或生产 Token、主体登记编号及域名 challenge 摘要。

## 统一回归必须验证

- 资料待审和旧资料修订；资料退回投影已通过专项测试。
- 域名到期状态；失败和旧修订投影已通过专项测试。
- 准入待审和退回；缺失、旧修订和暂停投影已通过专项测试。
- 凭据与状态写入真正并发变化；到期、手动撤销和资料修订撤销联动已通过专项测试。
- 真正并发写入与 HTTP 读取时的状态竞争；不存在 App、停用与重新启用后的相邻请求结果已经通过进程内 Axum 测试。
- PC 快速切换 App、过期响应、刷新、空列表、小屏布局和生产构建。
