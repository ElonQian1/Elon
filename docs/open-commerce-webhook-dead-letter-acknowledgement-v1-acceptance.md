# 开放商业 Webhook 死信人工确认 V1 验收

## 当前状态

`verified_local_store_subset`

Rust 服务端已编译；全新 SQLite 数据库上的专项测试验证死信确认、同一操作人和原因幂等重放、不同原因不可覆盖、健康计数收口，以及人工重试原子清除确认字段。历史库升级、HTTP 权限、真实并发和 PC 页面仍未验证。

## 已形成代码

- V157 为投递增加确认时间、确认用户和确认原因，并增加待处理死信查询索引。
- 项目编辑者可确认本人 App 下的单条死信；App、订阅或生产资格失效不会阻止历史死信收口。
- 同一用户和同一原因重复请求幂等，其他覆盖请求失败关闭。
- 原事件、失败码、投递状态和尝试次数保持不变，确认不冒充成功送达。
- 人工重试原子清除确认字段，并继续复用订阅验证、凭据环境和生产资格检查。
- 健康摘要区分待处理死信与已确认死信，仅前者要求处置。
- PC 投递列表支持填写原因后确认，并继续保留单条重试入口和确认标识。

## 统一回归必须验证

- V157 从既有 V156 数据库升级、新增字段默认值、索引及旧死信统计口径。
- 非死信确认、跨项目、跨 App、非所有者、只读项目成员和不存在投递的拒绝路径。
- 4/500 字符边界、空白、控制字符和不同用户覆盖冲突。
- 并发确认时仅一个请求写入，失败请求不能覆盖确认人、时间和原因。
- App 停用、订阅停用、生产凭据撤销或到期后的确认，以及不满足生产资格时的重试拒绝。
- 确认前后完整健康状态与重新投递失败后的再次收口。
- PC 加载、提交、错误提示、快速切换 App、刷新、小屏布局和生产构建。
