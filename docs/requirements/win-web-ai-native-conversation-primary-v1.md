# Win 网页 AI 原生会话主界面 V1

## 背景

Win 生产聊天曾在正常聊天画布上自动叠加一个 `contentOnly` 官方 WebView。该区域只保留官网最后一条完成的助手节点，会遮住 React 已同步的用户/助手历史气泡；它同时把官网输入框隐藏，导致语义适配器把 `composerReady` 降为 `false`，最终形成“能看最后一条回答、不能继续上下文聊天”的断裂体验。

## 范围

- 仅调整 Win/Tauri 与 PC React 的网页 AI 生产聊天；不修改 PWA 或 Android。
- 正常“聊天”画布始终使用现有原生消息列表、结构化富卡、来源组件和缓存，完整展示用户与助手回合。
- 官网 WebView 继续持有真实会话、Cookie、富内容和输入能力，但不再自动覆盖正常聊天画布。
- 用户点击“官网完整内容/官方页”时，才在现有内部浏览器标签显示完整官网 WebView；关闭或返回后恢复同一个原生会话。
- 删除仅服务于自动“最后答案覆盖层”的 PC/Tauri 代码，不新建聊天窗口或第二套消息状态。

## 验收

1. 正常聊天画布不会自动呈现 `contentOnly` 官方 WebView，React 用户气泡、助手气泡和历史回合保持可见。
2. 后台官网输入框不再因答案覆盖层 CSS 被隐藏，`composerReady`、草稿和发送继续由既有语义适配器判断。
3. “官网完整内容”仍显示完整官方页面及其天气、地图、图表、图片、引用和交互，并可返回原生聊天。
4. 本机缓存、结构化富内容 AST、来源 Logo、会话绑定和游客身份逻辑继续复用，不建立重复实现。
5. PC 契约、TypeScript、Tauri Rust 定向测试、生产构建和 Win 本机更新通过。

## 非目标

- 不复制或打包厂商前端源码。
- 不绕过登录、真人验证、地区限制或账号选择。
- 不承诺所有官网私有交互都能在原生富卡中逐像素复现；精确保真由显式官网标签提供。
