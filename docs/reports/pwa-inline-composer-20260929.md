# PWA 单行聊天输入区与键盘间距

用户提供 iPhone PWA 和微信的对比截图，要求输入内容与操作按钮保持一行，减少键盘上方
的空白。本批修改 PWA 公共输入结构和群聊键盘适配，沿用 V2 主题及原发送链路。
Android 原生、项目广场、账号、上传协议和共享颜色 Token 不受影响。

## 实现与能力保留

- 真实 textarea 常驻输入行，点击直接聚焦，不再由占位按钮切换成上下两层。
- 附件、输入内容、表情入口、语音或发送按钮同排；文字换行才增长，高度最多 140px，
  超长草稿在输入框内滚动。按钮仍有至少 48×48 CSS px 的实际触控区域。
- 全屏编辑入口移入附件面板，沿用原有 Android 能力提示；表情入口也保留原能力边界，
  本批不宣称实现 PWA 表情选择或全屏编辑。照片、文件、录音仍用既有网页实现。
- 输入框增加明确名称和发送键提示；保留中文输入组合保护、草稿、附件选择和发送处理。
- 群聊记录键盘打开前的高度，即使 innerHeight 与 VisualViewport 同时缩小也能识别。
  输入期间不随键盘动画的小步缩高改写基准；关闭动画结束前不恢复底部安全区。
- 键盘打开时底部留白为 4px，总结条暂时收起；关闭后恢复手势安全区和总结条。
  缩放不追随固定视口，宽度变化重置基准。好友/项目采用单行输入，保留其原模式行。

WebKit 有键盘出现后底部安全区仍保留的公开问题记录；本批采用应用层视口适配，
不是操作系统修复。参见 [WebKit 217754](https://bugs.webkit.org/show_bug.cgi?id=217754)
与 [Visual Viewport 官方说明](https://webkit.org/blog/9674/new-webkit-features-in-safari-13/)。

## 验证证据

生产 HTML、CSS 和脚本在本机合成群聊中运行，不登录真实账号，不向生产上传或发消息。
390×844、常规文字大小的 WebKit 测量如下，数值是 CSS px，不是截图物理像素：

| 测量 | 修改前 | 修改后 |
|---|---:|---:|
| 聚焦且单行时的输入面板 | 104 | 52 |
| 包含外边距的整个输入区 | 116 | 64 |
| 键盘打开后的整个输入区 | — | 60 |
| 两行文字时的输入面板 | — | 74 |

- `test-pwa-inline-composer.cjs`：WebKit、Chromium 各 27 组测量，覆盖 320/390/430
  宽度、浅深主题、真实单次点击、单行/多行/清空、IME、仅视觉视口变化和双视口逐帧
  缩小、47/34 安全区、平移、失焦后关闭、缩放、横屏、附件中的全屏入口及好友模式。
  双视口动画用例在基准随小步变化时失败，固定输入期间基准后通过。
- `test-pwa-group-layout.cjs`：两个引擎各 14 组；群工具、草稿、阅读位置、长标题、
  150%/200% 文字、空/错误总结和返回好友继续通过。
- `test-pwa-chat-input.cjs`：两个引擎各 6 场景，群聊、好友、项目及浅深主题。
- `test-pwa-rich-attachments.cjs`：WebKit 20 / Chromium 21 场景，图片、文件、预览、
  语音、失败恢复继续通过；Chromium 录音使用生成音源，非真实麦克风。
- `test-mobile-conversation-polish.cjs`：WebKit 6 场景；同步其旧占位入口夹具，等待
  本机读取结束再导航，避免把页面卸载中止请求误记为跨域失败，不过滤页面异常。
- V2 治理自测 12 项及规范检查通过。源码与文档规模检查由提交门禁执行。

已查看浏览器运行截图。键盘及安全区为显式几何模拟，不能冒充 iPhone 系统键盘实测；
VoiceOver、真机性能及用户手机验收仍未执行。截图里的 iOS 辅助栏不属于网页输入区，
本批未修改它，也不承诺移除。前端运行证据与硬件验收分开记录。

## 发布与手机复验

通过既有 `publish-mobile-pwa-static.ps1` 原子发布自包含模板，来源提交、文件哈希及
HTTP/HTTPS 回读以本任务发布回执为准，无需服务器重编译或 APK 更新。
重新打开 PWA 并进入群聊，确认点空输入框后仍保持单行，键盘上方没有重复安全区留白；
长文字自然换行，清空后缩回。照片/文件/语音仍从原入口使用，退出键盘恢复底部安全区。
