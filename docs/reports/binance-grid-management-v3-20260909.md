# 本人合约网格：追加投入

主 APK 新增可发现的 `BinanceGridManageV2Activity`。正式量化消费者沿用签名、组件和 nonce 校验，发现 V2 后进入追加投入页面；旧入口保留原合同。真实操作只在本人可见页面确认，MCP 仍只有只读动作。

## 合同来源

沿用已取得的币安官方前端 `page-ee55.148047e5.js`，SHA-256 `7e4ef73c9811d2b2eab572e43acdb409045e46c999f521a0f899196bce464747`。模块38935定义 `/bapi/futures/v1/private/future/grid/update-grid-investment`；365112和370032附近构造 `{symbol,strategyId,investmentDelta}`，其中 delta 为用户输入的策略追加保证金，不是杠杆后的名义价值。模块45337按初始名义价值/初始杠杆+累计调整显示参考投入。前端 success 后刷新详情，不要求 settings/close 的 updateStatus 响应形状。

这属于官方静态源码证据，尚未取得本次用户实际追加的响应。没有凭空填余额或最高可追加额度；交易所仍须在提交时校验余额、限额和策略状态。

## 实现与兼容

- 每次只接受明确填写的正数，最多8位小数、单次不超过2,000 USDT；本机技术验证上限不代表止损保证。
- 追加前读取当前策略及精确投入数据，准备60秒有效。提交前再次核对账号、策略状态、既有设置、初始价值/杠杆和累计调整。任何变化均须重新检查。
- 固定接口只发3个字段，不串行修改设置、不替用户追加仓位保证金、不自动划转资金。
- 单次提交前保存未决记录；网络中断或不明确响应保持未知，不自动补发。V2日志兼容旧V1日志，只持久化目标累计调整值的指纹，不保存金额正文或可重放请求。
- 结果查询只能证明观察到目标值，不能证明该变化唯一由本次请求造成，也不清除未决记录。用户核对官网后结束本机记录。
- V1消费者不看到追加入口；若恢复到V2未决记录，旧回执安全降级为未知。新量化接受V2受理而策略状态未返回的情况，不伪造WORKING状态。
