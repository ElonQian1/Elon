# PWA 聊天图片粘贴与拖入

日期：2026-09-30。交付与测试证据，不定义新的产品规范。

## 范围与原因

Mac 用户反馈截图、微信复制的图片无法直接进入聊天。原 PWA 只接入文件选择器，没有聊天输入框的 `paste` 或聊天区域的 `drop` 处理。基线测试在 WebKit 中复现：携带 PNG 文件的粘贴事件没有被处理，也没有附件预览。

复用 `social_source_compose.js` 的附件生命周期，在原模块增加输入适配；页面只连接当前会话与发送器，无新增后端路由、协议、主题或 APK 改动。

- 群聊和好友聊天输入框支持图片/文件粘贴；输入栏与消息区支持拖入本地图片和文件。
- 先打开现有分享预览，确认发送后才上传，取消不上传；输入框原草稿保留。
- 同步读取 `DataTransfer.files`，为空时兼容 `items.getAsFile()`；不合并两份列表，避免同一附件重复上传。保留混合剪贴板中的文字作为可编辑说明。
- 给无名图片补文件名，按已知图片扩展名补空 MIME；不转换或伪造图片字节。
- 纯文本和链接保留浏览器默认粘贴行为，不解析、执行或远程抓取 HTML 中的图片。
- 复用每次最多 6 个、单个不超过 12 MB、非空、失败重试及不确定发送不自动重发等规则。无法读取文件时提示重新复制或选择文件。
- 当前账号/会话变化时撤销预览，引用通过原发送器校验；禁用输入、其他输入框和非社交聊天不被接管。
- 取消后立即再次粘贴允许打开新预览，避免原生 dialog 的异步 close 事件造成短暂吞图。

数据读取依据：[WebKit 剪贴板改进](https://webkit.org/blog/8170/clipboard-api-improvements/)、[DataTransfer.files 事件有效期](https://developer.mozilla.org/en-US/docs/Web/API/DataTransfer/files)。采用用户触发的粘贴事件，无额外后台剪贴板读取权限。

| 能力 | 实现 | 验证 | 用户验收 |
|---|---|---|---|

- `scripts/test-pwa-image-transfer.cjs`：WebKit 16 项，Chromium 18 项；后者额外验证 Windows 系统剪贴板图片、文字及真实 Ctrl+V。测试的系统剪贴板仅含合成图片与文字。
- 大小、数量、空文件、混合文件、空 MIME、无名图片、items fallback、重复事件、取消立即重贴、上传重试、切换会话、禁用输入和引用链路均通过。
- `scripts/test-pwa-rich-attachments.cjs`：WebKit / Chromium 各 20 项通过，覆盖原选择器、图文、文档、音视频、重试、取消、权限、录音释放与账号切换。
- V2 规范 12 项自测及检查、JS 语法、差异与提交门禁通过。预览截图检查保留现有控件和布局。
- 所有浏览器测试只访问 loopback 合成接口；无生产聊天写入。Windows WebKit 不能等同于 macOS Safari 或 Mac 微信实测；未使用真实 Mac 或手机。

## 交付与复验

提交推送后走 `publish-mobile-pwa-static.ps1` 发布完整内嵌资源模板；发布 SHA、摘要、入口只读校验及最终收尾状态保存在任务工件。无需增加后端路由或重建 APK。

Mac 用户刷新 PWA 后，在群聊或好友聊天点击输入框，复制截图/微信图片后按 ⌘V，确认预览再发送；本地图片也可拖入聊天区域。单纯复制图片网址仍按文字处理，不承诺所有外部应用均向浏览器提供图片字节。
