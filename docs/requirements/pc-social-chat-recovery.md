# Windows 会话缓存与消息同步恢复

## 目标与现状

Windows 的 `/pc` 好友和群聊页面首次加载失败时静默展示空列表，消息只有内存状态。私聊未订阅更新；群聊串行轮询缺少超时与恢复前台触发。全局 WebSocket 忽略好友/群聊事件，OPEN 状态的失效连接不能主动恢复。

本次只修改 React PC 客户端，复用已有聊天查询、preserve_unread 和 WebSocket 合同。缓存是近期内容的加速副本，不是完整离线历史归档。发送、编辑审计、附件和下载能力必须保留。不改 APK、移动 PWA、服务端数据库或真实用户消息。

## 验收标准

1. 同账号再次打开先显示有界近期会话和消息缓存，后台更新；缓存按服务器和账号隔离，退出登录清理，损坏或容量不足不能导致白屏。
2. 好友和群列表独立加载；加载中、成功空数据、失败可重试状态明确区分。局部失败保留已有内容。
3. 好友、群聊的新消息及编辑事件触发同步，轮询作为漏事件兜底；重复事件合并，不重复插入消息、不重放提示音。
4. 前台恢复、网络恢复、页面恢复和连接重建立即补齐；挂起请求有超时及取消，旧响应不能覆盖当前账号或会话。
5. 后台读取保留未读状态；前台打开的会话更新已读。权限失效清除对应缓存并停止展示。
6. 切换会话保留各自草稿；发送和修订结果不串入另一会话，失败保留可恢复内容。
7. 浏览器替身覆盖缓存重开、错误、超时、切换、前后台和实时消息；原修订记录、媒体回归及 PC 生产构建通过。发布后核对真实 `/pc/release.json`。

## 交付边界

缓存、同步调度和 UI 组装分模块；共享通知入口仅增加聊天事件转发和失效连接恢复。浏览器测试使用隔离账号和拦截接口，不写生产群聊。实际用户 Windows 休眠环境的长期验收由用户更新后反馈。
