# Windows 本地 AI 工作日报助手 MVP 技术方案

最后更新：2026-07-09

## 1. 结论

推荐采用“Windows 本地桌面端 + 本地 SQLite + 可替换 AI Provider”的方案，先跑通个人日报闭环，再考虑团队化和平台化。

这套方案开发量适中，隐私风险可控，也方便后续接入一龙 PC 节点或独立发布。

## 2. 推荐技术栈

### 2.1 桌面端

推荐：Tauri 2 + React + TypeScript。

原因：

- Windows 桌面应用体积小。
- 前端页面开发效率高。
- Rust 后端适合做系统权限、截图、SQLite、后台任务。
- 后续如果要接入一龙现有 Rust/PC 能力，技术栈更接近。

备选：

- Electron：开发快，但包体大、后台常驻资源占用更高。
- WPF/.NET：Windows 原生体验好，但与现有一龙技术栈距离更远。
- Python + PySide：原型快，但打包、权限、长期维护风险更高。

推荐结论：MVP 用 Tauri，不用 Electron。

## 3. 系统模块

### 3.1 Recorder 采集模块

职责：

- 定时触发采集任务。
- 截取当前屏幕。
- 读取前台应用名称。
- 读取前台窗口标题。
- 检查排除应用名单。
- 把采集任务交给 AI 分析队列。

关键规则：

- 采集间隔默认 1 分钟。
- 采集前先判断是否暂停。
- 命中排除应用时不截图，只记录“已跳过”。
- 连续失败时停止采集并提示用户。

### 3.2 Privacy Guard 隐私保护模块

职责：

- 管理排除应用名单。
- 管理敏感关键词。
- 管理暂停状态。
- 决定截图是否允许送去 AI。
- 控制原图保留策略。

MVP 策略：

- 默认不保存原图。
- 原图只在内存或临时目录中短暂存在。
- AI 分析成功或失败后都删除临时图片。
- 用户删除某天数据时，删除当天所有分析记录和报告。

### 3.3 AI Analyzer 分析模块

职责：

- 把截图、应用名、窗口标题发送给 AI Vision 模型。
- 要求 AI 输出结构化 JSON。
- 对 AI 输出做格式校验。
- 识别失败时生成低置信度记录。

结构化输出字段：

```json
{
  "summary": "正在修改登录页面样式",
  "category": "开发",
  "confidence": 0.82,
  "privacy_risk": "low",
  "visible_sensitive_content": false,
  "todo_or_risk": "登录按钮间距需要复查"
}
```

AI Provider 设计：

- `CloudVisionProvider`：调用云端多模态模型。
- `LocalVisionProvider`：预留本地模型接口，MVP 可以先不实现。
- `MockVisionProvider`：开发和测试用，不发送真实截图。

### 3.4 Timeline Engine 时间线模块

职责：

- 把连续相似记录合并成一个时间段。
- 统计应用使用时长。
- 标记低置信度记录。
- 支持用户编辑和删除。

合并规则 MVP：

- 同一应用、同一分类、摘要相似，并且间隔小于 10 分钟，可以合并。
- 如果窗口标题明显变化，不强行合并。
- 用户手动编辑过的记录不再被自动覆盖。

### 3.5 Report Generator 日报生成模块

职责：

- 根据当天时间线生成 Markdown。
- 支持模板化输出。
- 支持用户预览、编辑、复制、保存。

默认模板：

```markdown
# 工作日报 - 2026-07-09

## 今日概览

- ...

## 主要工作

- ...

## 时间线

- 09:30-10:20 开发：...

## 应用使用统计

- VS Code：3 小时 10 分钟

## 待办与风险

- ...
```

## 4. 本地数据设计

推荐数据库：SQLite。

核心表：

### 4.1 capture_events

记录每次采集事件。

| 字段 | 说明 |
|---|---|
| id | 主键 |
| captured_at | 采集时间 |
| app_name | 前台应用 |
| window_title | 窗口标题 |
| screenshot_policy | sent_to_ai / skipped_excluded_app / skipped_paused / failed |
| screenshot_hash | 原图 hash，可为空 |
| status | pending / analyzed / failed / deleted |

### 4.2 analysis_records

记录 AI 分析结果。

| 字段 | 说明 |
|---|---|
| id | 主键 |
| capture_event_id | 对应采集事件 |
| category | 工作分类 |
| summary | 摘要 |
| confidence | 置信度 |
| privacy_risk | 隐私风险 |
| visible_sensitive_content | 是否疑似敏感 |
| raw_ai_json | 原始 AI JSON，便于排查 |
| user_edited | 用户是否编辑过 |

### 4.3 timeline_segments

记录合并后的时间线段。

| 字段 | 说明 |
|---|---|
| id | 主键 |
| started_at | 开始时间 |
| ended_at | 结束时间 |
| category | 分类 |
| app_name | 主要应用 |
| title | 时间线标题 |
| summary | 时间线摘要 |
| include_in_report | 是否写入日报 |

### 4.4 reports

记录生成过的日报。

| 字段 | 说明 |
|---|---|
| id | 主键 |
| report_date | 日报日期 |
| markdown | Markdown 内容 |
| generated_at | 生成时间 |
| edited_at | 编辑时间 |

## 5. 数据流

```text
启动应用
  -> 用户开启记录
  -> Recorder 定时采集截图 + 前台应用 + 窗口标题
  -> Privacy Guard 判断是否允许分析
  -> AI Analyzer 输出结构化记录
  -> SQLite 保存文字化结果
  -> Timeline Engine 合并成时间线
  -> 用户查看/修正
  -> Report Generator 生成 Markdown 日报
  -> 用户复制或保存
```

## 6. 隐私风险

### 6.1 最高风险

截图可能包含：

- 聊天内容。
- 客户信息。
- 密码、验证码、Token。
- 财务、合同、医疗、法律材料。
- 公司未公开代码或商业机密。

如果调用云端 AI，这些内容可能被发送到第三方模型服务。

### 6.2 MVP 必须做的保护

- 首次启动显示隐私说明。
- 状态栏常驻显示正在记录。
- 一键暂停。
- 排除应用名单。
- 分析后删除原图。
- 用户可删除当天全部数据。
- 日报生成前预览确认。
- AI prompt 要求脱敏，不输出聊天原文、密码、Token、身份证号等内容。

### 6.3 MVP 不应承诺的事情

不能承诺：

- 绝对不会识别错。
- 绝对不会上传敏感信息。
- 自动脱敏 100% 有效。
- 排除应用能覆盖所有隐私场景。
- 云端模型不会保留任何数据，除非模型服务商合同明确支持。

## 7. 工程量评估

按一个熟悉 Windows/Tauri/AI API 的开发者估算：

| 阶段 | 内容 | 估算 |
|---|---|---|
| 需求和原型 | 页面草图、数据结构、隐私策略确认 | 1-2 天 |
| 桌面壳和基础设置 | Tauri 项目、托盘、设置页、本地配置 | 2-3 天 |
| Windows 采集 | 截图、前台应用、窗口标题、排除应用 | 3-5 天 |
| SQLite 存储 | 表结构、CRUD、数据清理 | 2-3 天 |
| AI 分析 | Provider 抽象、Vision 调用、JSON 校验、失败重试 | 3-5 天 |
| 时间线 | 合并规则、编辑、删除、筛选 | 3-5 天 |
| 日报导出 | Markdown 模板、预览、复制、保存 | 2-3 天 |
| 隐私和稳定性 | 首次提示、暂停、删除、错误提示 | 2-4 天 |
| 打包和自测 | Windows 打包、长时间运行测试 | 2-4 天 |

MVP 总量：

- 乐观：3 周左右。
- 稳妥：4-5 周。
- 如果要做漂亮 UI、自动更新、安装器签名、本地模型、团队同步，至少再加 4-8 周。

## 8. 主要技术风险

### 8.1 Windows 截图权限和多屏兼容

风险：多屏、缩放比例、远程桌面、HDR、锁屏状态可能导致截图异常。

处理：

- MVP 先支持主屏幕。
- 截图失败要记录错误，不让后台死循环。
- 后续再做多屏选择。

### 8.2 前台窗口标题读取不稳定

风险：某些应用标题为空、浏览器标题变化频繁、权限不足。

处理：

- 标题只是辅助信息，不作为唯一依据。
- 失败时写入未知。

### 8.3 AI 成本和速度

风险：1 分钟一次截图，一天 8 小时就是 480 次 Vision 调用，成本可能高。

处理：

- 默认 5 分钟间隔更省钱，用户可改成 1 分钟。
- 空闲或重复画面不送 AI。
- 截图压缩后再上传。
- 同一应用同一标题连续重复时降频。

### 8.4 AI 识别不准

风险：AI 可能把娱乐、聊天、开发、阅读误判。

处理：

- 输出置信度。
- 低置信度标记。
- 用户可编辑。
- 日报生成前必须预览。

### 8.5 隐私争议

风险：用户可能误以为“本地助手”完全不上传任何内容。

处理：

- 明确区分本地存储和云端 AI 分析。
- 设置页显示当前 AI Provider。
- 允许关闭 AI 自动分析，只保留本地时间线。

## 9. 版本路线

### v0.1 原型

- 手动触发截图。
- 手动调用 AI 分析。
- 保存一条分析记录。

### v0.2 MVP 内测

- 定时采集。
- 前台应用记录。
- SQLite 时间线。
- Markdown 日报导出。
- 暂停和排除应用。

### v0.3 可用版

- 托盘常驻。
- 设置页。
- 错误恢复。
- 应用时长统计。
- 数据删除。

### v0.4 增强版

- 周报/月报。
- 多日报模板。
- 本地模型 Provider。
- 飞书/企业微信导出。

### v1.0 商业化候选

- 自动更新。
- 安装器签名。
- 企业隐私策略。
- 团队模板。
- 可选一龙平台接入。

## 10. 建议的下一步

下一步不是写完整代码，而是先做两个决策：

1. 是否确认 MVP 只做 Windows 本地个人版。

如果确认，下一轮可以开始创建独立项目骨架和原型界面，但仍先不接真实 AI。
