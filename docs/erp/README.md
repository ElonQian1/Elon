# 通用 ERP 蓝图 V1

本目录描述一龙平台如何让小商户在不重复造轮子的前提下，获得可定制、可升级、可由 AI 管理的独立 ERP 项目。

## 一句话模型

官方蓝图提供稳定内核和扩展点；每个商户拥有独立项目、数据、主题和私有扩展；AI 在服务商户时优先组合现有能力，确认确有共性缺口后只提交脱敏提案，由维护者决定是否进入公共内核。

## 核心对象

- **ERP 蓝图**：关联一个现有平台项目，声明通用模块、能力目录、主题和扩展点。
- **蓝图版本**：不可变的发布清单，记录 Git 提交、模块版本、迁移和回滚依据。
- **商户实例**：关联一个独立平台项目，固定使用某个蓝图版本，并拥有自己的主题、插件、数据与私有扩展。
- **能力目录**：供 AI 检索的机器可读目录。AI 先判断已有能力能否直接满足或组合满足需求。
- **需求信号**：经商户明确授权后提交的脱敏缺口描述，不含经营原始数据、密钥或私有源码。
- **通用提案**：按稳定 `need_key` 聚合多个独立商户需求；达到条件仍只进入人工评审，不自动改内核。
- **升级活动**：对目标版本执行兼容检查、准备、采用和回滚记录，不覆盖私有扩展。

## AI 代理工作顺序

1. 读取商户实例、当前蓝图版本和能力目录。
2. 将需求判定为 `existing`、`composition`、`private_extension` 或 `candidate_common`。
3. 已有能力直接复用；可组合能力生成商户项目内的工作计划。
4. 商户专有需求放入私有扩展，不改公共内核。
5. 只有商户明确授权时，才提交脱敏需求信号。
6. 维护者接受通用提案后，平台才创建正式 Matter；Matter 仍需既有评审、测试和发布流程。
7. 新版本发布后先做兼容检查，再由商户选择采用；失败时记录回滚到原版本。

## 安全边界

- 蓝图只引用项目和发布清单，不托管商户密钥或经营原始数据。
- 需求信号禁止客户姓名、电话、订单明细、令牌、私有源码和数据库转储。
- AI 不得自动接受提案、合并代码、发布公共版本或批量升级商户。
- 升级只操作公共模块和声明的插件边界；私有扩展命名空间必须保持不变。
- V1 不包含真实支付、代币、公共消费者网络或大厂生产适配器。
