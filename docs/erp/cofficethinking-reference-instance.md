# `cofficethinking` ERP 参考实例

`cofficethinking` 是已付费、已存在真实代码和经营模块的咖啡店项目，也是通用 ERP 的 `existing_project` 参考实例。它不是公共内核源码副本，而是验证“公共内核 + 咖啡行业插件 + 商户主题 + 私有扩展”能否落到真实商户项目的独立实例。

## 已有契约

- ERP 实例清单：`contracts/erp/instance-v1.json`
- 开放商业运行契约：`contracts/open-commerce/merchant-runtime-v1.json`
- 商户运行说明：`docs/open_commerce_runtime.md`
- 已有消费者能力：商户资料、商品搜索、商品详情、服务端报价、显式确认后的幂等下单和订单查询。
- 订单确认权威：平台服务端一次性确认后把 `action_confirmation_id` 写入 HMAC 签名信封；咖啡店运行时不再接受业务输入自报的确认布尔值或第二确认编号。
- 订单事实边界：`order.commit` 写入咖啡店自己的 `unified_orders`，标准业务回执引用该商户订单；一龙平台只保存调用和结果证据，不复制订单表。

## 纳入步骤

1. 在官方 ERP 蓝图工作台选择“纳入现有项目”。若列表中尚无该项目，点击“登记本机仓库”，通过本机目录选择器登记或复用平台项目；系统只登记项目，不自动纳入 ERP。
2. 确认 PC 节点工作区、Git 身份和项目编辑权正确，选择刚登记的项目，再明确点击“纳入”，登记 `cofficethinking.store`、咖啡行业、主题、模块、插件和私有扩展。
3. 创建初始化 Matter。AI 先对照实例清单盘点已有模块，只补齐蓝图缺口，不重新生成整套 ERP。
4. 真实修改继续在该商户项目的独立 Git 工作区完成；测试、合并、数据库迁移和发布仍需商户确认。
5. Assignment 完成后登记 `.yilong/erp-instance.json` 的摘要和验证结果；平台只保存证据，不读取经营原始数据、密钥或私有源码。
6. 在 ERP 工作台读取“消费者 AI 接入就绪度”。单商户项目自动选择节点；多商户项目需明确选择 `merchant_id`。依次补齐运行时验证、`merchant_runtime` 能力和开放目录发布，不以契约文件存在代替真实就绪状态。

## 当前边界

仓库中存在契约和运行代码不代表公网运行时已启用。当前跨仓库契约与定向测试已经通过，但未启动咖啡店 PostgreSQL 完成真实订单写入和状态回读。HTTPS 域名、主机白名单、双方密钥、商户与门店标识、生产商品和真实支付仍需分别配置和验证。美团、抖音、京东和淘宝闪购生产适配器也不能由本参考实例的存在推导为已完成。

平台提供的就绪度接口只汇总已保存事实，并隐藏运行地址和密钥引用。显示“消费者 AI 可调用”仍不等于公网部署、真实支付或外部平台适配器已经验收；显示“ERP 项目已验收”也不自动代表商户已发布到消费者目录。
