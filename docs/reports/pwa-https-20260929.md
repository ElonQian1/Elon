# 群聊录音的 HTTPS 交付

用户确认苹果 PWA 使用 `http://43.139.149.158:8080/web`。附件与录音界面已在
`6ed6c10f9` 发布，后端为 0.3.1794，但 HTTP 页面无法取得浏览器麦克风能力。
因此继续补齐原生 HTTPS PWA 入口，而不是把“录音界面存在”当作语音功能可用。

## 实现边界

- `MOBILE_PWA_HTTPS_ENABLED` 默认关闭，依赖既有账户 TLS 配置。启用后将原 HTTP
  浏览器路由作为 HTTPS fallback，复用鉴权、上传限制和项目/聊天功能。原生账户
  路由保留优先级及查询/请求限制；这是显式开放浏览器表面，不是账户白名单模式。
- 使用已有 8443 监听和证书热更新，不添加端口、不改全局 PUBLIC_URL、不搬迁账号数据。
- HTTPS HTTP/1 连接支持 WebSocket upgrade。原 HTTP 地址继续服务。
- HTTPS 页面把同主机、明确聊天附件路径的旧 HTTP 地址转换为当前 HTTPS origin；
  附件元数据仍保持原绝对 URL，兼容 Android/旧端。外部链接及其它路径不改写。
- 配置脚本仅比较交换一个开关，与正式发布共用锁。失败回滚旧值并重启，不覆盖其它配置。
- 既有量化 HTTPS 核验识别已启用的 PWA 标记；未开启 PWA 时继续检查受限路由不可达。

## 验证与使用

附件和录音的既有 WebKit/Chromium 回归见
[附件交付记录](pwa-rich-attachments-20260929.md)。HTTPS 追加验证覆盖开关默认关闭、
TLS 前置条件、账户路由优先级、匿名鉴权、上传体积限制、真实 TLS WebSocket 升级、
配置比较交换及回滚、同源媒体地址转换。账户 HTTPS harness 共 36 项通过，配置事务
3 项通过，媒体地址转换在 WebKit 和 Chromium 均通过；Rust 服务端 check 通过。
部署及目标环境结果以本任务正式发布和配置核验回执为准。

入口为 `https://43.139.149.158:8443/web`，必须在正式后端发布并通过配置脚本核验后使用。
Safari 首次打开新地址需要重新登录，再添加到主屏幕；HTTP 旧图标不会自动迁移 origin。
已有群聊、文件和账号数据保留。实际 iPhone 麦克风权限、键盘和系统文件选择器仍待用户验收。
