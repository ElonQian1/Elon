# ADR：ERP 发布、兼容检查与升级 V1

- 状态：已接受
- 日期：2026-08-01

## 决策

每个蓝图版本必须有不可变发布清单，至少包含源 Git 提交、公共模块及版本、公开能力、迁移步骤、兼容范围、扩展点和回滚说明。

升级采用四段状态机：

1. `checking`：比较当前实例与目标清单。
2. `ready` 或 `blocked`：输出结构化兼容结果，不修改商户项目。
3. `adopted`：仅商户实例所属项目可在确认真实开发、迁移和验证完成后采用；记录验证摘要、可选部署提交以及采用后的配置修订号。
4. `rolled_back`：仅商户实例所属项目可填写原因并恢复升级前版本和完整公共配置快照。

兼容检查至少验证必需模块、模块版本范围、扩展点、插件要求和私有扩展命名冲突。活动同时保存检查时的实例修订、升级前配置、目标配置和私有扩展快照；任一配置或私有扩展在检查后变化，旧活动必须失效并重新检查。

公共升级不得删除或重写私有扩展清单。采用会原子更新固定版本、主题、启用模块和插件；回滚会原子恢复升级前快照。该状态表示平台已登记商户提供的执行证据，不等于平台亲自完成 Git 合并、数据库迁移或生产部署。
