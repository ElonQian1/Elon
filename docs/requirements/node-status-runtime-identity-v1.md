# 节点状态压缩保留更新所需的任务身份

## 问题和范围

Win 私人网格读取链路的更新诊断发现：`/api/status` 在恢复摘要过大、进入强压缩时，
丢失 `active_cli_prompt_task_ids` 和 `active_task_runtime`。更新器因缺少可验证身份
正确拒绝继续安装，但回复大小本身不应造成合法空闲状态不可验证。

本批修复状态生产端，不放宽更新器拒绝条件，不清除历史恢复账本，不重启当前窗口。
先抽出已有压缩函数保持行为，再独立修复并验证。旧安装版仍须经过正式升级才能生效。

## 验收

1. 恢复摘要过大时，数量、完整 prompt ID 和运行中任务身份在大小允许时保留。
2. 空闲状态仍明确返回空数组；缺失、无效或过大的身份不能伪装为空闲。
3. 压缩不丢弃活动身份，仅移除运行详情；ID 不截断，数量不改写。
4. 保留身份后仍超过预算时继续明确降级，更新器保持拒绝；响应不超过原 64 KiB 上限。
5. 既有状态字段兼容性和压缩测试通过；使用实际生产压缩模块验证回归。
6. 代码、构建、发布、新 Win 激活与真实同步分别记录，未激活不能宣称现场修复成功。

本批不定义交易执行权限，也不改变币安接口、用户授权、撤销和过期合同。
