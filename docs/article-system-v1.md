# 文章内容与群聊分发

状态：首版实现。范围：一龙主项目的 Windows PC、Android APK 和移动 PWA。

## 使用流程

群聊入口“文章”包含“群文章”和“我的文章”。用户创建草稿，编辑标题、摘要、封面、正文段落、小标题、引用和图片，保存后可以跨设备继续编辑。预览文章后选择 1–10 个所在群发布，群聊显示可打开的文章卡片。

阅读页包含封面、标题、作者、发布时间和完整图文正文。讨论沿用群消息，首版不增加独立文章评论、点赞、转发计数、关注或公开广场。

保存草稿是显式操作。浏览器关闭和 APK 返回时会提示未保存的修改；这不是自动保存功能。跨设备编辑发生版本冲突时，服务端拒绝覆盖，客户端保留输入并显示原因。用户应复制当前内容后重新读取最新草稿再整理。

## 数据边界

| 数据 | 职责 |
|---|---|
| `social_contents` | 作者、内容类型、当前草稿、编辑版本、状态 |
| `social_content_revisions` | 每次发布的不可变文档快照 |
| `social_content_distributions` | 内容版本发布到哪个位置、关联哪条群消息 |
| `social_content_media` | 作者上传的图片、摘要缩略图与哈希 |

内容属于作者，群消息只引用内容版本，不承担正文存储。现有群 AI 总结帖继续使用原模型，不迁移、不改变其置顶和生成行为。

内容类型和发布位置类型均为独立字段。首版仅创建 `article` 内容和 `group` 分发；其他类型不会自动取得阅读权限。群分发的目标存在性由迁移触发器保证，群删除后清理分发，文章作者的原稿仍然存在。分发的 `message_id` 为群消息外键；删除群消息只移除这条分发关系。

## 文档合同

```json
{
  "title": "标题",
  "summary": "卡片摘要",
  "cover": "article_media_…",
  "blocks": [
    {"type": "paragraph", "text": "正文"},
    {"type": "heading", "text": "小标题"},
    {"type": "quote", "text": "引用"},
    {"type": "image", "media_id": "article_media_…", "caption": "说明"}
  ]
}
```

文档为结构化数据，不接受任意 HTML、脚本、iframe 或远程图片 URL。客户端通过文本控件呈现正文，图片只能引用当前作者已上传的媒体。

当前限制：标题 120 字、摘要 300 字、正文 50,000 字、120 个块（其中图片块不超过12个）、12 张不同图片（含封面）。上传支持 PNG/JPEG/WebP，客户端先压缩；服务端限制单张 512 KiB、4096×4096 像素，并解码校验。每个作者当前最多 300 张图片、100 MiB 图片存储、1000 篇未撤下文章。

图片不复用可匿名下载的聊天附件链接。通过已鉴权的文章详情返回 data URL，卡片接口仅返回封面缩略图。所有成功的文章 API 响应使用 `private, no-store`。群聊卡片自身已包含的标题、摘要不会在撤下时追溯擦除；阅读正文每次重新校验权限。图片配额回收和更大文件的对象存储不属于首版。

## 权限与状态

- 草稿仅作者可读写。
- 已发布版本允许作者，以及当前仍在该版本分发群中的成员阅读。
- 群消息被撤回、删除，或者读者退群后，相应分发不再授予阅读权限。读者仍在其他已分发群中时保留该群授予的权限。
- 作者可撤下文章；所有已发布版本停止提供阅读。撤下为终态，首版不恢复旧分发。
- 不提供公开阅读、匿名访问或“持链接即可读”。

`edit_version` 使用乐观并发控制。保存要求提交期望版本，并将版本加一。首次发布不修改编辑版本；后续保存生成新草稿版本，旧发布快照保持不变。版本号可以跳号，不表示连续发布次数。

发布事务先检查全部目标群的成员资格，再写入不可变版本、群消息及分发关系，最后提交状态。同一内容版本、同一群的分发唯一约束使发布重试幂等。任何目标群校验或消息写入失败，整个事务回滚。提交后只为新增群消息发送现有实时事件；实时事件故障由既有群消息轮询恢复。

文章发布不会扫描正文触发群 AI。所有聊天、@、语音和原消息通知仍沿用既有行为。

## 接口

所有接口要求当前账号鉴权，路径前缀 `/api/me/articles`。

| 方法 / 子路径 | 行为 |
|---|---|
| GET `/` | 我的文章；`group_id` 可切到已加入群的文章；`offset` 分页，每页 20 条 |
| POST `/` | 创建草稿，正文为文档对象 |
| GET `/:id/draft` | 作者读取当前草稿 |
| PUT `/:id/draft` | `{version, document}` 保存 |
| POST `/:id/publish` | `{version, group_ids}` 发布 |
| POST `/:id/withdraw` | `{version}` 撤下 |
| GET `/:id/revisions/:revision` | 读取指定已发布版本；`compact=true` 仅卡片预览 |
| POST `/media` | `{base64}` 上传图片，返回 `{id, data_url}` |

不存在或无阅读权限返回 404，非群成员的群列表/发布返回 403，编辑冲突返回 409，非法文档返回 400，超限图片返回 413。

群消息卡片使用版本化前缀 `【一龙文章】` 加换行及 JSON，包含 `schema:1`、`article_id`、`revision`、`title` 和 `summary`。老客户端仍能看到文本摘要；新客户端只把合法引用解析为卡片，正文阅读必须调用鉴权接口。

## 后续扩展

| 阶段 | 新增内容 | 复用内容 |
|---|---|---|
| 个人主页 / 朋友圈 | 个人发布位置、好友可见范围、分页时间线 | 内容 ID、图文媒体、群聊卡片、文章阅读 |
| 公开广场 | 明确公开发布、内容审核、举报、删除策略、时间线和推荐排序 | 发布快照与分发记录 |
| 关注流 / 短动态 | `post` 内容类型、关注关系、关注时间线 | 统一作者和内容 ID、图片存储 |
| 社交互动 | 按内容 ID 关联点赞、收藏、评论与引用 | 文章和短动态共用互动体系 |

时间线查询、推荐排序与内容本体分开。增加公开发布时必须明确新权限策略，不能把现有群内文章自动公开。未来评论可关联内容 ID 与可选群讨论上下文，避免复制整篇文章或把不同群的讨论混在一起。

## 模块与验收

- 后端：`store/articles` 负责文档、媒体、版本、权限和事务；`router/social_routes/articles` 负责 API 和移动资源。
- PC：`features/articles` 负责文章中心、编辑、预览、卡片、阅读。
- APK：`com.elon.app.articles` 独立原生页面，主群聊和消息适配器只接线。
- PWA：`articles.js` / `articles.css`，既有群聊入口只做初始化与消息卡片挂载。

后端测试覆盖草稿越权、快照不可变、重复发布、增发新群、事务中途失败回滚、退群/撤回/撤下权限、聊天消息删除兼容、媒体所有权与非法块。`scripts/test-article-ui.cjs` 使用独立合成账号和 API 替身检查 PC/PWA 的编辑冲突保留输入、保存、预览、发布重试、卡片和阅读；此测试不向线上群发送内容，也不代替 APK 真机视觉验收。

部署顺序：先发布含 PC 前端的服务端和数据库迁移，再发布移动 PWA 和 APK。客户端先于服务端上线时接口会失败，因此不应倒置顺序。回滚客户端或服务端旧二进制可以保留新表；首版不执行破坏性回滚迁移。
