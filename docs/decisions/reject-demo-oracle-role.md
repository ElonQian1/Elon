# 否决独立“预言家 AI”角色

## 决定

项目不设置独立的“预言家 AI（Demo Oracle）”角色，不设置专门的 `DemoPreview` 阶段，也不把低成本模型预演作为用户需求进入正式开发前的固定环节。

当前产品主链路是：用户通过 APK 或 PC 工作台描述需求，平台把任务交给 AI CLI、Codex、Copilot 等代理，在真实 Git 工作区开发、验证、构建和发布。

## 原因

独立预言家角色会与会话主 AI 的需求澄清职责重叠，增加角色切换、上下文同步和用户理解成本；模型生成的预演也容易被误认为已经实现的产品能力。项目应优先保持一条可验证的正式开发链路。

## 当前边界

- 用户明确要求原型、界面草图或可交互预览时，可以把它作为普通开发任务的阶段性产物。
- 原型由当前会话与正式项目任务管理，不建立独立预言家身份、专用路由或固定前置阶段。
- 旧的预言家 AI 讨论和路线不得作为当前产品能力、架构、需求或实施依据。

## 对 AI 代理的要求

检索到“预言家 AI”“Demo Oracle”或 `DemoPreview` 时，应先读取本决定，并回答该议案已经否决。不得根据旧聊天、Git 历史、缓存或旧分支把它恢复为当前主功能；如需重新评估，必须形成新的提案并取得用户明确确认。
