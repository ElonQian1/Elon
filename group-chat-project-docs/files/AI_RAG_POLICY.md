# 群聊 RAG 检索规则

AI 总结群聊时不能随机搜索，必须按 Context Pack 使用系统提供的检索结果。

## 检索优先级

1. 精确消息 ID：用户选中的消息或明确引用的消息。
2. 时间窗口：指定上午、下午、昨天、本周等范围。
3. 关键词全文检索：任务名、项目名、人名、错误码、关键词。
4. 结构检索：某个人的发言、回复关系、置顶帖、历史总结帖。
5. 向量检索：用于补充语义相近但关键词不一致的旧讨论。

## 当前可用工具

- `POST /api/me/groups/:group_id/messages/search`
  - `query`：关键词全文检索，适合任务名、项目名、错误码、人名。
  - `sender`：按发言人 ID 或昵称过滤。
  - `message_ids`：精确取回指定消息。
  - `start_at` / `end_at`：按时间窗过滤。
  - `limit`：返回数量，系统会返回命中分数和命中原因。
- 总结帖生成接口会把最终选中的消息保存到 Context Pack，之后可审计。
- 群聊向量索引当前状态是 `pending_group_chat_embedding_index`；向量检索只能作为后续补充，不能替代上述确定性检索。

## 混合检索原则

- 精确命中优先于向量相似。
- 历史总结帖只能作为参考，不能替代源消息。
- 检索结果互相矛盾时，保留冲突说明。
- Context Pack 中没有的材料，不得在总结里写成事实。
