# ESK 首批用户交付阶段目标 V1

## 可用于 Goal 的目标正文

持续交付一龙主项目与一龙量化的首批用户 ESK 资产闭环及 Sui 上线准备。
复用主项目账户、技术栈与服务器，保持独立量化仓库和版本化合同。
先让用户在主项目个人中心和量化端一致地查看 ESK 数量、来源、流水、
占用和官方卖回申请进度，再按事实推进链上资产状态和量化产品。

ESK 保持同一种服务支付、治理和经批准利润快照参与资产；消费或转让会减少
后续参与权重。QSHARE 的份额、净值和申赎独立核算，不混同公司法股权。
收益来自已实现、对账并批准的利润，不固定价格、不保证年化或即时兑付。

历史付款先做只读对账、用户映射和防重复导入预演。真实入账依据已核对的付款、
用户用途确认及审批，不从聊天推定金额或补造交易。平台、迁移中和链上资产
分别标注；通过有来源的迁移与反向结转避免同一资产重复统计。

先完成 Sui 查询、发布证据、地址绑定及终局性投影准备。签名或发布前确认网络、
钱包、正式参数及授权；没有链证据不得显示已上链。自有公链保留为后续适配目标，
不作为当前交付依赖。

量化端持续完善行情、持仓、净值、收益来源及申赎对账；回测、模拟与实盘明确区分。
完成项目广场 APK 下载、安装、登录和本人资产验收。每轮查重、认领、分模块实现、
风险匹配测试、同步共享文档，并分报代码、验证、推送、部署和用户验收状态。
某一环节等待授权时，继续推进不依赖它的工作。

主网发行、生产密钥、真实 USDT 兑换/支付、自动交易和币安实盘必须另行获得
明确授权并满足安全及适用法律要求，不从“继续开发”推导资金操作权限。
本阶段完成以首批用户闭环及明确的上线验收证据为界，不无限扩展为整个项目。

## 协作与权威边界

每个实现切片先查询 Feature Registry，核对代码祖先与所有权，再认领；不得并行
改写同一余额/迁移真源。文档有需求不代表代码已完成，代码已推送不代表 APK 已发布。
本路线图保存阶段目标，不替代功能登记、发布清单、审批记录或客户端 Goal 状态。

保持 [ESK Sui 决策](../decisions/esk-sui-economic-foundation-v1.md) 和量化 V21
QSHARE 合同的领域权威。后续代理不得原地放宽 Paper V1/V2 响应，也不得把观察器
回执当作可花费余额、地址所有权证明或完整发行认证。经济参数改变须另行决策。
