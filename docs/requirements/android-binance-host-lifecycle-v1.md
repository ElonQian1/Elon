# 量化前台绑定币安会话宿主

承接个人网格产品和已有事件合同。主1700更新后，量化0.7.47原管理页保持连接中；启用已有MCP后台调试服务后，同页恢复账号和列表。观察表明前台量化必须明确管理跨进程宿主生命周期，不能把调试服务作为正常产品依赖。该现象尚不证明具体ROM调度机制；新方案必须真机验证。

新增只绑定、不主动启动的固定服务，随量化前台事件订阅建立和释放。服务不创建网页、不授予访问权、不接收交易或任意命令，也不输出凭据。既有Provider仍逐调用校验正式量化签名、账号、授权和操作状态。事件能力回复可选声明 `lifecycle_service=yilong.binance_host_lifecycle.v1`，旧客户端忽略；新版量化核验原签名和固定组件后绑定。旧主包没有声明时沿用原事件合同并保留其恢复限制。

不增加周期查询、后台定时唤醒、调试保活依赖或永久通知。服务更新/死亡让旧订阅和准备失效；后台/退出释放绑定。不得以本批服务连接成功替代列表、详情、草稿或真实交易验收。

验收：声明、固定服务和Provider权限边界测试通过；双包原签名发布安装；关闭本次临时MCP保活，在量化原创建/管理/记录页跨主更新验证恢复。管理需重新核验同账号同策略详情，保留未提交输入，拒绝旧业务回执与确认。若绑定未改善实机状态，记录失败并继续定位，不擅自放开网页重载或自动交易。

机制参考：[Android绑定服务](https://developer.android.com/develop/background-work/services/bound-services)。
