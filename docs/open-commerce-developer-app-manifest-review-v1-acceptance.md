# 开放商业开发者 App 资料清单与审核 V1 验收

## 当前状态

`implementation_compiled_local_state_http_subset`

Rust `elon-server` 测试目标已编译；全新 SQLite 专项测试已验证当前修订资料完成本地审核后，后续资料编辑会递增修订、退回草稿、清除域名证明、把既有准入退回修改并撤销活动生产凭据。两项进程内 Axum 测试又验证登录、项目与 App 管理隔离、修订冲突、提交、管理员待审队列和批准边界；真实 TCP、历史迁移和 PC 交互仍未验证。

## 已形成代码

- V151 为既有沙盒 App 增加资料、能力申请、修订号、提交和审核字段。
- 编辑资料会递增修订并清除旧审核结果；提交和审核均要求预期修订号一致。
- App 所有者或项目管理员可维护资料，平台管理员可读取待审队列并批准或要求修改。
- PC 开发者门户可维护资料、提交审核并查看状态和审核说明。
- PC 仅向系统 `admin` 或本地 `owner` 显示待审队列，可批准当前修订或填写说明后要求修改。
- 提交审核前要求当前资料修订已经完成主页域名控制证明。
- 审核记录明确固定 `production_credential_issued=false`，不会改变沙盒环境或测试凭据。
- `server/src/open_commerce_developer_production_state_tests.rs` 已锁定资料修订与准入、生产凭据的失败关闭联动。
- 资料 HTTP 在进入领域写入前复用 App 管理授权；只读成员、非 App 所有者普通编辑者、跨项目调用方和无项目权限的平台管理员均返回 `403`，不再把权限错误混为 `400`。

## 统一回归必须验证

- V150 到 V151 升级、空资料默认值、重复迁移和索引创建。
- URL、邮箱、能力数量、能力格式和审核说明边界。
- 项目 `admin` 的资料写入与 App 停用后的全部接口状态；App 所有者、项目 owner、普通编辑者、只读/非项目成员和平台管理员审核边界已通过进程内 Axum 测试。
- 并发保存、重复提交、过期修订审核和停用 App 的失败关闭行为；审核后再编辑的本地事务联动已通过专项测试。
- 审计事件、待审排序、PC 表单状态、错误提示和小屏布局。
