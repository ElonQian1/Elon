# ADR：ERP 发布、兼容检查与升级 V1

- 状态：已接受
- 日期：2026-08-01

## 决策

每个蓝图版本必须有不可变发布清单，至少包含源 Git 提交、公共模块及版本、公开能力、迁移步骤、兼容范围、扩展点和回滚说明。

升级采用四段状态机：

1. `checking`：比较当前实例与目标清单。
2. `ready` 或 `blocked`：输出结构化兼容结果，不修改商户项目。
3. `adopted`：商户或维护者确认既有开发发布流程已完成后，更新固定版本。
4. `rolled_back`：恢复升级前版本，并保留活动和原因审计。

兼容检查至少验证必需模块、模块版本范围、扩展点、插件要求和私有扩展命名冲突。公共升级不得删除或重写私有扩展清单。V1 只管理计划与审计，不直接执行 Git 合并、数据库迁移或生产部署。
