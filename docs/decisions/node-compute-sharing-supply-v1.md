# 节点模型算力显式共享供给 V1

## 背景

项目已有 PC 节点、模型上报、推理路由、用量账本和提供者收益记录，但过去只要节点在线并上报模型，就可能成为其他用户的自动调度候选。在线不等于同意出租算力，远程开发共享也不等于同意共享本地模型，因此必须增加独立、默认关闭的供给授权。

## 决定

1. 每个节点拥有独立的模型算力共享策略，默认关闭；节点在线、开放远程开发或上报模型都不会自动开启共享。
2. 只有节点所有者可以修改策略，并必须明确选择允许其他用户调用的模型。
3. 所有者可设置对外共享最大并发数和每日已完成 Token 阈值。阈值为 0 表示不限制；达到阈值后停止接收新任务，已经运行的任务可能使最终用量略高于阈值。
4. 所有者使用自己的节点不受对外共享策略、并发数和每日阈值限制。
5. 指定节点和自动选点都必须经过同一供给检查及原子占位。自动选点在候选节点被关闭、满载或达到阈值时继续尝试下一候选。
6. 相同调用编号只允许完全一致的用户、提供者、节点、模型和用途重放；不得用幂等键把已存在任务重新绑定到其他身份或资源。
7. 市场页面只把明确开放模型算力或远程开发能力的节点展示为服务节点，并分别显示两类共享状态。
8. 继续复用现有节点执行证明、消费者计量、提供者收益和失败记录；V1 不新增代币、链上提交或自动提现。

## 安全与运行边界

- 供给策略使用数据库立即事务，在派发前重新检查开关、模型、并发和每日阈值并占用执行名额。
- `started` 推理持有 2 分钟活动租约，服务端在流式接收期间每 30 秒续期；并发判断使用最近续期时间，不再因任务总时长超过固定窗口而提前释放名额。
- 节点流必须收到与请求编号一致的结束事件才进入结算。错误、提前断流或租约已终止均失败关闭并释放预授权。
- 服务重启会终止进程内流接收器，因此启动恢复会把遗留的 `server_node_llm` 执行证明标记失败，并立即尝试释放对应计费预授权。
- 公开模型目录只返回调用者自己的模型或当前明确可用的共享模型。
- 策略读取异常时失败关闭，不把节点推断为可共享。

## 非目标

V1 不是完整公开算力市场，不负责异构训练任务拆分、竞价撮合、节点质押、故障赔付、法币提现、链上分账或企业级 GPU 集群等效能力。远程开发共享与模型推理共享仍是两个独立权限。
