# Win 网页 AI 私有传输能力对齐

## 目标与范围

本批次只改 Windows Tauri/WebView2。Android APK 作为已经验证过的实现基线，PWA、APK
产物和服务端均不修改。Win 继续使用现有一龙原生聊天 UI、会话目录、DPAPI 快照和富内容 AST，
不增加第二套聊天记录或数据库。

私有传输模块只旁路观察官方页面已经发起的同源请求和流式事件。发送、登录、验证和账号状态仍由
官方页面负责；观察器不伪造请求、不重放生成回答的 POST，也不导出 Cookie、Authorization 或
WebRTC 凭据。

## 能力矩阵

| 能力 | APK 基线 | Win 实现 | 用户价值 | 回退 |
|---|---|---|---|---|
| ChatGPT 会话/项目目录 | 文档启动阶段被动观察 GET | 复用相同模块并在 DOM 就绪前安装 | 启动即显示缓存，后台补齐官网历史，减少旧会话串线 | 现有 DOM 目录与 DPAPI 缓存 |
| ChatGPT 当前会话正文预取 | 同源只读 GET | 已有，继续复用 | 切换历史后更快恢复上下文 | 官方页面导航 |
| ChatGPT 发送观察 | 观察官网 POST 派发 | 已有，继续复用 | 更准确区分“已写入”和“已发送” | 可见输入框与快照回执 |
| ChatGPT 流式/WebSocket | 文档启动阶段安装 socket tap | Win 在 DOM 就绪前安装同一 tap | 更早显示流式正文和完成状态 | DOM 流式观察 |
| Google 会话目录 | 文档启动阶段观察 `ListThreads` XHR | 复用相同模块并在 DOM 就绪前安装 | 新会话与历史切换更稳定 | 当前页可见语义与本机缓存 |
| Google 回复完成 | 观察官方 `/async/folif` 完成并触发 DOM 探测 | 复用相同模块 | 降低长时间停在“回答中”和漏正文 | 有界 DOM 轮询 |
| Google 查询策略 | APK 版本化策略 | 复用同一资产与版本 | 减少错误恢复 URL 和跨会话污染 | 官方页面回退 |

## 装载顺序

目录观察器和 ChatGPT socket tap 必须在 `DOMContentLoaded` 前安装，因为官网可能在 React
根节点创建前就发出目录请求或建立流连接。其余语义适配器仍等待 DOM 根节点可用后安装，避免把
“WebView 已连接”误判成“输入框已可发送”。所有共享脚本均保持幂等，页面完成、登录跳转或 SPA
切换后的重复注入不会建立重复监听器。

Win 的 Rust 回归会直接解析 Android 页面适配器的资产清单和版本号。Android 新增、删除、改序或
升级版本后，Win 测试会失败并提示重新评审，而不是静默继续使用旧协议。

## 数据边界

- 会话目录只保留有界的 ID、标题、项目归属和安全恢复路径。
- 回复观察器只用于确认本轮官方回复完成，正文仍进入版本化 `yilong.ai.ui.v1` 与富内容 AST。
- 原始研究样本遵守本机 Profile 的容量、保留期和清除会话策略，不上传云端、不写 Git。
- Google 不直接发送私有请求，也没有安全的会话正文预取端点；此能力明确保持未实现。
- 实时语音凭据、WebRTC 信令和厂商身份凭据不持久化、不回放。

## 验收

1. Rust 测试确认 Win 与 APK 的 ChatGPT/Google 资产清单和版本完全一致。
2. JavaScript 合同测试覆盖两个目录观察器、ChatGPT socket tap 与 Google 回复完成观察器。
3. Win 全量 Web AI 验证、Tauri 构建与 PC 前端生产构建通过。
4. 安装版现场验证：缓存首帧不等待官网、连续新建两次会话不串线、回复生成不自动切到完整官网页、
   收起官网后原生 UI 能收到同一轮完成态正文与富内容降级结构。
