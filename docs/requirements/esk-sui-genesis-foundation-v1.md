# ESK Sui 创世基础与可验证发行门禁 V1

## 用户结果

一龙主项目拥有一份可由程序验证的 ESK 上链创世合同，并提供最小 Sui
`Currency` 源码。项目方能够在不接触真实用户资金和主网私钥的情况下完成本地或
Sui 测试网编译、测试、发布演练；只有取得可核验的链上证据后，产品才允许把状态
从“平台登记”升级为“测试网上链”或“主网上链”。

本需求是 ESK 从现有 Paper 账本走向真实链上资产的第一项基础能力。它不会把
数据库余额、付款截图或聊天承诺自动变成链上 Coin，也不授权本轮执行主网交易。

## 已接受的产品决定

1. 稳定资产 ID 为 `esk`，展示符号为 `ESK`，链上精度为六位小数。
2. ESK 是一个可消费的市场定价资产，同时承载服务支付、治理和团队批准的可分配
   利润快照参与权；消费或转让后，未来快照权重随余额减少。
3. 某一销售批次可以使用 `1 ESK = 1 USDT` 作为成交参考，但 ESK 不是永久
   1:1 锚定币，不承诺储备担保、固定净值、固定年化或无条件面值赎回。
4. 法定公司股权、客户量化本金和量化份额 `QSHARE` 是独立事实。ESK 不得被
   客户端文案或链上元数据描述为法定股份、存款或保本凭证。
5. ESK 处于 `paper_recorded` / `platform_recorded` 时，主项目账本是余额真源；进入
   `onchain` 后，Sui 是数量、所有权和终局性的真源。主项目继续拥有身份—地址绑定、
   准入、发行映射、披露和已终局链上索引投影；量化子项目拥有策略、风控、OMS、
   交易所对账、NAV、申赎和 `QSHARE`。

## 本轮范围

### 1. 创世清单

新增版本化 JSON Schema 和一个已完成本地验证的 `local_verified` fixture。清单必须固定：

- 资产身份、符号、精度、Sui `Currency` 标准和目标网络；
- 总供应量、各分配桶和精确守恒关系；
- 金库、升级、元数据、分配、暂停和 gas sponsor 等职责分离；
- Paper、平台登记、测试网、主网各阶段的证据要求；
- 历史付费用户获得 ESK 前必须满足的对账、用途选择和幂等规则；
- ESK、QSHARE、公司股权、服务订单和量化资金的账本边界。

所有整数资产数量使用十进制字符串表示 base units。Schema 和测试不得通过
JavaScript 浮点数计算总供应或分配。

### 2. 最小 Sui 资产包

新增独立 `esk_currency` Move 包，只负责：

- 使用 Sui Currency Standard 创建 `ESK`；
- 在初始化交易中铸造清单指定的总供应；
- 随后永久固定供应，禁止继续增发；
- 把初始 Coin 和元数据能力交给一次性发布角色；发布交易产生的 `UpgradeCap` 不由
  Move 初始化器创建或交付，而由后续治理交接仪式连同前述资产分别移交；
- 不包含量化交易、收益计算、USDT 兑换、用户申购或利润分配逻辑。

利润快照、锁仓、受限转移或参与回执属于后续独立
`yilong_participation` 包，不能为了快速发布而塞进不可变的货币核心。

### 3. 自动验证

仓库测试必须拒绝下列危险或不完整状态：

- 分配桶之和不等于固定总供应；
- 网络、资产 ID、符号、精度或标准与本需求冲突；
- 把 ESK 标成永久 USDT 锚定、固定收益、无限保本或法定股权；
- 计划态伪造 package ID、type tag、交易摘要或 checkpoint；
- 宣称已上链但缺少 package ID、type tag、交易摘要、checkpoint 和独立验证状态；
- 清单包含私钥、助记词、API secret、bearer token 或可直接使用的 RPC 密钥；
- 将 Paper 余额自动视为链上余额，或允许未经对账的付款记录直接铸币；
- 把 ESK 总供应能力交给交易机器人或交易所 API key。

## 状态机与证据

测试网和主网各使用独立清单，不能把测试网对象原地改写成主网对象。各自只允许按以下
方向推进：

```text
testnet: planned -> local_verified -> testnet_published
mainnet: planned -> local_verified -> mainnet_ready -> mainnet_published
```

- `planned`：只有参数、源码和验证合同，链上证据字段必须为空。
- `local_verified`：记录确定的 Sui 工具链版本和可复现的编译/测试摘要；仍未上链。
- `testnet_published`：必须记录测试网 package ID、ESK type tag、发布交易摘要、
  chain identifier、checkpoint、待接收 Currency 对象、注册后 Currency 对象、逐桶
  分配回执、`verify-source` 结果，以及与发布端点不同的独立查询结果。
- `mainnet_ready`：仅用于 `mainnet` 清单；安全审计、供应分配、多签、恢复、目标
  法域准入和迁移演练均有
  审批证据，但尚未主网发布。
- `mainnet_published`：必须记录主网发布及 Currency 注册最终确认的两笔交易证据，
  区分注册前后对象，并由与发布方不同的只读端点复核源码、类型、供应和持有人。

每次持久化状态推进都创建新清单修订，记录前一清单 ID、修订号和前序文件规范化
UTF-8/LF 内容 SHA-256；验证器按“最新前序到最早根记录”的顺序读取全部前序文件，逐份重算摘要、
验证 Schema/语义、时间递增、合法状态边和不可变字段。旧清单必须保留，修订 1 可作为
没有前序的根记录。回滚只能暂停后续映射、分配或产品展示，不能假装已经发生的链上
交易被撤销。

## 初始供应与分配

V1 fixture 只用于验证结构，不是主网最终经济参数。默认示例总供应为
`1,000,000,000 ESK`，即 `1000000000000000` base units，并划分为：

- 用户迁移与生态分配；
- 团队长期归属；
- 项目金库；
- 流动性；
- 社区和贡献者激励；
- 安全与运营储备。

每个桶必须有独立用途、接收角色、锁定或归属政策引用。主网上线前允许通过新版本
决策更换数值；一旦铸造，禁止修改历史清单来伪装另一套供应。

货币初始化器只产生一枚总供应 Coin，不负责把它自动拆成六桶。进入任何 `published`
状态前，发布仪式必须实际执行拆分和角色交接，记录每笔交易摘要；独立验证器必须按
最终对象余额复算供应与各桶，而不能仅接受项目方填写的任意摘要。团队归属等时间约束
必须由可执行合约或经批准且可验证的托管流程落实，不能只引用一段说明文字。

每桶发布回执必须逐一绑定 bucket、base units、接收角色及其 holder、归属政策、执行
方式、结果对象、交易摘要和 checkpoint；`team_vesting` 必须由 Move 合约执行。

## 已付费用户迁移

历史用户不是按聊天记录直接空投。每条迁移 claim 至少绑定：

1. 主项目内部用户主体的不可逆脱敏标识；
2. 已对账的收款事实、资产、金额、时间和唯一外部引用；
3. 用户明确选择的商业用途：购买 ESK、购买服务或量化申购；
4. 对应销售批次、成交价、ESK 数量、披露版本和地域准入结果；
5. 唯一幂等键、审批人与审计摘要；
6. 用户自持地址或经批准托管账户的绑定证明。

同一笔付款只能落入一个商业用途。选择量化申购时进入 `QSHARE` 申购流程，不能
同时当作 ESK 销售款；选择 ESK 时也不会自动加入可随时赎回的量化基金。

## 密钥与资金安全

- 发布/升级、金库、分配、暂停和 gas sponsor 使用不同角色；生产环境采用多签
  或等价审批，不把单人热钱包设为全部能力持有人。
- fixture 中的单签一次性 deployer 只允许本地/测试网演练。主网 Publish PTB 的 sender
  必须是发布多签，且在同一 PTB 把发布产生的 `UpgradeCap` 直接交给升级多签，避免
  单一私钥短暂控制全部供应、元数据和升级能力。
- 币安或其他交易所机器人密钥只允许交易权限，不允许提现；链上发布私钥和交易所
  API key 完全隔离。
- 客户量化资金、项目融资 USDT、项目自营量化资金和运营资金分别记账、分别对账。
- 本仓库只提交地址、对象 ID、摘要和公开配置，不提交任何秘密或可签名材料。

## 主项目与量化子项目合同

主项目向量化仓库提供版本化、签名、只读的 ESK 身份和账户投影。量化仓库 V20
仅作为现有 UI/产品体验及市场、Paper、`fund-product-core` 基础能力的复用基线；量化
`origin/main@04b09b5849cf9e64f5992811a21522e3eb72d003`
的 V21 `tokenized-managed-share-product-v21.md` 与 ADR 0004 是 `QSHARE-P1`、
份额、NAV、申赎、Senior/Junior 资本栈和链无关状态投影的唯一合同权威。子项目不得
新增第二个 ESK 余额真源，也不得把 ESK 直接作为 `QSHARE` NAV。

后续 `yilong_participation` 只实现 ESK 团队利润快照、锁仓和领取回执，不实现或复制
V21 的 QSHARE 份额、NAV、申赎、资本瀑布或链投影。

项目方用融资资金参与自营量化时，资金先进入独立项目金库账本。已实现、已对账且
经审批的团队利润才可进入 ESK 利润分配池。若另设客户量化产品，项目方承担损失
只能实现为金额上限明确且可观察的 Sponsor Junior Capital 瀑布，不作无限保证。

## 明确非目标

- 本轮不发送主网或测试网交易，不创建或导入生产私钥，不移动真实 USDT。
- 本轮不开放公众买币、兑换、提现、自动卖回或真实量化申购。
- 本轮不承诺 6%、800% 或任何固定收益，不用新增 ESK 支付收益。
- 本轮不开发公链；Sui 先作为可替换的结算层，业务真源保留版本化接口。
- 本轮不覆盖既有 Paper 用户页面和余额，而是为后续逐条迁移提供门禁。
- 当前 Move 包与本地证据固定到 Sui `testnet-v1.79.0`；主网清单必须采用独立修订，
  固定主网 release、协议兼容结论并重新 build/test，不能复用测试网工具链摘要。
- Move 包公开的供应常量仅用于本地交叉验证；发布后 Currency Registry `0xc` 的已注册
  Currency 对象才是 fixed supply 和总供应真源，客户端不得以可升级 getter 取代它。
- 离线验证器按规范化 UTF-8/LF 内容绑定 `Move.toml`、可选 `Move.lock` 和包内所有
  `.move` 文件的整体摘要，Windows 与 Linux 检出同一 Git 内容会得到相同结果。
  本轮尚无治理/在线链证据验证器，因此它必须拒绝所有 `mainnet` 清单，以及任何外部
  清单自称 `testnet_published`；后续功能固定主网兼容包或核验真实链证据后，才能按
  状态分别移除对应 fail-closed 门禁。

## 验收标准

1. 创世 fixture 通过 JSON Schema 和仓库语义测试，修改守恒、精度、标准、阶段证据
   或账本边界后测试会失败。
2. `esk_currency` 源码只具有一次铸造并固定供应的路径，未保留公开增发入口。
3. Move 测试覆盖总供应、精度、固定供应和能力归属；没有可用 Sui 工具链时必须把
   结果标成 `UNCOMPILED`，不得声称通过。
4. 清单和源码扫描不含秘密，交易机器人不能持有供应、升级或金库能力。
5. 文档给出从 Paper 到主网的证据状态机，并明确已付费用户逐条对账和单一用途。
6. 本功能在项目注册表中被认领、记录实现和测试证据；跨仓后续任务有明确所有者。

## 后续功能

1. `esk-sui-reproducible-toolchain-ci-v1`：已把固定版本本地验证封装为可重复安装、缓存、
   生产字节码冻结和 CI 检查；具体远程运行证据见该功能交付记录。
2. `esk-sui-testnet-publication-v1`：多签演练、在线链证据验证器、测试网发布、Currency
   最终注册、逐桶对象复算和独立端点复核。
3. `esk-paid-user-migration-v1`：对账队列、用途确认、地址证明、审批和批量领取回执。
4. `esk-sui-allocation-vesting-v1`：可执行六桶拆分、逐桶对象复核和团队归属约束。
5. `esk-sui-participation-v1`：独立可升级的快照、锁仓、分配和暂停对象。
6. `esk-mainnet-launch-v1`：主网兼容包/工具链、注册集成测试、UpgradeCap policy、审计、
   准入、密钥仪式、`verify-source` 证据和渐进开放。

## 回滚

计划态可以停止，不影响现有 Paper 账户。测试网发布后停止映射服务并保留证据；
主网发布后不得通过数据库回滚链上供应，只能暂停尚未执行的分配、关闭入口并启动
经审计的迁移或包升级流程。
