# Win 微信记录附件本地缓存

后续更新：[正文近期缓存先显示](win-record-reopen-latency-20261003.md) 已替代下文“每次等待正文复核”的规则。附件缓存仍复用本模块；断网或 5xx 不再删除已下载附件。

## 原因

旧 PC 阅读器每次挂载附件都调用 `cache: no-cache` 的鉴权 GET；即使 HTTP 缓存存在，仍等待网络复核。关闭阅读器会释放 Blob URL，重新打开、嵌套返回又请求附件。`RecordAsset` 还依赖整个 `row/card` 对象，父消息刷新产生等价对象时也会销毁并重建媒体。

不是每次重新下载、解压微信 ZIP。群记录正文与附件已独立存储；本批不改变导入数据，也不修改 Android 或 PWA 实现。

## 修复与边界

- 保留每次打开记录正文时的网络权限复核。仅成功获得记录文档后，才读取其中绑定附件的本地副本；没有有效正文时不展示离线图片。
- 内存最多 32 MiB，IndexedDB 最多 128 MiB/128 项，单附件不超过 12 MiB，最长保留 7 天。按账号、服务器、群、记录和附件 ID 隔离，不存 Cookie、token 或请求头。
- 磁盘保存原始 Blob，不二次压缩。淘汰只扫描小型元数据，读取时不重写大文件；按最近使用时间回收，过期视为未命中。
- 同附件并发请求合并；关闭单个视图不影响其他订阅者，全部取消后停止下载。拒绝权限、撤回、退出/切换账号和手动清理会失效相应缓存，迟到响应不能重新写入。
- 图片组件依赖稳定 ID/类型/文件名；普通群消息刷新不再打断图片加载。预览沿用原图适宽、缩放、下载与关闭返回，不新开外部页面。
- 阅读器“更多”提供“清理本条记录的附件缓存”。浏览器存储关闭、配额不足或 I/O 超时时，退回有界内存及正常网络读取，不阻塞阅读器。

## 验证

- 9 项离线定向测试：API 合同、权限拒绝、账号切换、内存 LRU、过期、空附件、迟到响应、请求合并和单订阅者取消。
- 真实 HTTP + Chromium 的生产 React 阅读器，在 1280/390 视口验证两张图片和一个视频。附件响应故意使用 `no-store`，排除浏览器 HTTP 缓存影响：首次各下载一次，嵌套返回、关闭重开和页面刷新不增加附件请求；正文仍逐次复核。
- IndexedDB 实测持久化、容量/条数淘汰、过期和前缀隔离；手动清理后重新下载；撤回后不显示旧记录。等价对象刷新保留同一个媒体容器。
- PWA 原 HTTP 条件缓存、社交卡片及拖动回归通过，未把 PC 新缓存误写为 PWA 已启用。原图预览生产组件的双视口回归通过。
- 以上为合成数据，未下载、导出或发送群里的私人图片。不将浏览器测试冒充用户那两张图片的 Win 现场耗时。
