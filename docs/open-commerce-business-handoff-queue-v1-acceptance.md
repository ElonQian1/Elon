# 开放商业业务衔接待办队列 V1 验收

## 已实现

- HTTP 与 MCP 可按商户读取全部、`pending` 或 `retry_required` 待衔接证据。
- 队列由业务证据和最新衔接回执实时计算，没有新增可漂移的待办状态表。
- 尚无回执的证据显示为待处理；最新处理失败的证据保留为需重试。
- 最新回执为成功应用或明确忽略后，证据自动移出队列。
- 每项返回完整证据摘要、是否允许声明 `applied` 及可选最新失败回执。
- PC 商户工作台提供独立队列、状态筛选、数量提示和处理入口；保存回执后自动刷新。
- 所有界面和响应继续声明不自动调用外部系统、不创建平台订单且未移动真实资金。

## 验证范围

- Rust 专项测试覆盖无回执进入队列、失败转为需重试、状态筛选、MCP 读取、成功回执自动移出和非法筛选失败关闭。
- PC 契约测试覆盖独立队列入口、两种状态、最新回执排序、处理后刷新与资金边界。
- PC TypeScript 生产构建和目标文件 ESLint 通过。

## 未完成边界

- 没有生产适配器、自动任务领取、退避重试、机器签名或外部 ERP 回读。
- 队列不是支付、订单、库存、客户或财务事实来源。
- `rejected` 只表示最近一次人工确认的接入结果失败，不代表平台独立核验了外部故障。
