# 多书签与独立阅读进度方案

本方案回应每周上线一次、在多个历史位置之间往返阅读的需求。
它是统一消息时间线的扩展设计，尚不代表已实现书签 API、跨端同步或书签 UI。
基础合同见 [统一消息时间线](message-timeline-v1.md)。

## 用户行为

消息菜单提供“添加书签”，允许命名和添加简短备注，默认仅自己可见。
同一会话可以创建多个书签；书签列表提供“回到标记”和“继续阅读”。
固定标记保留最初那条消息，继续阅读位置只更新当前激活书签的进度。
从书签 A 切换到 B 前保存 A；阅读 B 不修改 A，也不自动移动固定标记。
另有一个会话级“上次读到这里”，用于未从书签进入的日常阅读。

例如：在消息 A 创建“周一讨论”，读至 B 后退出；下周“继续阅读”到 B，
“回到标记”仍到 A。另一个“技术方案”书签有自己的起点和进度。
主动回退后退出可以保存回退位置；“最后阅读位置”和“最远读到的位置”分开。

## 稳定定位

长期保存 source kind、project ID、conversation ID、message ID 和不可变排序键。
现有排序键为 `(created_at, message_id)`，不能把数组下标、页码、数据库 OFFSET
或短期增量同步游标当成书签身份。排序字段应保持不可变。

同设备可附带消息相对视口的像素位置；跨设备优先使用消息 ID 和正文块内位置。
字体、屏幕、图片高度变化时像素坐标只作提示，回退至该消息顶部，不能定位到其他消息。
流式消息须先取得持久化 ID；临时 ID 不创建可跨设备同步的正式书签。

时间线需扩展 `around(message_id)`，直接取目标附近约 50 条，返回更早和更新两个游标。
继续向上或向下按稳定排序键翻页，始终只保留活动窗口。多个书签不同时加载多个窗口。
命中消息高亮后恢复视口；媒体预留尺寸，后续加载保持当前可见锚点。

## 持久化与同步

建议独立 ReadingPosition 模块使用公共 TimelineSource 适配器：

| 记录 | 最小字段 |
| --- | --- |
| Bookmark | id、owner、source/scope、title、note、anchor_message_id、anchor_sort_key、revision |
| BookmarkProgress | bookmark_id、current_message_id、current_sort_key、in_message_position、revision、device_id |
| ConversationProgress | owner、source/scope、current_message_id、current_sort_key、in_message_position、revision |

原消息正文不复制为书签永久快照；撤回后的内容不通过备注预览自动复活。
备注是用户主动输入，系统摘要或自动预览在消息撤回、删除后清除或重新计算。
本地即时更新，停止滚动后合并上传，切换书签、会话或退后台时尽力刷盘。
离线先保存本地待同步队列；恢复网络后按版本条件更新，不能仅依赖设备时间戳。
同一书签的跨设备冲突保留双方可恢复位置，当前正在阅读的屏幕不被远端进度强制移动。
身份切换清除对应活动状态，每次定位和同步都重新检查会话访问权限。

## 已读与异常边界

阅读进度、通知未读计数、消息已读回执是三个独立状态。
跳转到后面的书签不表示中间全部已读；若需要精确未读，应记录已读区间，
不能用当前单一最大时间戳推导“所有历史都已阅读”。

消息撤回保留占位；物理删除时使用原排序键定位最近的可访问消息并提示偏移。
不能访问原会话时标记书签不可用，不泄露原消息或依次搜索其他私有会话。
同步日志过期只影响增量校验，不使长期书签过期，也不能强制跳到最新消息。
当前基础实现新增 window 重校验分支，历史阅读时仅重验已有消息并换新同步游标。
它不等于 around 定位，也不等于多书签功能已上线。

## 接入与验收

Win/PWA 复用领域状态机；APK 使用同一服务合同和原生列表定位。
自有好友、群聊、个人 AI、项目频道共用定位协议；外部厂商 Web AI 必须由适配器
声明稳定消息 ID 与历史定位能力，能力缺失时明确降级，不能承诺任意历史跳转。
显示书签不改变模型输入；只有用户显式引用的授权消息才进入原有上下文编译路径。

验收覆盖：一周离线/十万条历史、多书签往返、独立进度、重启、跨设备字体变化、
图片迟到、同时间戳、撤回/删除、权限撤销、断网和版本冲突、增量日志过期。
跳转网络请求和内存应随窗口大小受限，不能从第 1 页逐页扫描至目标。
