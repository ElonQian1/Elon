# 局域网公共 Android 真机主机

状态：当前运行约定
最后更新：2026-07-14

## 目标

同一项目的多台 PC 可以发现项目共享手机、读取真机画面并使用 Live UI 调试。手机只需在至少一台常开 Windows PC 上完成 ADB 授权；其他 PC 网页端不复制 `adbkey`，也不需要重复授权。

## 连接模型

1. 网页优先检查本机节点；本机已经连接目标手机时直接使用本机，延迟最低。
2. 本机没有目标手机时，服务端只探测“在线、公开开发共享、支持 Android 设备主机协议”的节点。
3. 节点上报的设备必须与当前项目的共享硬件序列号一致，才会显示在设备下拉框中。
4. 网页选择共享手机后，真机捕获和 `/api/android-live/*` 请求经项目鉴权的云端 WebSocket 隧道转发到托管节点。
5. 托管节点只接受专用设备主机协议和 Android 白名单接口，并在本机注入内存中的 local-admin token；通用 PC relay 不能访问这些能力。

无线配对、手动连接、忘记设备、启用 `tcpip 5555` 只在托管电脑本机操作。云端只保存硬件身份和最近私网端点，不保存 ADB 私钥。

## 多用户和多手机

- 多台 PC 可以同时发现同一手机，也可以各自保持 ADB 连接。
- 单台物理手机只有一个前台画面。捕获后启动 APP、安装调试包、拖动元素、撤销、构建验证和源码写回必须取得项目设备租约。
- 同一硬件序列号同一时刻只有一个浏览器实例持有租约；10 秒续租，断线后最迟 45 秒释放。
- 设备下拉框按硬件序列号去重；本机在线连接优先，否则使用共享设备主机。切换手机时，画面、草稿和 Live Session 按稳定硬件身份隔离；已创建的 Session 固定回原主机，不会串到新手机。
- 真正同时测试两套前台交互需要两台手机；一台公共手机只能按租约轮流测试。

## 托管电脑要求

- 安装并运行包含 `android_device_host_v1` 能力的最新版 Windows 节点。
- 节点开启公共开发共享，且账号可访问目标项目。
- 手机与托管电脑网络互通，手机已授权该节点的 ADB host key。
- 项目共享设备档案使用硬件序列号；IP、端口和 mDNS 冲突后缀只作为可更新线索。
- 构建调试 APK、验证和源码写回实际在托管节点执行。托管节点必须能访问项目工作区；另一台 PC 尚未同步或提交的本地源码不会自动复制到设备主机。

## 故障判断

| 网页现象 | 优先检查 |
|---|---|
| 完全没有手机 | 托管节点是否在线且为最新版、公共开发共享是否开启、项目是否共享该硬件序列号 |
| 显示手机但等待画面 | 设备租约是否被占用、手机是否解锁、托管节点能否执行本机真机捕获 |
| 只在托管电脑可见 | 服务端和 PC 前端是否已发布设备主机 API；托管节点是否上报 `android_device_host_v1` |
| 构建或源码写回找不到目录 | 项目工作区不在托管节点，先同步代码或把设备托管到拥有该工作区的节点 |
| 多人画面互相覆盖 | 租约未生效或使用旧版客户端；升级后按占用者提示轮流测试 |
