# 群聊与好友多书签首批交付

用户已要求实现并上线[多书签方案](message-reading-bookmarks-v1.md)。
实现、验证、发布与设备验收的状态以[本批交付记录](../reports/social-reading-bookmarks-20261002.md)及功能登记为准。
本切片交付群聊、好友在 APK/PWA/Win 的完整创建、列表、固定起点、独立续读、
双向历史、离线恢复和跨设备进度冲突流程。服务端定位/进度模型复用四种自有来源的
TimelineSource，但个人 AI/项目页面接入属于后续切片，不冒充已上线。

沿用父需求 B01–B12 和[技术设计](../design/message-reading-bookmarks-v1.md)。
保留普通进群最新、空同步也绑定导航、串行分页、已有引用/附件/撤回/草稿能力。
书签不发群通知，不把跳过历史标记连续已读，不扩大模型输入。

首批必须交付：

- 服务端私人书签和独立进度、版本冲突、幂等与删除不复活。
- 按消息直接定位，前后连续分页和有界窗口；删除后同会话附近定位。
- 三端可发现入口，多个书签独立续读、退出/杀进程/离线恢复。
- 小米 APK、PWA、Win 浏览器运行证据及版本、提交、工件身份。
- 服务端先部署，再启用客户端；保留旧协议与回滚时的书签数据。

父功能的所有来源迁移不作为本切片虚假的已完成依赖。已发布的群聊/好友分页与
APK 重入修复为本切片基础，新增 around/after、书签和同步由本切片自己实现并验收。
