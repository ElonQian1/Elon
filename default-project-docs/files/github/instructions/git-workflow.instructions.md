# Git 与发布流程

本文件用于 Git、分支、提交、推送、发布、回滚相关任务。

## 基本规则

- 修改前先看 `git status --short --branch`。
- 不回滚来源不明的用户改动。
- 主工作区脏或多人并行时，优先从最新远端分支创建隔离 worktree。
- 新建文件必须显式加入 Git；提交前检查是否还有未跟踪文件。
- 提交信息写清楚用户可见变化。

## 提交前

1. 确认只 stage 当前任务相关文件。
2. 运行与改动相关的验证。
3. 如果验证失败，要修复或明确说明为什么不能继续。

## 推送与发布

- 有远端时，按项目约定推送当前目标分支。
- 发布必须走项目内脚本或文档指定流程，不手搓发布命令。
- 发布脚本通常只处理已提交代码；不要以为未提交文件会被发布。
- 发布失败时，保留错误输出中的关键事实，说明代码是否已经推送。

## 回滚

- 回滚属于高风险操作，先确认要回滚的提交、范围和影响。
- 不使用会丢弃用户未提交改动的命令，除非用户明确要求。
