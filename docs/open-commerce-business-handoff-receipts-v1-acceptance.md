# 业务证据到 ERP/CRM 显式衔接回执 V1 验收

## 已实现

- 项目编辑者可通过 HTTP 或 MCP 明确记录 `applied`、`ignored`、`rejected` 三种处理结果。
- 回执绑定当前商户、终态 Invocation、已登记接入器和结果 SHA-256，摘要不匹配时失败关闭。
- `applied` 必须来自带有效标准业务回执的成功调用，并提供外部目标记录号；数据库只保存目标记录号摘要。
- `ignored` 和 `rejected` 必须提供结果代码，不能伪造外部目标记录。
- 跨商户接入器、停用接入器、未确认请求和非编辑者写入均被拒绝。
- `integration_id + receipt_key` 保证同结果幂等重放；同键改写结果返回冲突。
- 回执与审计记录均标记 `project_editor_asserted` 和 `funds_moved=false`，不创建第二套订单账本。
- PC 商户工作台可从业务证据选择接入器、ERP/CRM、处理结果和目标记录号；界面生成幂等键并要求显式勾选确认。
- PC 只显示外部目标记录摘要，并持续标记“人工确认”和“未扣真实资金”。

## 验证范围

- Rust 专项测试覆盖首次记录、幂等重放、同键改写、摘要篡改、用户确认、项目角色、跨商户隔离、无标准回执拒绝、列表和 MCP 读取。
- 数据库迁移测试覆盖幂等建表和有限状态约束。
- PC 开放商业契约测试覆盖工作台入口、显式确认、摘要显示、未扣款边界和 MCP 共用服务。
- PC TypeScript 生产构建、目标文件 ESLint 和包体硬门禁通过；全仓 ESLint 仍有与本功能无关的 `ConversationPage.tsx` 既有无效禁用注释。
- Rust 格式化、源码体积和文档模块化门禁纳入提交前验证。

## 未完成边界

- V1 没有适配器独立机器身份、签名证明或外部 ERP 回读校验。
- 没有实现美团、抖音、京东、淘宝闪购等具体生产写入适配器。
- 没有自动写入库存、财务、CRM、支付、物流或退款系统。
- 没有移动真实资金，也不把项目编辑者声明升级为平台独立证明。
