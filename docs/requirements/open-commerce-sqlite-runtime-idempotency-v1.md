# 开放商业商户运行时 SQLite 幂等存储 V1

## 背景

`@elon/open-commerce-connector` 的签名商户运行时已经定义 `claim/complete/release`
幂等合同，但当前包只提供进程内参考实现。商户节点重启后会丢失成功结果和处理中占位，
每个商户若自行编写数据库实现，又容易重复引入并发接管、所有权丢失和结果损坏问题。

## 范围

1. 提供可选的 Node SQLite 幂等存储子路径，不改变连接器根入口的 Node 20 兼容边界。
2. 按“商户、调用 App、能力、幂等键”建立唯一记录，并保存请求摘要、当前执行所有者、
   状态、成功结果和更新时间。
3. `claim` 必须原子区分首次取得、处理中、同键异输入冲突、成功重放和超时接管。
4. `complete` 与 `release` 只能由当前 invocation 和请求摘要共同匹配的所有者执行。
5. 数据库重启后，相同请求重放原成功结果；返回对象不得允许调用方修改持久化结果。
6. SQLite 忙、关闭、未知 Schema 版本、非法结果和损坏结果必须失败关闭，不泄漏记录正文。
7. 存储支持显式关闭；生产宿主仍负责数据库文件权限、备份、磁盘容量和生命周期。

## 验收标准

1. 重启存储后，同键同输入返回 `replayed`，业务处理器不会再次执行。
2. 同键不同输入稳定返回 `conflict`。
3. 未超时的并发领取返回 `busy`；超时后新 invocation 可接管。
4. 被接管的旧 invocation 不能完成或释放新所有者的记录。
5. 处理失败释放后，新的 invocation 可以重新领取。
6. 非法或损坏的成功结果失败关闭，且错误不包含原始结果内容。
7. 连接器既有完整 Node 测试与新增 SQLite 专项测试全部通过。

## 非目标

- 不启动 HTTP 服务，不托管密钥，不创建商户生产部署。
- 不代替 ERP 订单事务、支付幂等、外部平台幂等或跨区域数据库。
- 不自动创建父目录、备份数据库、清理成功记录或承诺多机共享文件系统可用性。
- 不把本机 SQLite 验证描述为生产高可用或灾难恢复验收。
