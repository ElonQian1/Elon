# 微信记录阅读器与缓存

`capability_id: social_wechat_record_reader_cache_v1`

## 根因与改动

- APK 卡片子文字被 `setOnLongClickListener(null)` 激活了长按消费，吞掉父卡片点击。共享选择绑定不再为 null 监听启用长按，保留已有语音长按和多选行为。
- ZIP 仅用于导入。服务端已经保存不可变结构化文档、嵌套消息和独立附件；本次不修改导入格式，不重新上传历史记录。
- APK 原先在阅读页销毁时删除全部媒体；PC/PWA 每次请求使用 no-store。现在文档和媒体 GET 支持 ETag，服务端先检查当前群成员、撤回/删除状态、记录附件绑定，再返回 304。命中不读取文档 JSON 或附件 BLOB。
- 服务端 GET 使用 private/no-cache、Vary Authorization，修改与失败响应保持 no-store。浏览器每次打开复核权限，不使用离线过期正文。
- APK 使用应用私有缓存，按服务器、账号及会话摘要隔离，不落盘凭证。文件原子替换、SHA-256 校验，总量 128 MiB，老化 7 天；关闭阅读页不删除，拒绝访问即清当前范围，不成功复核则不显示缓存。
- Win 标题栏可拖动，限制屏幕边界，双击居中；移动端保持全屏。嵌套返回保留滚动位置。
- 三端阅读器复用群聊公众号/短视频卡片，包括来源、作者、封面和播放入口。Win 原文阅读暂时收起记录模态框，收起原文阅读栏后恢复原记录位置；APK 沿用已验收的微信独立任务栈返回方式。

## 验证与边界

- Android：19 项定向测试通过，含真实触摸标题/摘要/底部、选择模式、缓存重开/损坏/账号隔离/撤回、原 ZIP 解析与社交卡片。
- PC 请求合同 3 项通过；TypeScript/Vite 构建和改动模块 ESLint 通过。
- `scripts/test-chat-record-cache-browser.cjs`：生产 React/PWA 组件，在 1280/390 宽度全部通过。合成 HTTP 服务保留真正浏览器缓存，非 Playwright route mock；正文、图片和合成视频初次各一次 200，嵌套返回与关闭重开走 304，撤回 403 后无旧消息显示；视频读取到元数据，卡片与拖动/居中检查通过。
- 浏览器截图保存在本任务 `.ai-tmp/chat-record-cache-ui`，只含合成内容。
- 后端 6 项定向测试通过，覆盖成员权限、记录/附件绑定、撤回、重放和条件请求匹配；不把组件测试当作用户微信数据或真机播放验收。
- 合入主线主题改动后，原生卡片点击/选择的 8 项回归及浏览器四组重新通过；测试视频由独立可见 canvas 生成并先检查非空，避免应用布局和编码调度生成空 WebM 而误报播放器失败。
- 内部 Debug APK 构建通过，SHA-256 `260a5ebd67dcd7ce701f4c3d17533af2617190edced6138b54145fff768660a5`。它不是正式发布包，也未覆盖手机现有安装/登录数据。
- APK 发布暂受主线 [全局主题 V2 的原生验收缺口](mobile-design-v2-desktop-takeover-20260928.md) 阻挡。本任务不回退其他任务的主题改动、不绕过门禁，也不将 Debug 构建或组件测试代替新正式包的用户验收。
- 服务端与 PC 已通过统一脚本发布：`0.3.1787`，源码 `29c41cbe4edd7d7b73717cdbd6868f162b33c7c0`；线上版本接口、PC release marker 一致。未登录记录请求实测 401、`private, no-store`、`Vary: Authorization`；成功的 200/304 缓存链路证据来自上述真实浏览器 HTTP 测试及后端权限测试，未冒充真实用户线上记录验收。

首次读取仍需下载导出包确实包含的原始附件。只有视频链接时，复用平台卡片和原平台播放，不伪装成本地视频，也不缓存微信 DRM/登录数据。
