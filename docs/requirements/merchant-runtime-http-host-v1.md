# 开放商业商户运行时 HTTP 宿主 V1

## 背景

`@elon/open-commerce-connector` 已提供签名商户运行时、ERP 组合层和可持久化的 SQLite
幂等存储，但商户项目仍需自行编写 HTTP 读取、限制、响应和停机代码。重复实现容易在原始
请求字节、体积上限、慢请求、错误投影和进程退出期间引入差异，使已经验证的运行时合同
无法直接成为可启动的商户节点。

## 范围

1. 连接器提供独立 Node 子路径，创建可复用的 HTTP 或 HTTPS 商户运行时宿主；根入口
   不自动启动端口，也不引入证书或部署副作用。
2. 宿主只接受固定调用路径上的 `POST application/json`，完整保留原始请求字节和规范化
   请求头，交给既有 `runtime.handleInvoke`；禁止重新序列化签名正文。
3. 在进入运行时前校验 `Content-Length`、流式累计体积、Content-Type、方法和路径；
   超限、截断、异常流和不支持的 `Expect` 必须失败关闭。
4. 响应必须使用有界 JSON、禁缓存和 `nosniff` 头；宿主或注入运行时返回非法形状时，
   只返回稳定的宿主错误，不泄漏异常、密钥、请求正文或内部堆栈。
5. 默认监听 `127.0.0.1`。显式 HTTPS 模式只接受调用方提供的 Node TLS 选项，不生成、
   保存或轮换证书；公开部署仍应由可信反向代理或商户自己的证书生命周期负责。
6. 宿主必须设置有界 header、request、keep-alive 和连接参数，并提供幂等优雅停机：先
   停止接收新连接，等待在途请求，到期后关闭剩余连接并返回可审计停机结果。
7. 健康接口只表示当前宿主处于 `ready` 或 `draining`，不得宣称开放目录、ERP、支付、
   外部平台、生产 TLS 或公网部署已经就绪。

## 验收标准

1. 本机真实 TCP 请求可穿过 HTTP 宿主进入签名运行时，并保持成功结果和幂等重放。
2. 方法、路径、Content-Type、声明体积和流式体积错误在业务处理器前被拒绝。
3. 签名失败由运行时安全投影；注入异常和非法运行时响应由宿主投影为通用 500。
4. 健康读取不触发商户能力、幂等记录或业务写入，并能反映停机状态。
5. 优雅停机等待在途请求；超过期限时强制关闭连接，重复关闭保持幂等。
6. HTTP 与调用方提供证书的 HTTPS 模式共享同一请求处理器和安全边界。
7. 新子路径 Node 测试、连接器全量测试、ERP 运行时桥回归和包清单检查全部通过。

## 非目标

- 不签发 TLS 证书，不配置 DNS、反向代理、系统服务、防火墙或生产密钥。
- 不实现平台运行绑定发布连接器、服务发现注册或自动部署。
- 不新增支付、结算、外部平台适配器、多机幂等或跨区域高可用。
- 不把本机 TCP/HTTPS 夹具描述为公网生产验收。
