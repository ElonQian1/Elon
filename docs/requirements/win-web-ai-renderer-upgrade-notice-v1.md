# Win 网页 AI 富内容渲染升级提示 V1

## 目标

当 ChatGPT 或 Google AI 官网在一条已经完成的回答中出现当前 Win 原生渲染器尚未完整支持的
富内容时，一龙不得静默丢弃、显示空卡或让用户误以为官网只返回了纯文本。原生聊天继续显示
已识别的正文、引用和富卡，同时明确提示用户查看官网完整内容，并引导检查 Win 客户端更新。

## 范围

- 仅修改 Win/PC 原生聊天的富内容兼容性判断、消息提示和契约测试；不修改 PWA。
- 复用 `yilong.rich-content.v1`、现有 `AiChatMessageRow`、官网完整内容入口和 Win 更新页面，
  不建立第二套聊天 UI、更新器或富内容协议。
- 兼容性判断只读取完成状态、内容 part 类型、版本化 schema、kind 和有界安全原因码；不读取、
  记录或上传回答正文、URL、域名、Cookie、Token、请求头或原始私有响应。
- 生成中、页面水合中、空占位或已经受支持的 V1 富卡不提示，避免把瞬时 DOM 状态误报为官网升级。

## 验收标准

1. 已完成的 assistant 回答包含未知 schema、未知 kind、无效富卡，或当前只能降级描述的
   chart、map、media、artifact、interactive 内容时，最后一条受影响回答显示非阻塞升级提示。
2. 提示文案说明“官网出现了当前版本尚未完整支持的新富内容”，不武断声称厂商故障；正文、
   引用和已支持富卡继续渲染。
3. 提示提供“查看官网完整内容”和“检查 Win 端更新”，分别复用现有官方页控制器与节点更新页面。
4. streaming/pending 回答、普通 Markdown、代码、表格、公式和合法 finance/weather/media/map V1
   富卡不误报；历史列表中只提示最新一条完成且受影响的回答，避免重复横幅。
5. 兼容性结果只含固定状态和固定安全原因码，不持久化原始内容或网络数据；ChatGPT 与
   Google AI 模式均适用。
6. 定向契约、用户浏览器回归、TypeScript、lint、生产构建和源码体积门禁通过。

## 非目标

- 不在本功能中主动重放厂商 POST/流式生成请求，不启用生产私有响应授权。
- 不把“尚未支持”伪装成“客户端已经有可下载的新版本”；是否有更新仍由现有更新服务判断。
- 不复制厂商 CSS、前端包或整页 DOM。
