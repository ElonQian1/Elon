# 节点算力共享运行健康 V1

状态：已接受并实现
日期：2026-08-02

## 决定

为节点所有者提供只读运行健康快照，基于持久化共享推理记录计算近 24 小时终态数、失败数、Token 预留偏差和当前过期租约。健康快照只进入本人节点策略接口，不进入公开节点目录。

## 规则

1. 只统计消费者与提供者不同的 `server_node_llm` 任务，所有者自用不计入共享风险。
2. 实际 Token 超过准入时保存的预留预算，记录 `token_budget_overrun`。
3. 活动任务超过租约期限仍未终结，记录 `expired_active_run`。
4. 近 24 小时出现执行或结算失败，记录 `recent_execution_failure`。
5. 预留超出或过期活动任务为 `critical`；仅近期失败为 `warning`；其余为 `healthy`。
6. 快照是运行诊断证据，不自动扣款、惩罚、赔付、提现或提交链上交易。

## 原因

每日预算只解决准入风险。节点所有者仍需要看见估算偏差、失败和失联任务，才能决定是否调整模型、预算或停止共享。将这些事实限制在所有者控制面，可以提高可运维性，同时避免公开暴露节点故障细节。

## 后续边界

- 后续可增加时间序列、模型维度和可确认的事故处置，但不得根据瞬时快照直接执行经济处罚。
- SLA、赔付、声誉和链上结算必须另立决策，并使用可复核的终态证据。
