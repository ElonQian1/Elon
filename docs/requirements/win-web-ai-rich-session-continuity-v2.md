# Win 网页 AI 富内容会话连续性 V2

## 用户问题

ChatGPT 与 Google AI Mode 共用原生聊天首页和各自持久 WebView2。切换厂商或后台恢复时，
多个前端恢复路径可能同时请求创建同一标签的 WebView2；Rust 在两次“尚不存在”检查之间发生
竞态后，后一个请求会报“同名 WebView 已存在”，原生输入框随即保持不可用，富内容官网区域
也无法接管。在线完成回答虽然能使用官网最后一条回答节点，但创建竞态会把正常的缓存优先、
后台同步流程退化成错误页或黑屏。

## 范围

- 只修改 Win/Tauri 网页 AI 会话宿主、PC 原生聊天调用去重和对应测试；不修改 PWA。
- 同一厂商与本机身份的后台打开请求在前端合并，Rust 端仍以进程级创建门禁作为最终一致性保护。
- 已存在的 WebView2 必须直接复用，不清空 Profile、不重新导航、不丢失访客 Cookie 或当前上下文。
- 保留现有“在线完成回答使用官网回答节点、加载/流式/缓存阶段使用原生 AST”的分层策略，
  不新增第三套聊天 UI，也不扩大私有响应授权范围。

## 验收标准

1. 同一标签的并发后台打开只执行一次桌面创建调用，后续调用共享结果；显示窗口与后台打开不错误合并。
2. Rust 在检查与创建 WebView2 的完整临界区内串行化，第二个请求能复用第一个请求创建的页面，
   不再返回“同名 WebView 已存在”。
3. 复用已有页面时只请求适配器快照，不导航到首页、不清除缓存或 Cookie；失败后仍可正常重试。
4. ChatGPT/Google AI 切换、新建会话、缓存首帧与官网回答区域的现有行为保持兼容；
   `test:user-browser`、PC typecheck/build/lint、相关 Rust 测试和 Win Web AI 全量验证通过。
5. 正式发布后本机节点发布身份精确匹配目标提交，Win 客户端重启后切换 Google AI 不再出现重复 WebView2 错误。

## 非目标

- 不读取或持久化 Cookie、Token、Authorization、请求头或原始私有响应。
- 不复制厂商整站 UI/CSS，不新增完整浏览器、无限标签页或 PWA 功能。
- 不把研究许可或口头授权自动登记为生产私有接口授权。
