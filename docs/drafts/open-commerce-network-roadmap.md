# 开放商业网络阶段路线图

## 当前实施切片

第一版已经实现并验证“商户节点 → 能力发布 → 发现 → 授权调用 → 计量审计 → MCP/PC 观察”的项目级纵向闭环。权威边界见：

- `docs/decisions/open-commerce-network-v1-architecture.md`
- `docs/open-commerce-network-v1-api.md`
- `docs/open-commerce-network-v1-acceptance.md`

真实支付、第三方平台连接器、消费者数据保险箱、多排序器和联邦治理继续留在后续阶段，不进入第一版完成条件。

## 阶段一：商户 AI 经营系统

选择一个高复购行业和单一区域，交付数据连接、经营诊断、营销执行、小游戏、会员召回和结果归因。目标是证明商户获得的增量收益或节省成本高于产品费用。

关键验证：

- 哪些数据源可合法稳定接入；
- 商户是否愿意持续付费；
- 哪类经营任务能形成可重复闭环；
- 50–100 家商户能否形成足够密度。

## 阶段二：标准化商户节点

把第一阶段积累的数据模型与工作流固化为可迁移的商户节点，加入身份、授权、能力描述、审计和托管迁移。

关键验证：

- 商户能否在不依赖唯一客户端的情况下发布能力；
- 平台托管、自建和第三方托管能否兼容；
- 数据新鲜度、失败语义和权限边界是否清晰。

## 阶段三：开放消费者 AI 与开发者接入

开放 SDK、API、MCP、沙盒和计费，支持不同消费者 App 与 AI 发现和调用同一商户能力，并完成至少一个跨 App 预约或交易闭环。

关键验证：

- 多排序器是否真正可替换和解释；
- 调用费与交易服务费由谁承担；
- 开发者是否因“一次接入多个商户”而加入；
- 身份、授权、风控与争议证据能否闭环。

## 阶段四：联邦治理与可选基础设施

网络规模与经济模型成立后，再决定是否成立独立基金会、如何治理协议与认证，以及是否引入去中心化存证、边缘推理和闲置算力市场。

Sui 作为阶段四候选所有权与结算层的设计边界、对象模型、任务闭环、资产分层和验证门槛，见 `docs/drafts/open-commerce-network-sui-agent-economy.md`。

这些长期方向必须单独验证可靠性、安全、成本和收益，不能成为前三阶段的交付前提。

## 近期未决任务

1. 选择第一行业、城市和理想商户画像。
2. 盘点官方 API、商户导出和 POS 连接能力。
3. 定义协议最小版本：发现、身份、授权、调用、订单和结算的边界。
4. 设计免费信息、收费能力与交易费的定价实验。
5. 建立商户身份、数据质量、虚假评价和欺诈治理方案。
6. 核验“共市”等品牌、域名和商标可用性。
7. 为商业计划书中的每项技术主张建立演示或测试证据。
