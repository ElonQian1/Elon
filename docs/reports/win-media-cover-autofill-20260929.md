# Win 抖音与小红书封面自动补齐

状态：实现、正式发布、本机自动升级及两条原群链接的 Win MCP 取图/解码验收完成。

## 原因

APK 1829 的成功证据来自打开原网页后的同内容回读与本机缓存。Win 卡片仅靠服务器预览时，可能有标题和作者却无图；原网页适配器虽已共用，首次卡片没有自动调用它。不能把两端已更新或解析器 fixture 通过当作首次卡片有图。

## 实现

- 共享卡片在可见范围触发预览后通知 PC 补图，已有图片不启动补图。
- PC 使用账号/服务器/会话作用域、单飞串行队列、最多 8 个排队任务、30 秒失败退避。退出会话或切账号后的结果不入缓存、不更新 UI。
- Win 专用原生命令只接受严格白名单中的抖音视频页、小红书笔记页，保留原分享参数，不接受任意脚本或 HTTP 地址。最多一个临时阅读 WebView，35 秒截止，结束必关闭；关闭媒体自动播放，不影响用户主动打开的阅读标签。
- 共用 APK 的生产适配器及同内容 ID/CDN/可见标题校验；小红书用移动网页布局，抖音用桌面页面的被动详情观察。不复制 Cookie、不重放签名请求、不向共享服务器上报本机读回。
- 成功后继续复用现有 24 小时、128 项、2 MiB 本机缓存。旧壳或平台验证失败保留原网页入口和更新预览，不伪造封面。B站既有取图和播放器路由不变。

## 验证

- 群业务 MCP 只读取得原群消息完整链接；未发送消息。真实 Chromium 运行生产适配器，抖音约 5 秒、小红书约 2 秒取得同内容图片，浏览器解码通过。此项不是正式 Win 壳验收。
- `test-social-media-cover.cjs` 5 项覆盖串行/单飞/队列容量、取消、退避、账号切换、缓存通知、Native ACL/AppManifest 注册及脚本/属性触发的自动播放拦截。
- 原生 URL 白名单测试、PC TypeScript/生产构建、共享卡片既有合同通过。
- 真实公开封面使用生产卡片 JS/CSS 在 1280px、360px 宽度渲染，图片可见且没有横向溢出；这是独立卡片渲染证据，不是 APK 或主群聊窗口截图。
