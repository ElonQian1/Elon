# 通用 ERP 蓝图 V1 验收标准

## 蓝图与实例

- 维护者可把一个现有项目登记为官方 ERP 蓝图，并登记不可变版本。
- 商户可基于已发布版本创建独立平台项目实例，而不是共享同一数据库或工作区。
- 咖啡店和最小零售实例使用同一蓝图内核，但主题与插件不同。
- 实例只保存私有扩展的标识、版本和边界，不向平台上传源码。

## AI 需求处理

- AI 可检索能力目录并返回直接复用、组合实现、私有扩展或通用候选四类结论。
- 未授权时不得提交需求信号；提交内容经过字段白名单和敏感键检查。
- 相同 `need_key` 按不同商户实例去重，不允许单一商户重复请求制造虚假共识。
- AI 只能生成候选提案；只有蓝图维护者能接受提案并创建 Matter。

## 发布与升级

- 发布清单包含 Git 提交、模块版本、能力、迁移、兼容范围和回滚说明。
- 兼容检查能够识别缺失模块、版本不兼容、扩展点移除和私有扩展冲突。
- 只有通过检查的实例可进入准备和采用状态。
- 回滚恢复原固定版本，且前后私有扩展清单一致。

## 接口与界面

- HTTP 和 MCP 均可读取蓝图总览、能力目录并解析需求。
- 受控接口支持登记蓝图/版本/实例、提交信号、维护提案和准备升级。
- PC 工作台提供 ERP 蓝图页，能查看实例、能力、提案和升级状态，不展示密钥或原始经营数据。
- 自动化测试覆盖权限、脱敏、去重、Matter 桥接、兼容性和回滚。
