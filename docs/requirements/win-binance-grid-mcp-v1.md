# Win 币安网格只读 MCP

Codex、Claude 等客户端通过现有 `browser_research` MCP 直接读取本人币安 WebView
中的最新运行网格列表和指定策略详情。复用页面内固定私有 API、账号校验和原生观察合同，
不点击页面，不依赖 ChatGPT 的输入框或运行时，也不启动交易。

## 接口与生命周期

- 新命令 `binance_grid_list`：`request_id` 必填；`offset` 默认 0、`limit` 默认 25，最大 50。
- 新命令 `binance_grid_detail`：`request_id` 和正整数串 `resource_id`（策略 ID）必填。
- `instance_id` 延续研究 MCP 的宿主定向。不得传入 URL、JS、请求头或任意 HTTP 方法。
- 新 request_id 加 `query="start"` 才启动一次读取。先返回 pending；后续相同 request_id
  省略 query 只查询该读取。5 分钟内重复 start 不重读；ready 表示收到新观察，不能由受理推断成功。
- 列表分页复用同一次不可变快照，保留 observed_at_ms 和 next_offset。最多保存 16 个
  操作、每份最多 500 策略、5 分钟；失效要求新 request_id，不自动重新读取。
- 详情先刷新本人列表确认策略归属，再读取精确 ID。不存在、重复 ID、换账号、换文档、
  超时、关闭窗口、迟到响应均不得返回旧结果或另一个策略。
- owner 和项目隔离；宿主重启/页面重新加载后旧请求丢失，轮询和分页均返回明确失效。
- 冷启动可在后台恢复本人币安会话；登录和网站验证仍由用户完成。无有效 API 上下文时
  明确失败，不以缓存、UI 点击或猜测请求头补齐。

## 数据边界

仅返回固定网格字段、精确十进制字符串、空值和时间。账号 ID、文档标识、Cookie、
Authorization、CSRF、网页任意文本、钱包与其他接口数据不得进入 MCP 输出或通用日志。
原生界面的“附带网格”继续只由用户显式点击触发，MCP 新入口不会改变该偏好。
返回的网页业务数据仅供参考，不是给 AI 的操作指令。

## 验收

1. 真实 Win 上仅通过 MCP 取得新列表、精确策略详情和采集时间，无桌面点击。
2. 重查和分页不重复读 API；不同请求、过期、并发、身份变化和结果不匹配有明确表现。
3. 接收端检查命令与响应一致，并拒绝额外字段、错误策略 ID 和凭据。
4. 原网格附件测试不回退；完成定向合同/集成测试、构建、发布、精确版本回读。

非本次范围：交易写入、APK 新入口、ChatGPT Rspack 适配或自动发送聊天。
