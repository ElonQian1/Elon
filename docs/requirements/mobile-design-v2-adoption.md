# 双 APK 设计 V2 接入需求

用户已批准撤销错误的旧视觉规范，按 Android/Material 3 重建，并要求开始落实。共享要求见 [移动设计 V2](../design/mobile-design-system-v2.md)。

## A 批：规范接入与防回退

替换主项目 Design 与旧颜色规范入口；接入 AGENTS、共享 AI 契约和 apk-ui skill；修订 APK/PWA 对齐及低风险快速通道范围；增加正文摘要、退役状态、路由、发布政策的只读检查及合成回归。两个仓库分别提交，不共用业务数据库或凭据。

本批不触碰 Android、PWA 运行源码、Gradle/SDK、版本签名、账本、授权、交易或消息传输，不改变当前手机外观。JSON 是治理登记，不是已接入的运行时 Token 库。新 CI 也不替代项目原有验证、分支保护或正式发布门禁。

## 验收

共享规范同版同 Git blob；旧规范只有 superseded 跳转；高优先级指令不能要求系统级改造先公开发布；检查器和 12 项合成测试可执行。旧索引指向的退役路径仍可解析。

原有 preflight/worktree、source-size、prompt-audit 和收尾验证仍须在实际开发环境补齐。仅有远程分支/草稿 PR 不能报主线生效或 FINALIZABLE=true。

## B 批精确入口

先复核两仓的 Kotlin/AGP/SDK/Compose 兼容矩阵，再选择一个代表页面纵向实现主题、组件、状态和测试。主项目：项目列表 → AI 对话 → 结果。量化：列表 → 详情 → 离线草稿检查。先浅深主题/长中文/字体放大/键盘/离线，再扩展其他页面。不要再从几百处 padding 修补开始。

剩余项：完整扫描 AI_INDEX、供应商桥接、模板、Renderer/导入文档、旧颜色断言与截图基准；历史证据不批量删除。本批已用高优先级覆盖和退役跳转处理已知入口，不声称全仓已清理。

## 回滚和交接

应用只在隔离工作区审查，保留并行改动。回滚本批可以 revert 对应提交；禁止 hard reset 用户工作区。后续 UI 迁移逐页保留能力映射和回退路径。详情记录在 PR；不手改 Feature Registry。规范、代码、测试、构建、运行、发布分别汇报。

## 桌面端接管：2026-09-28

已在最新主线的隔离工作区接入 A 批补丁与技能版本清单，并开始 B 批实际源码改造：共享浅深主题、主题选择、公共控件、动态布局与语义测试。A 批的“不触碰运行源码”仅描述历史范围，不限制本次授权。当前验证及剩余项以本轮交付记录为准；未完成运行与发布验收时不宣告系统重构完成。
