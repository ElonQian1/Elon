# 游戏奖励结算候选核算工具

## 已接受范围

为独立核算方提供离线 Rust 工具：验证指定来源对单个主账号参与者的累计现金核算签名、连续期间、完整证据归档及精确币种，计算已有 `Settlement v1` 的未签名候选。用户已授权完善主项目与游戏之间的利润奖励框架。

已有主项目接口接受独立核算方签名，并不自行读取交易所。本批不更改这个接口及其信任模型；工具不读取签名私钥、不提交结算、不连接交易所、不生成奖励预算、不支付。候选输出不能直接作为 Signed Settlement 或链上授权。

量化仓库的展示 PNL、QSHARE NAV、ESK 价格和用户本金不能直接作为利润输入。上游必须建立正式的单参与者已对账累计现金出口；当前该出口尚未完成，本批不能宣称真实资金接通。

## 验收条件

- 配置固定政策摘要、币种及小数位、来源公钥、参与者、钱包绑定和起算点；签名错误、Paper、跨账户、跨币种、未知字段和不规范整数失败。
- 净额等于累计已实现交易损益 + 累计净资金费 − 累计交易费 − 累计其他成本 − 当前准备金留存；保留负数，不截断亏损。本金和未实现损益只参与审计，不计为利润；历史已发奖励由主账本扣减，工具不再次扣除。
- 首期从固定起算点开始；后续要求上一来源签名与核算方签名的上一 Settlement，两条链分别连续，费用累计值不得倒退。更换政策或来源需要独立迁移流程。
- 五种证据角色完整且顺序固定，CLI 验证所有内容摘要对应的本地文件；缺失、篡改或超限证据失败，输出采用 create_new，不覆盖已有候选。
- 候选携带原签名来源、核算分解、证据摘要、原 Settlement 结构和准确签名字节；输出标明未签名、未支付、外部事实仍需核算方复核。
- 测试覆盖亏损恢复、准备金释放、浮盈/本金排除、费用缺失、签名与连续性、溢出、取消式无输出失败、原主项目账本互操作，以及真实命令行文件边界。

## 模块与交付

`tools/esk-game-reconciler` 为独立离线程序，模型、验签、核算、文件和 CLI 分离；每个新增文件预计少于 500 行。复用主项目 Settlement 源类型，运行主项目受管 Rust 验证及增量门禁，代码推送交付；不修改后端运行逻辑或发布配置。

详细使用和上游缺口见 [核算合同](../esk-game-reconciliation.md)。测试只使用生成密钥及合成账目。
