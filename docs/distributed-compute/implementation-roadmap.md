# 分布式算力实施路线

本文只规定阶段目标、顺序约束和退出门槛，不记录某次编译或专项测试结果。当前实现成熟度统一见 [`current-implementation-status.md`](current-implementation-status.md)，稳定领域边界见 [`architecture.md`](architecture.md)，各接口的精确约束以专题文档为准。

## 路线原则

- 普通公网节点按独立任务参与，不把异构设备描述成低延迟虚拟 GPU。
- 市场准入、任务执行、证据验证、内部结算和外部付款是彼此独立的权威层，不用一个回执替代下一层授权。
- 新阶段必须复用前一阶段的稳定身份、版本和摘要，不另建平行账本或第二套状态机。
- 默认关闭高风险能力；启用、撤销、隔离和恢复都必须有明确主体、幂等键、审计证据与失败关闭行为。
- 文档中的目标不等于生产能力；只有当前状态页和验收证据可以声明成熟度。

## F0 统一语言和合同

目标是统一 Provider、Pool、Offer、SKU、Price Snapshot、Job、Reservation、Claim、Attempt、Execution Receipt 和 Settlement Receipt 等领域语言，并让旧 LLM 节点路径保持兼容。

退出门槛：

- 合同具备稳定身份、版本、摘要、因果引用和向后兼容策略。
- Store、Service、HTTP/MCP 和客户端使用同一语义，不各自复制状态定义。
- 关键拒绝路径具有合同测试，旧客户端不会被无提示强制升级。

## F1 用户节点成为可插拔 Provider

目标是在用户明确开启共享后，按硬件和任务需要安装受信插件、运行时与模型工件，生成有时效的技术就绪证明，再由独立市场流程创建 Offer。

退出门槛：

- 签名、内容寻址、原子安装、回滚、撤销、隔离和跨重启恢复形成完整闭环。
- Windows 特权组件与普通插件使用独立信任根和授权链；普通插件不能授权内核代码。
- 真实 Sidecar/Runner、探针、工作准入和节点命令通道在受控环境通过故障矩阵。
- `ReadyCapability` 只代表技术就绪，不自动产生报价、容量、收入或任务授权。

## F2 Broker、执行验证和结算

目标是形成从报价发现、预算和容量预留、任务派发、租约续期、用量证据、终态验证、内部结算、争议处理到提款申请的完整业务链。

退出门槛：

- Broker 在单一权威事务中锁定价格、预算和容量，失败时无部分写入。
- 真实 Adapter/Runner 完成 Start、ACK、Renew、Cancel、超时、重试和 fencing 验证。
- Provider 声明、平台观测和消费者审核保持分离，并由明确 Verification 规则形成可信终态。
- pending、available、withdrawn、纠正和释放可从不可变账本重建并通过并发、崩溃及生产数据库升级验证。
- 外部银行、钱包或 Sui 付款由独立适配器执行和核验；内部提款回执不得冒充外部到账。

## F3 外部算力池与企业集群

目标是让企业 GPU 集群和外部算力池通过受控 Adapter 作为逻辑 Provider 接入，同时隐藏凭据正文并保留可撤销的运行权威。

退出门槛：

- Adapter 发布、漏洞与沙箱复验、凭据授权、Secret custody、TLS 传输、运行探针和激活形成单一可审计链。
- 至少一个真实外部 Provider 完成受控生产试运行、故障恢复和停用演练。
- Provider 激活不绕过 F1/F2 的市场准入、容量、派发、计量和结算门卫。
- 外部 Provider 的真实 SLA、价格和能力由可验证来源提供，不由平台静态声明代替。

## F4 标准化容量与高级市场

目标是在 F2/F3 稳定运行并形成真实供需之后，围绕标准 Compute SKU 和交付窗口扩展容量承诺、分配、指数、标记价和到期交割能力。

退出门槛：

- 价格来源具备多源验证、异常样本处理和可追溯治理，不把 fallback 曲线描述成真实指数。
- 容量承诺与实际可交付资源、风险限额和履约补救绑定。
- 订单、持仓、结算和风控使用独立权威模型，不复用任务账本伪装金融账本。
- 该阶段不得阻塞 F1-F3 的基础供给、执行和结算闭环。

## 推进顺序

1. 先完成 F1 的真实节点安装、运行、撤销和恢复闭环。
2. 再完成 F2 的一笔真实任务，从报价到内部 available 余额全链可重放、可审计。
3. 接入一个真实外部 Provider，完成 F3 生产试运行和故障演练。
4. 只有在真实供需和结算数据稳定后，才进入 F4 高级市场。

跨阶段工作必须在 [`current-implementation-status.md`](current-implementation-status.md) 记录验证强度，并链接独立验收证据；不得把“代码已写”“静态构建通过”和“真实生产闭环完成”合并为同一状态。
