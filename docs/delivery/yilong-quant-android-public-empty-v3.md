# 官方量化 APK 公开空状态 V3 交付证据

## 交付结果

主服务器的固定量化下载地址现在具有公开、稳定且不误导用户的空状态：在没有通过
新版准入的正式 APK 时，匿名请求直接得到 `404` 和“暂无可安装新版 APK”，不再
回落到成员鉴权并错误显示“缺少下载 token”。响应带 `Cache-Control: no-store`，
避免客户端缓存过期的空状态。

这个例外只适用于精确项目 ID `yilong-quant`。相似项目和普通项目仍执行既有成员
下载鉴权；存在合格量化发布时，原有受管工件、路径限制、大小和 SHA-256 复核以及
匿名 `200` 下载路径不变。

## 实现与验证证据

- 下载处理器在公开目录没有返回合格发布后，先识别精确官方量化项目并返回非缓存
  `404`；它不会读取 bearer、查询参数 token 或成员关系。
- 真实处理器测试使用全新临时 SQLite 和合成账号，覆盖无凭据、伪查询 token、伪
  bearer 三种官方请求，三者均返回同一 `404`，响应没有鉴权提示。
- 回归测试对相似项目 `yilong-quant-preview` 发起无凭据请求，仍得到既有 `401`，
  证明本切片没有扩大其他项目的匿名权限。
- 定向 Rust 验证通过；测试不连接外部网络，也不读取真实用户、密钥或发布配置。

## 线上发布回执

- 主服务器 `0.3.1730` 已从提交
  `fbcde10e2905e5f5239623214fd631aee2424f89` 发布；健康接口返回 `OK`，版本接口回读
  的源码提交与发布提交一致。
- 匿名访问固定地址实际返回 `404`、`Cache-Control: no-store` 和稳定中文错误；请求
  没有携带账号或 token。
- 公开项目目录仍返回 `yilong-quant.latest_apk_url = null`，与“当前没有合格新版”
  的真实状态一致，没有恢复旧包或制造虚假可安装入口。

## 发布与验收边界

本切片只纠正“尚无正式新版 APK”时的线上表达，不能替代量化 APK 的正式签名、上传
和真机验收。量化 `0.5.0 (5)` 仍须使用既有正式证书，由有权限的人员完成受控上传，
再验证固定地址返回 `200`、服务器摘要与设备端包名/证书/版本一致。

本批不读取或创建签名材料，不构建、签名或上传 APK，不修改用户余额，不移动 ESK、
SUI、USDT，不调用币安或执行交易。
