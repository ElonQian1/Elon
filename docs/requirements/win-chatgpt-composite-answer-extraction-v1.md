# Win ChatGPT 组合回答原生提取 V1

## 用户问题

ChatGPT 新版回答可在同一个助手回合中同时放置行情卡、正文、引用和反馈控件。现有 Win
适配器只读取助手节点中的第一个 `.markdown`，因此会把“提供反馈”误当正文；生成完成后
原生聊天只剩通用富卡，还会错误显示“完整同步”，迫使用户回到整页官网才能看到回答。

## 范围

- 只交付 Win/Tauri ChatGPT 官方 WebView 与原生聊天链路；不修改 PWA UI。
- 复用现有消息协议、`yilong.rich-content.v1`、行情卡、引用卡、缓存与官网完整页，不建立
  第二套聊天状态或独立测试窗口。
- 将同一助手回合内多个正文容器按 DOM 顺序合并，并排除复制、反馈、重试等操作栏文本；
  富卡继续从整个助手回合识别，不能遮蔽同回合正文。
- 原生正文不充分时不得宣称“完整同步”；界面保留当前原生消息并明确提示适配器需要更新，
  官网完整页仅由用户显式打开。
- 上线前原始响应研究同时修复当前 ChatGPT 请求族匹配与可观测状态，采样失败不能影响聊天。

## 验收标准

1. “行情卡 + 正文 + 引用 + 反馈控件”组合回答在原生聊天同时显示行情卡和完整正文，正文不再是
   “提供反馈”。
2. 生成中保留原生用户消息和稳定的回答中状态；完成后仍停留在原生聊天，不自动切换或覆盖为
   官网完整页。
3. 仅反馈/复制/重试等页面控件不能形成已完成助手正文，也不能触发“完整同步”成功状态。
4. 现有纯文本、Markdown、表格、代码、引用和行情卡行为不回退；合成 fixture 覆盖多正文容器、
   嵌套容器去重、操作栏排除和富卡并存。
5. 本机 DPAPI 快照可证明正文与富卡同时进入同一助手消息；Win 发布后实际运行版本精确匹配目标
   Git SHA，并通过真实已存在回答的只读回归检查。

## 非目标

- 不复制 ChatGPT 整站前端、CSS 或品牌资源。
- 不重放生成回答的 POST，不绕过登录、真人验证、地区限制或账号策略。
- 不修改 Android/PWA 产品 UI；共享适配器若需调整，必须保持协议向后兼容。
