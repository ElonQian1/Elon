# 普通群聊 Web AI 接入

## 范围

目标是首页普通群聊使用网页 AI，而不是把项目工作模式或个人 ChatGPT 页面搬进群聊。
既有群消息存储、成员权限、附件、摘要帖和工作模式语音输入保持不变。

## 当前实现

第一批共享请求底座已完成，第二批已接入 APK 群聊网页执行路径（发布与真机验证状态见下）：

- `social_ai` 的群聊提及和 `social_ai_message_reply` 的选中消息入口，共用
  `store/social_ai_messages::requests`，不再各自用进程内锁竞争同一条消息。
- `(group_id, trigger_message_id)` 唯一约束保证当前回复请求只有一个执行者。
  重新生成应建立明确的新请求，不把重复点击解释成重新生成。
- 回复消息与完成记录在一个 SQLite 事务中提交；相同结果再次确认不重复插入，
  不同结果不能覆盖已发布回复。
- 结果不明不因轮询或进程重启重发；迟到结果仍可完成原请求。
- 完成时复核原请求者的群成员身份与源消息，已撤回源消息不再发布回答。

APK 的群聊提及和选中消息优先使用独立临时 ChatGPT 文档，复用现有页面适配器和
私有发送命令；不会导航或覆盖个人 ChatGPT 会话。请求记录不承载网页凭证。
`prepared` 可取消或明确选择备用 AI；`dispatched` 和 `indeterminate` 均禁止跨引擎重放。
派发许可只发一次，许可响应丢失也不猜测供应商是否收到。旧客户端继续兼容旧接口。

定向验证入口（只构建服务端，不构建 PC 节点与安装器）：

```powershell
& ./scripts/validate-rust.ps1 -- test --manifest-path server/Cargo.toml --bin elon-server social_ai_messages::requests::tests -- --test-threads=1
```

回归覆盖跨连接去重、并发领取、迟到结果、权限撤销、源消息撤回、事务失败回滚和迁移幂等。
测试过滤器必须使用 Rust 模块路径，不能用文件名；零测试通过不算验收。

## 第二批接线与边界

1. 原生群聊增加网页 AI 上下文传送确认。执行账号是发起者
   本机账号；接收回答的其他成员不需要登录网页服务。
2. 服务端原子保存群消息和网页请求归属，再广播消息，避免旧轮询抢先运行服务端 AI。
   选中消息也进入同一请求协议，不能另开手机直发旁路。
3. 固定源消息边界，构造有界群上下文。群聊网页执行容器与个人会话导航、缓存、草稿
   隔离；只复用已有身份与私有传输，不复用个人当前会话正文。
4. 使用请求者操作标识、单次派发许可、结果回传和服务器原子发布。进程退出、网络超时
   或供应商已接收但回传未确认时，不能切引擎重放。
5. 仅在确定未派发且用户允许时改用旧服务端 AI；费用和提供方需可见。不得把
   Cookie、令牌或个人账号身份上传到群服务器。
6. 原生 Snackbar 展示 ChatGPT 处理状态并允许取消。完整回答回写普通群消息；同步
   失败保留本机回答，再进入群或点击重试只补交结果。已派发但没有获得完整回答的请求
   保留不确定状态，不自动重问。当前尚无跨设备找回未完成供应商输出的能力。

实现入口：`GroupWebAiFeature`、`GroupWebAiExecutor`、`group_web_ai` 路由及
`social_ai_messages::requests::web`。群消息和请求预约在同一个事务提交后才广播，
旧轮询不能抢先发送。群上下文冻结在源消息行之前，最多 30 条、12000 字符正文。
兼容主线群消息修订字段；之后编辑群消息不会自动重发已经派发的 AI 请求。

## 群聊输入框与扩展边界

2026-09-15 第三批：仅普通群聊复用聊天 AI 的模型弹窗、蓝色档位滑杆、
高级菜单和输入框样式。工作 AI 移至“切换网页 AI”的二级选择；群设置、成员、
附件和提及保留，不把个人 ChatGPT 会话或工作项目界面搬进群聊。

- `GroupAiComposer` 只拥有群聊控件，退出恢复原控件；不绑定个人聊天控制器。
- `GroupAiConfigurationStore` 按服务器、一龙账号、群分别保存引擎与模型选择路径。
  模型目录复用已有有界异步缓存和预设；缓存 id 不直接用于另一个网页文档。
- `GroupAiModelPicker` 复用 `WebChatModelControlPopup`、模型映射和档位策略，
  在独立临时文档同步高级选项，不发送消息、不申请麦克风。
- `GroupWebAiModelConfiguration` 在现有单次派发许可之前，把冻结的模型/档位意图
  重新解析到当前文档并落实。档位数量漂移、选项不唯一、命令失败都不能继续发送。
  模型默认未指定时沿用临时文档默认值，UI 标为“默认”，不假称已选“自动”。
- 普通消息、转发提及和选中消息均使用发起时的配置。工作 AI 走原群聊服务端配置，
  不使用个人工作页的 CLI/模型设置；明确选择工作 AI 时提示可能计费。

后续工具按此边界扩展：在配置模型中增加类型化工具意图，在群聊菜单展示已接入能力，
在同一执行前配置阶段校验并落实；附件等有副作用操作单独维护确认与上传状态。
最后仍由现有群请求预约、单次派发和结果回传协议发送，不另造发送/重试通道。
不要直接挂接个人 `MainSocialAiChatFeature`，也不要为了显示按钮复制整套工作输入框。

本批 Android Release Kotlin 编译与 22 项定向测试通过（配置 7、群回复 3、共用模型控件策略 12）。
包含私有子菜单先于操作成功回执返回的顺序回归；已到达的菜单不得丢弃或靠 DOM 重读恢复。
组装接线由最终 Release 构建再次检查。发布以端点记录为准；设备端真实群聊问答仍需单独验收，
模型控件同步不等于问答通过。

## 群聊 AI 设置统一（第四批）

2026-09-15：第三批只复用了档位弹窗，提供方选择仍为独立对话框，工作 AI
也只有默认通道，没有可实际使用的模型设置。本批修正这两个缺口：

- `ChatAiChoiceSheet` 提供统一选择面板，个人聊天与群聊共用展示组件；
  不共用账号、群、会话配置或执行控制器。群入口名称为“切换 AI”，二级列出
  ChatGPT 与工作 AI；个人聊天仍保留原来的网页提供方和入口。
- ChatGPT 保留档位滑杆、高级菜单与模型路径；工作 AI 显示服务端可用模型目录，
  可选择具体模型，并单独设置是否使用备用模型。两种引擎的配置分别保留。
- 工作 AI 目录先显示已有缓存，再按 5 分钟有效期异步更新。请求失败保留缓存；
  目录不包含凭证或服务端地址，不改原工作页和个人聊天的模型偏好。
- 群消息提及、转发提及、选中消息都复用已有请求预约协议。`work` 动作在同一个
  数据库事务中固定模型设置并激活服务端执行；不创建网页执行容器。
- `group_ai_work_options` 按既有请求 ID 保存不可变配置，服务端实际调用所选模型。
  重复确认不得重新派发，已派发请求不得切换模型或引擎。旧客户端和没有显式设置的
  旧请求继续使用原有默认策略；明确选择工作 AI 不偷偷转到开发 CLI。

扩展时保持三层边界：选择面板只负责展示；`GroupAiConfiguration` 保存每群意图；
执行器把发起时冻结的意图落实到对应引擎。新增工具不得绕过已有单次派发协议。

## 暂不接入

- 个人会话目录、ChatGPT 项目文件夹、图片库与完整 Canvas。
- 编译、Git、发布、MCP 开发操作和多人实时语音。
- 将每条群消息自动送给 AI，或未经用户选择读取其他成员的网页账号。

附件、搜索与群摘要后续复用相同执行协议，不再各写一套发送或回退实现。
