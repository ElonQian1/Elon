# 开放商业消费者客户端加密数据保险箱 V1 验收

## 当前状态

`verified_local_crypto_pc_build`

## 已形成代码

- 客户端使用固定 PBKDF2-SHA256 和 AES-256-GCM 参数加解密自由文本。
- 密文通过附加认证数据绑定记录 ID 与修订号，明文信封再次校验相同绑定。
- 服务端按用户和项目隔离保存密文，列表只返回最小元数据。
- 创建、读取、更新、下载密文和显式删除 API 及 PC 操作入口。
- 更新和删除使用修订号乐观并发，服务端限制条目数与密文大小。
- 审计不包含标签、明文、口令或派生密钥。

## 已验证

- Node 24 直接加载 PC 浏览器实际密码学模块，使用 Web Crypto 完成 Unicode 明文往返，并确认每次加密使用不同盐值、随机数和密文。
- 错误口令、密文篡改、跨记录替换和跨修订替换均以统一认证失败关闭。
- 客户端在 PBKDF2 前拒绝错误算法、错误迭代、非法时间、非规范 Base64、过短或超过 1 MiB 的密文、非法口令和超过 900 KiB 的明文。
- 服务端真实 `elon-server` Rust 专项覆盖合法 V1、非规范或超长 Base64、密文上下限、记录 ID、修订、算法参数和 RFC3339 时间；超长编码在 Base64 解码前失败。
- `test:open-commerce`、PC TypeScript 类型检查和 Vite 生产构建通过，现有 React 调用面可解析 `.js + .d.ts` 实现。
