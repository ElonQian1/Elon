# Win 控制层同版本更新 No-op v1

## 背景

Win 节点的重启恢复状态已经能够在目标版本与当前发布身份一致时收敛为 `runtime_online`。但是 `win_control_action(update_and_restart)` 仍会把同版本请求排队给 Tauri，导致桌面壳发生一次没有必要的重启，窗口 PID 变化并打断用户操作。

## 范围

- 仅修改 Win 端语义控制动作的服务端入队边界。
- 保留精确发布身份校验、`codex_mcp` 来源限制和动作审计记录。
- 不修改 PWA，不放宽任意命令、URL、脚本或更新目标权限。

## 行为要求

1. `update_and_restart` 的精确目标等于当前节点 `release_identity` 时，动作立即成为可查询的 `succeeded` 终态。
2. 同版本终态动作携带明确的 no-op 回执，说明已在目标版本，无需调度 Tauri 重启。
3. 同版本动作不得出现在 `pending_actions`，Tauri 不得领取或执行它。
4. 不同的合法精确目标仍按现有流程进入 `queued`，等待 Tauri 执行。
5. 非 `codex_mcp` 来源、缺失目标和非法目标继续被拒绝。
6. MCP 返回的完成说明必须区分“已立即完成”与“仍需等待 Tauri 回执”。

## 验收标准

- Rust 单元测试覆盖同版本立即成功、无待执行项、不同版本继续排队及原有校验边界。
- Win 本机发布后，重复请求当前精确版本得到终态成功回执。
- 在重复同版本请求前后多次采样，桌面进程 PID 不变，节点保持 `runtime_online` 且无活动重启事务。
