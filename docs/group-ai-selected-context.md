# 群聊 AI 选区、分享与私人续聊

本文件描述当前代码边界，不把规划或离线测试当作真机验收。

## 已实现的纵向链路

1. 群聊长按“AI回复”，或“多选 → AI 分析”，明确选中 1 至 100 条文字消息。
2. 确认界面允许补充问题，并明确回答会发到当前群。不自动上传附件。
3. 服务端按当前成员权限、群 ID、消息 ID 和 revision 重新取数，按真实时间顺序构造提示词。
4. 选区请求使用 `context_scope=selected`，不混入最近 30 条窗口，不自动进入旧工作 AI 回退。
5. 已有独立网页 AI 执行器保留临时空白会话隔离，私有发送传输和现有模型档位继续复用。
6. 服务端 dispatch 只发一次许可；结果不确定时不重新发送。完成时再次核验选区版本和权限。
7. 发起人可长按 ChatGPT 精选分析回答“转发”，预览“所选消息 + 补充问题 + 回答”，再选择群发送已有原生分享卡片。
8. 群成员点卡片，以已有原生只读聊天 UI 阅读，Markdown 和代码正文保留；重新打开和继续讨论均重新鉴权。
9. “继续私聊”打开自己的 ChatGPT 空白会话，确认新会话命令成功、路由与草稿为空后才填入选段草稿。必须由用户按发送，不自动写回群。
10. 返回键回原群；未发送的私人草稿需要确认放弃，不能带到群输入框。旧回答无法获取精选上下文时仍可选择仅转发正文。

## 数据与隐私边界

- 身份 Cookie、运行时令牌继续留在设备 WebView，不进入群聊服务端或分享卡片。
- `group_ai_selected_sources` 固定消息版本。编辑、撤回、退群后拒绝派发、完成或重新生成精选分享草稿。
- 完整选区超出 20,000 UTF-16 单位会拒绝，不静默截断。
- 同一 operation 不可改群、改用户、改选区或问题；不同成员可以各自分析同一条消息。
- 已显式发布的卡片是独立快照，原消息后续编辑不会重写快照；撤回分享仍走已有快照权限流程。
- 分享给其他群需要用户在预览中明确选目标。不会自动创建任何公开 ChatGPT 链接。
- 当前群聊分析执行器只返回文字；富文本 Markdown 保留，但本批未接通图片附件输入或结构化生成图片输出。
- 私人续聊当前只准备文字及完整写作/代码块；图片保留在卡片阅读页，不会自动上传或声称已交给模型。

## 尚未实现

| 能力 | 当前边界 |
|---|---|
| 一个用户账号内，一个群绑定一个 ChatGPT Project | 未实现；当前群聊执行器仍使用临时会话 |
| 群改名不换项目、项目删除恢复、跨设备创建去重 | 未实现，依赖下方生命周期合同与实测协议 |
| 项目内多个主题会话和显式继续既有话题 | 未实现；不能用当前临时请求宣称持久上下文已接通 |
| 官方公开分享链接原生导入、官方会话分叉 | 未实现；现有续聊是用户确认后的选段文字草稿 |
| 任意旧群 AI 回答生成完整精选上下文 | 不支持；只有本人发起的 selected ChatGPT 请求有明确来源记录 |
| 图片/附件直接参与群分析并进入私人续聊 | 未实现，必须复用已有上传协议并保留逐项确认 |

## 项目生命周期后续合同

- 绑定主键应为一龙用户 + 厂商账号及 workspace 指纹 + 不可变 group_id；群名仅作显示。
- 每个绑定有 generation、project_id、状态及创建操作租约。后端只存映射和无凭证回执。
- 创建前在设备同源身份层验证账号/workspace；服务端租约防止多个设备重复发起创建。
- 超时、401、403、限流、目录未加载不等于删除。只有经确认的缺失才允许显式重建。
- 创建结果未知时不能盲目重放 POST；先核对已创建对象，再提交绑定。
- 项目记忆和“仅所选消息”是不同模式。严格选区默认保持隔离，不能悄悄读取其他项目聊天。
- 项目内以主题 ID 绑定 conversation_id；私聊续聊不能复用群发布请求或自动发布结果。
- 已在当前公开页面资源确认项目 API 路由，但创建请求体及完整回执尚未实测；禁止据此写猜测协议默认上线。

### 群聊准备超时根因

- `v1.1.1787` 的有界 MCP trace 确认：独立页面约 2 秒已登录且输入框就绪，但 `temporary_route=false`、`ready=false`。
- `chatgpt_web_adapter.js` 出于最小化数据暴露，快照 URL 只包含 `origin + pathname`；旧群聊策略却从该 URL 要求 `temporary-chat=true`，因此合法临时会话也永远不能就绪。不是私有接口需要等待更久。
- 修复让群聊执行器只在本机读取当前隔离 WebView 的实际地址，并核验快照与实际文档的 origin/path 一致；临时参数、空消息、无草稿、非流式和发送授权检查全部保留。实际完整地址不写入日志或后端。
- 回归覆盖被裁剪的合法快照、地址与快照错配、普通/旧/跨源页面、额外作用域参数以及草稿/历史消息/登录阻断。发布后的真实回答与分享链路仍需另外记录，不把这项代码修复算成整条验收通过。
