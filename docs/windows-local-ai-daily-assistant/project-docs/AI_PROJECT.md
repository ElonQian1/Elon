# AI Project Guide

最后更新：2026-07-09

## 项目是什么

Windows 本地 AI 工作日报助手是一个个人效率工具。它在用户明确授权后，在 Windows 本机定时采集当前工作状态，用 AI 把工作过程整理成时间线，并生成可编辑、可复制、可保存的 Markdown 日报。

它的定位是“用户自己的工作记忆助手”，不是公司监控系统。

## 目标用户

MVP 目标用户：

- 每天需要写日报、周报或工作总结的人。
- 程序员、产品经理、运营、设计、自由职业者。
- 愿意授权本机记录工作轨迹，但要求能暂停、删除和排除隐私应用的人。

暂不服务：

- 老板远程管理员工。
- 团队考勤和绩效统计。
- 强审计行业。
- 需要跨设备云同步的企业客户。

## MVP 目标

第一版只验证一个闭环：

```text
用户开启记录
  -> 本机定时采集截图 + 前台应用 + 窗口标题
  -> AI 分析成结构化工作记录
  -> 本地保存文字化时间线
  -> 用户修正
  -> 生成 Markdown 日报
```

MVP 必须包含：

- Windows 桌面端。
- 暂停/恢复记录。
- 排除应用名单。
- 定时截图。
- 前台应用和窗口标题记录。
- 本地 SQLite。
- AI Vision 分析。
- 时间线查看、编辑、删除。
- Markdown 日报预览、编辑、复制、保存。
- 删除当天数据。
- 首次隐私说明。

MVP 不包含：

- 团队后台。
- 云端同步。
- 员工监控。
- 键盘记录。
- 录屏。
- 自动发送日报。
- macOS 或手机端。

## 推荐技术栈

- 桌面端：Tauri 2。
- UI：React + TypeScript。
- 本地系统能力：Rust。
- 数据库：SQLite。
- AI Provider：先抽象接口，第一版可使用云端 Vision API，必须保留 Mock Provider 和未来 Local Provider 边界。
- 打包：Windows 安装包，后续再考虑签名和自动更新。

## 最不能破坏的核心流程

1. 用户必须知道当前是否正在记录。
2. 用户必须能暂停记录。
3. 用户必须能删除本地数据。
4. 命中排除应用时不得截图上传。
5. 默认不长期保存截图原图。
6. 日报生成前必须允许用户预览和编辑。
7. 所有真实 AI 上传行为必须经过明确设置和说明。

## 项目负责人需要拍板的问题

必须拍板：

- 第一版是否允许云端 Vision API。
- 原图是否允许短暂落盘。
- 是否保存缩略图。
- 默认截图间隔是 1 分钟还是 5 分钟。
- 是否允许自动启动并后台常驻。

推荐默认：

- 云端 Vision API 可以作为 MVP 选项，但必须可关闭。
- 原图只短暂临时保存，分析后删除。
- 不保存缩略图。
- 默认 5 分钟间隔，用户可改 1 分钟。
- 不默认开机自启。
