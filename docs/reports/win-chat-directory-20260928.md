# Win ChatGPT 目录与正文读取

## 上游依据

本轮通过项目绑定 browser_research 读取用户已登录的生产 WebView 中已加载的官网代码，
没有复制 Cookie、令牌、聊天正文或请求头到报告，也没有更改置顶或发送聊天。

- 官网资源：`https://chatgpt.com/cdn/assets/647288.dfed090bc7.js`。
- 捕获代码 SHA-256：`e328c7416f3c1d62093d755fbe161c2b80eb74217e6f0cdd8e3d4d3201acc087`。
- 约 44257/44700 位置：官网分别 GET `/pins?item_type=project` 和 `conversation`。
- 约 68036 位置：置顶是 `{item_type,item}` 判别联合，项目 ID 来自 `item.gizmo.id`，会话来自 `item.id`。
- 普通会话列表不能单独证明置顶状态；截图、中文标题和 DOM 类名不是数据合同。

## 实现边界

- Win 专用 `chatgpt_win_directory.js` 版本化适配官网置顶合同，原有共享目录解析器保留。
- 身份材料只在页面同源请求内使用；读取有超时、单飞、文档和账号归属检查。
- 原生统一模型由实体 ID、类型、项目归属、置顶状态及顺序投影“置顶 / 项目 / 最近”。
- 同步未知字段保留缓存；明确 `false` 才取消置顶，空的权威置顶列表可清除旧置顶。
- 平时只刷新最近一页，旧会话显式加载；项目内容按展开读取。不是后台全量扫描。
- 完整历史分页与本次刷新完成分开，已完成的部分刷新也有两分钟有效期。
- 官网目录和本机缓存统一使用缓存优先的会话读取；旧异步请求不能覆盖新选择。
- 读取正文不要求输入框就绪，发送仍要求确认当前会话绑定；超时不偷偷切回上一会话。
- 没有正文时显示读取状态与重试入口；已缓存正文立即显示，后台更新不先清空缓存。
- 正文缓存保持系统加密，最多 200 个条目、合计 128 MiB，沿用 30 天过期策略。
- 原生 UI 与官网显示层独立；低频官网操作收进菜单，聊天模式不再堆工作区工具导航。

## 后续改版流程

1. 在许可范围内读取实际加载的资源、只读网络响应和结构，不根据截图猜字段。
2. 保存不含私人数据的最小合同样本，记录资源指纹和版本。
3. 只调整 provider 适配器，UI 不认识 `/pins`、官网字段名或 React 组件。
4. 结构未知时保留上次有效目录，不以空响应清空缓存或报告功能不存在。
5. 跑合同、乱序、缓存及渲染测试，再用生产身份进行一次只读验收。
