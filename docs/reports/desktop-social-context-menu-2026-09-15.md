# 桌面消息右键整改验收

## 发现与修正

现有 Windows 外壳默认加载线上 `/pc`，社交页已经是 React。消息虽有 `onContextMenu`，旧菜单仍把所有类型放进相同长列表，独立维护每行菜单状态，每条消息常驻更多按钮，没有图片/语音目标操作。

| 障碍 | 本轮行为 |
|---|---|
| 菜单像功能清单 | 32px 菜单行、统一图标、三组分隔；常用操作靠前，详情靠后；沿用深色主题 |
| 常驻更多按钮干扰阅读 | 仅悬停、聚焦、触摸时显现；已编辑标记始终可点击 |
| 图片、语音与文字混用操作 | 识别右键附件索引；图片查看/复制/下载，语音播放/暂停/复制已有转写/下载，文件下载 |
| 选中文字却复制整条 | 复制当前消息内完整选区，右键另一消息不会使用旧选区 |
| 连续右键及焦点混乱 | 会话级单实例；Escape 返回消息或原按钮；方向键/Home/End/Enter；外部点击、失焦、真正滚动和切会话关闭 |
| 放大后菜单被裁切 | 按实际缩放调整坐标及最大尺寸，窗口边缘避让 |
| 用户看不到操作失败 | 附件读取失败有中文提示；恢复网络后可重试，不显示内部异常栈 |

复制富文本仅在格式化文字中显示。编辑仍限定服务端支持的本人群文字消息；修改记录、撤回一分钟限制、引用版本快照、转发确认与部分失败续传保持原语义。收藏及隐藏明确“仅此设备”。没有增加尚无后端合同的私聊编辑。
