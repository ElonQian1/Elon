# 官方量化 APK 新版发布准入 V1

## 用户结果

主服务器不再把旧版、降级版或元数据不完整的一龙量化 APK 登记为当前可安装版本。
项目编辑者上传正式量化 APK 时，服务器只接受稳定项目 `yilong-quant` 的新版 Paper
发布合同；重复上传同一工件返回原发布记录，不制造第二个“最新版本”。在合格新版
尚未上传前，项目广场应诚实显示没有可安装新版，而不是继续分发历史旧包。

## 范围与依赖

- 复用现有项目编辑者认证、主服务器项目发布存储、公开下载路由和 Android 端最终
  包名/证书/版本复核。
- 本功能只收紧精确项目 ID `yilong-quant`；其他项目的既有发布合同保持不变。
- 最低版本为 `com.elon.quant`、`versionCode >= 5`、规范版本名不低于 `0.5.0`，
  渠道精确为 `paper`。
- 发布必须携带 40 位小写十六进制源码 Git SHA；服务器自己计算 APK SHA-256 和大小，
  并把内部准入证明绑定到这组工件身份，不接受调用方自报摘要或借用另一 APK 的证明。
- 服务器只做 APK 容器、Manifest、DEX 和签名块存在性的结构门禁；Android 端仍负责
  对真实包名、版本和唯一发布证书做最终验证。上传参数是已认证编辑者的发布声明，
  不能冒充服务器已经解析并证明 APK 内部身份。

## 新版唯一规则

1. 在创建发布目录或写入 APK 前，先验证项目 ID 对应的必填发布元数据和 APK 结构；
   旧版本、错误包名、错误渠道、缺失源码 SHA、非 APK 字节或无签名结构均失败关闭。
2. 对已发布版本实行版本码单调递增。低于当前合格版本的上传拒绝；相同版本码只有
   包名、版本名、渠道、源码 SHA、APK SHA-256 和大小全部一致时才是幂等重放。
3. 相同版本码但工件或来源不同、同一 APK 字节被改报为另一版本，均以冲突拒绝，
   不改写既有发布记录、项目首页或下载入口。
4. 幂等重放返回原 `release_id`；若原托管文件仍健康就清理本次暂存目录，若原文件
   丢失或损坏则先用本次完全相同且已验证的字节恢复并复核，再清理暂存目录。
5. 当前版本选择、发布列表、可安装筛选、稳定/历史文件下载、发布 ID 下载和项目广场
   安装入口都只承认满足新版合同的量化发布。旧记录无兼容承诺；即使数据库暂留内部
   审计，也不得进入用户产品面或成为可安装工件。
6. 项目目录和任务 APK 自动同步不得把旧量化记录重新写回 Android 下载卡片或生成
   404 安装入口；合格 `0.5.0 (5)` 或更高版本经正式发布页上传后才恢复公开安装。

## 验收标准

1. 单元测试覆盖精确项目、包名、渠道、版本名/版本码、源码 SHA、服务器摘要及 APK
   结构的正反例；相似项目 ID 不受官方量化专用规则影响。
2. SQLite 测试证明 `5 -> 6` 可发布，`6 -> 5` 拒绝，同版本同工件返回同一记录，
   同版本不同工件及同工件改报版本均拒绝，且发布号不产生空洞或重复。
3. 旧量化记录不再被发布列表、`latest_project_release`、可安装筛选、任一旧下载路由
   或首页/任务同步选中；其他项目旧有发布、列表、build 标签和下载行为通过回归。
4. HTTP 上传路径在任何磁盘写入前拒绝静态无效输入，冲突返回可区分的 409，结构或
   元数据错误返回 422，存储故障不泄漏内部路径或原始请求内容。
5. Rust 定向测试、相关项目广场/公开下载回归、源码尺寸与文档门禁通过；代码、服务
   部署、正式量化 APK 上传和真实设备安装验收分别报告。

## 非目标

本功能不读取、创建或提交 Android 签名密钥，不用 Debug 包代替 Release，不上传真实
APK，不移动 ESK、SUI、USDT，不连接币安或执行量化交易，也不把元数据门禁描述成
密码学签名验真。历史用户资产、付款、订单和设备应用数据不删除；旧 APK 不保留任何
用户可见兼容入口。
