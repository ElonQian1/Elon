# 多书签与独立阅读进度方案

## 范围与交付状态

面向每周上线一次、需要爬楼、在多个讨论位置间往返的用户。群聊、好友聊天、
自有个人 AI 对话与项目频道使用同一阅读语义，覆盖 APK、PWA 和 Win。
用户已授权实现与上线。群聊、好友首批由 `social-reading-bookmarks-v1` 独立登记，
已编写书签 API、持久化、同步及三端入口；交付状态见[本批记录](../reports/social-reading-bookmarks-20261002.md)。
父功能保留自有 AI/项目页面接入范围，不能把首批交付写成所有来源全部上线。

依据是本会话提出的“多书签、跳转历史、继续阅读后保存各自进度”需求。
基础见[统一消息时间线](message-timeline-v1.md)，
实现扩展见[书签与阅读位置技术设计](../design/message-reading-bookmarks-v1.md)。

## 前面讨论已形成的方向

1. 同一会话允许多个私人书签，每个书签有自己的阅读进度。
2. 固定起点和续读位置分开；向后阅读不移动原始标记。
3. 按消息身份直接定位，不按页码、数组下标或数据库 OFFSET 保存长期位置。
4. 每次只加载目标附近的有限消息，书签数量增加不增加同时加载的聊天窗口。
5. 书签不等于已读回执，也不自动扩大 AI 模型输入。

以下是已接受的产品合同；实际接口与首批差异见技术设计和交付记录。

## 三种位置与一个示例

| 对象 | 保存什么 | 何时更新 |
| --- | --- | --- |
| 书签起点 | 最初标记的消息，及创建时服务端确认的排序键 | 普通阅读永不移动；想标记另一处时新增书签 |
| 每个书签的阅读进度 | 上次停留的位置；另存最远到达的位置 | 只更新当前激活的书签 |
| 会话普通阅读进度 | 没有激活书签时上次实际阅读的位置 | 普通阅读时更新，独立于各个书签 |

周一在消息 A 创建“本周讨论”，从它续读到 B；另在 X 创建“技术方案”，读到 Y。
下周“本周讨论 → 继续阅读”到 B，“回到标记”仍到 A；“技术方案 → 继续阅读”到 Y。
群里新增一万条消息、其他消息撤回、清理本机历史缓存，都不改变这两个固定起点。

“上次停留”可以因主动向前回看而回退；“最远到达”只表示最靠后的到达位置，
不证明中间每条都读过，不显示为阅读完成百分比。首版主操作使用“上次停留”。

## 用户入口与可发现性

| 场景 | APK / PWA | Win |
| --- | --- | --- |
| 创建 | 长按消息 → 添加书签；消息更多菜单也可到达 | 消息更多菜单或右键 → 添加书签 |
| 管理 | 聊天室标题栏更多 → 书签，打开列表页或 Sheet | 聊天室更多 → 书签，打开侧栏 |
| 续读 | 点击列表项或“继续阅读” | 相同语义，可用键盘完成 |
| 固定起点 | 书签项菜单 → 回到标记 | 相同语义 |
| 普通进度 | 聊天室内“继续上次阅读”提示 | 相同语义 |

列表显示名称、标记时间、上次阅读时间、同步及访问状态；无名称时默认用“日期 + 时间”，
不把私人正文自动写入永久名称。允许重命名、备注和删除。重复点同一消息时复用已有书签；
确需同一起点的两个进度时用“另存为新书签”。创建只保存标记并提供“从此处续读”，
不悄悄替换当前激活书签。列表默认当前会话、按最近阅读排序，首版不依赖全局收藏中心。

删除书签不删除聊天记录。删除提供可撤销反馈；若正在读它，保留画面、退出该书签记录
模式，不再发送它的进度。撤销按技术设计新建恢复对象。
遵循[移动设计 V2](../design/mobile-design-system-v2.md)与[产品规则](../Design.md)：
关键操作有文字入口，APK 至少 48dp 触控目标；PWA/Win 支持键盘、读屏、焦点返回。
分别验证浅深主题、长中文及 100/150/200% 字体，不以跨端像素相同替代可用性。

## 进入聊天室和返回的规则

| 进入原因 | 打开位置 | 进度影响 |
| --- | --- | --- |
| 普通点击聊天列表 | 最新消息；有历史进度时显示“继续上次阅读” | 自动落到最新不覆盖之前的历史进度 |
| 书签“继续阅读” | 该书签上次停留；没有进度则用起点 | 成功定位后激活该书签 |
| 书签“回到标记” | 固定起点 | 激活该书签；定位动画不覆盖旧进度，继续阅读后才更新 |
| “继续上次阅读” | 会话普通阅读进度 | 激活普通阅读记录，不修改书签 |
| 通知 / 搜索结果 / 引用跳转 | 明确指定的消息 | 临时查看，保留出发点；可“返回阅读处” |
| 前后台 / 旋转 / 同一页面恢复 | 当前活动阅读位置 | 恢复不强制最新，也不算用户滚动 |

显式目标优先于页面恢复；没有显式目标的新开会话使用最新。
远端同步未回来时先展示本地可恢复位置和状态，不能稍后突然跳屏。
普通进群仍可直接看到最新，不能用自动恢复历史制造“群里有新消息但进群看不到”。

活动书签显示“正在续读：本周讨论”，提供切换书签和“回到最新”。
回到最新、发送消息需要前往最新、切换会话或退出前，先把当前有效位置写入本地；
回到最新成功后退出书签记录模式，最新位置不得写回刚才的书签。
网络失败保留原窗口和活动模式，提示重试，不用失败结果覆盖已有进度。

## 什么行为算进度更新

建议默认：用户主动滚动或键盘阅读后停止 600ms，采样安全区下方首个可见消息/正文块；
长消息保存块内位置。后台同步、预取、布局变化、定位动画、自动滚到最新及窗口裁剪
均不触发进度写入。辅助技术滚动属于用户阅读操作。消息菜单另有
“将此处设为当前续读位置”，供用户明确指定；没有活动书签时写普通进度。

本地先写入，网络合并上传最多每 3 秒一次；切换、退后台和退出会话尽力提交。
不能只在退出时保存，系统杀进程应恢复最近一次已落盘位置。
界面区别“已保存到本机，待同步”“已同步”“保存失败”；本地写失败必须可见。
自动显示的最新消息不覆盖旧进度，用户明确阅读操作后才开始记录新位置。
续读位置不代表理解程度，也不用停留时长推断整段历史已读。

## 定位、分页与性能

长期锚点包含账号、来源、项目/会话、消息 ID 和不可变排序键；像素 offset
只是当前设备辅助信息。跨设备、字体或图片尺寸变化时优先恢复消息与正文块，
无法对应则到该消息顶部，不能跳到别的消息。正式书签只接受已持久化消息 ID，
发送中的临时消息待成功后再保存。

用 `around(message_id)` 直接取目标附近一页，默认共 50 条、服务端最多 100 条。
向上到边缘加载更早，向下到边缘加载相邻的更新历史；显式“回到最新”才越过间隔。
目标高亮、媒体尺寸预留和可见锚点恢复一起工作，避免加载后跳动。
窗口裁剪后游标随保留的首尾消息重新计算，不能跳过被淘汰的中间历史。

沿用当前消息数量和文本预算：APK/PWA 默认 150 条、约 1.5 MB，PC 为 300 条、约 3 MB；
媒体及超长正文另做预算和延迟加载。这是实现约束，不是当前已经通过十万条历史或整机
内存验收的声明。书签列表分页 50 条，建议每会话上限 100 个、每账号 1000 个，
由服务端配置并返回额度，超限明确提示。多个书签不预加载多个消息窗口。

## 同步、删除与访问边界

书签默认仅自己可见，同一一龙账号跨设备同步。同步用服务端 revision 条件更新，
不只比较设备时钟。远端进度可更新列表，不能移动当前正在读的屏幕。
同一书签跨设备并发发生冲突时保留两个候选，显示“本机位置 / 另一设备位置”，
用户选择后成为共同续读点；不能直接取更靠后的位置而丢失主动回看的记录。

撤回消息保留占位，自动预览同步清除；不永久复制正文为书签快照。
物理删除时按服务端保存的排序键找同一会话内紧接其后的可访问消息，没有则找前一条，
提示“原消息已删除，已定位到附近”；原固定起点仍记录原 ID，不静默改写。
进度被删和起点被删独立处理；无可定位消息时保留书签并允许删除。
失去会话权限时停止定位和同步、清除自动内容预览；不跨会话寻找替代。

书签删除后，离线旧客户端更新不能将它复活。退出账号清除活动状态、可见缓存和旧回调，
持久队列按账号隔离，重新登录前不回放。断网设备不能立即获知远端撤权，联网后必须重验。
用户主动写的备注是本人数据；消息撤回不把笔记自动抹掉，也不自动复制失效正文到备注。

阅读进度、通知未读和已读回执分离。跳到后面的书签不表示中间全部已读。
首版书签定位路径不调用把最大 ID/时间戳当连续已读的旧回执，精确已读区间另行交付。
查看书签不改变 AI 输入；只有显式引用的授权消息进入既有上下文编译流程。

## 模块边界与交付顺序

独立 ReadingPosition 模块负责书签、进度、同步和导航意图，依赖现有 TimelineSource。
时间线负责消息窗口、分页、合并及锚点恢复。不另建聊天服务、不复制消息库、
不把全部逻辑塞进 MainActivity 或聊天页面。Win/PWA 共享网页领域逻辑，
APK 保持原生实现，使用同一版本协议与合同测试数据。

| 批次 | 完整交付切片 | 不能省略的条件 |
| --- | --- | --- |
| 1 | 群聊/好友：服务端定位、书签/进度及 APK/PWA/Win 完整入口 | 双向历史、离线重试、跨端冲突、权限和重入一起验收 |
| 2 | 自有个人 AI / 项目频道接入 | 保留流式、分支、任务卡、引用、权限，不宣称未接入页面已支持 |
| 3 | 外部厂商 Web AI 按适配器能力接入 | 无稳定 ID / 历史定位能力时只给有依据的会话级入口，不显示假定位按钮 |

群聊/好友首批有独立交付价值；不为提前认领而把父功能 `message-timeline-v1`
尚未完成的 AI/项目迁移标为完成。实施时按真实验收依赖登记可独立认领的切片，
保留父功能缺口；本次文档完善不修改其完成状态。

| B12 | 新旧客户端/服务器混用、服务端回滚 | 原聊天可用，未支持能力明确降级，已有书签数据保留 |
