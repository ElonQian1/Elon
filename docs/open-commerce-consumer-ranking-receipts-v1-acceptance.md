# 开放商业消费者排序凭证 V1 验收

## 当前状态

`implementation_uncompiled`

## 已形成代码

- 默认关闭、由消费者显式开启的排序凭证请求字段。
- 只保存输入指纹、候选范围、策略元数据和有序公开结果的规范负载。
- 服务端 SHA-256 摘要及 `signed_by_operator=false` 信任边界。
- PC 首次接收与下载前两次 Web Crypto 摘要复核。
- 下载文件同时携带精确负载字符串、解析后负载和摘要，便于外部工具复核。
- 每条有序结果固化当次公开目录的商户来源声明和新鲜度快照；二者均不构成外部平台证明。
- 现有三个 Rust 直接请求夹具补齐排序策略和凭证开关字段。

## 统一回归必须验证

- 省略或关闭开关时响应不含凭证，旧客户端仍可解析。
- 五种排序器、空结果、单结果、50 个结果和目录 100 候选上限。
- 搜索词、能力条件、App 身份和偏好明文不出现在凭证负载或下载文件中。
- 输入任一字段变化会改变请求指纹，结果顺序、分数、版本或目录时间变化会改变负载摘要。
- 来源类型、声明权威、新鲜度状态、声明更新时间或有效期变化会改变负载摘要。
- 声明期筛选开启与关闭会改变输入指纹，凭证回显对应固定筛选枚举。
- 服务端精确字节摘要、浏览器 UTF-8 摘要和独立 SHA-256 工具结果一致。
- 篡改 `canonical_payload_json`、摘要、算法或下载前内存对象会阻断操作。
- 凭证固定显示未签名、非付费、非全网穷举，候选上限与实际目录查询一致。
- Rust 序列化、HTTP 兼容、TypeScript、Chromium Web Crypto、下载文件和 PC 窄屏布局。
