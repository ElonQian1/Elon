# 商户 ERP 公共运行时内核 V1 需求

## 目标

把通用 ERP 从蓝图元数据推进为商户项目可直接依赖的无界面运行时，使不同商户复用同一套门店、商品、库存、采购、订单和审计规则，同时继续拥有独立项目、存储、主题和私有插件。

## 必须满足

1. 内核不保存全局商户数据库，不访问外部平台，不携带 UI、密钥或部署逻辑。
2. 每次读写都绑定 `merchant_id` 和 `store_id`；同一存储适配器中的不同商户必须隔离。
3. 采购录入必须在一个事务中增加库存、保存采购记录并生成借贷平衡的记账分录。
4. 下单必须使用内核商品价格，原子校验并扣减库存，重复幂等请求不能重复扣减；V1 订单保持未付款。
5. 商户可替换存储适配器、UI 主题和私有插件，公共内核升级不能覆盖这些边界。
6. 消费者 AI 能力映射必须复用同一内核，不另写一套订单逻辑；经营动作仍受平台授权和一次性确认约束。
7. ERP 发布清单必须可选绑定确定的运行时包和版本，初始化 Matter 合同必须把绑定传给开发代理。

## 非目标

- 不声称已经把 `cofficethinking` 或其他商户项目迁移到新内核。
- 不提供生产 PostgreSQL、SQLite 或第三方 ERP 适配器。
- 不处理真实支付、退款、履约、税务或完整会计期间结账。
- 不接入美团、抖音、京东或淘宝闪购生产 API。

## 验收标准

- Node 测试覆盖商户隔离、采购双分录、幂等冲突、订单库存原子回滚和开放商业映射。
- Rust 测试覆盖运行时绑定校验和物化合同透传。
- JSON 合同样例声明公共内核包且旧发布清单仍可读取。
- 源码体积、文档模块化、Rust 格式和项目门禁通过。
