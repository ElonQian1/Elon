# 开放商业开发者 Webhook 回调验证 V1 验收

## 当前状态

`implementation_uncompiled`

本批次仅形成代码并执行格式化与仓库文档门禁，尚未编译、构建或向真实 HTTPS 端点发起验证。

## 已形成代码

- V146 为既有订阅兼容回填验证状态，新订阅改为待验证且停用。
- 5 分钟随机 challenge、与正式事件相同的 HMAC 请求头及精确回显协议。
- HTTPS 白名单、禁止重定向、5 秒连接、10 秒总请求和 16 KiB 响应上限。
- 网络、HTTP、响应读取、响应大小、JSON 和 challenge 不匹配的稳定失败码。
- 验证成功才激活，并从成功时的终态序号开始，不补发验证前历史。
- PC 门户提供待验证、验证失败、已验证状态和显式验证按钮。

## 统一回归必须验证

- V145 到 V146 升级、重复迁移和既有订阅兼容回填。
- 新订阅在验证前不会产生可领取投递，手动启用未验证订阅失败关闭。
- challenge 请求的 Rust 签名可被 Node SDK 验证，合法回显通过，篡改、过期和错误密钥拒绝。
- 重定向、非白名单、超时、超大响应、非 JSON、错误 challenge 和各种 HTTP 状态。
- 验证与 App 停用、订阅停用、活动订阅上限及同时验证的事务竞争。
- PC 类型、渲染、错误状态和小屏布局。

- 生产 App 审核、组织身份认证、跨运营方密钥互认和证书自动轮换。
