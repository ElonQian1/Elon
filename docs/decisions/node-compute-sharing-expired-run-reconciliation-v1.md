# 节点推理过期执行回收 V1

状态：已接受并实现
日期：2026-08-02

## 决定

服务端周期性回收超过可续期租约且仍未收到可信终态事件的节点推理。回收在同一数据库事务中读取并把执行证明置为失败，随后按原调用编号幂等释放消费者预授权。

## 状态边界

1. `started`：节点执行中，必须通过服务端流收集器持续续租。
2. `usage_received`：服务端已收到匹配请求编号的终态事件并冻结实际 Token，异步记账尚未完成；不再占执行并发，也不参与执行租约回收。
3. `verification_pending`：现有 PC CLI 的人工核验非终态，仍允许进入最终终态。
4. 其余结算、失败或释放状态均为不可变终态，迟到结果不得覆盖。

## 回收规则

- 默认每 30 秒扫描，`NODE_LLM_LEASE_RECONCILE_SECS` 可调整但不得低于 5 秒。
- 只回收 `server_node_llm` 且仍为 `started`、最近续租时间超过 120 秒的运行。
- 回收状态为 `failed`，结算状态为 `expired_released`，保留零实际用量和错误原因。
- 数据库事务决定执行终态；账单释放使用已有幂等调用编号，重复扫描不重复退款。
- 服务重启时同时失败关闭 `started` 与 `usage_received`，因为内存中的流收集或异步结算任务均已丢失。

## 不做的事

- 不把迟到的节点结果当成成功，不补记提供者收益。
- 不自动执行 SLA 赔付、节点罚款、声誉扣分、提现或链上交易。
- 不回收 `pc_agent_cli` 或其他异构任务，它们使用各自的恢复与核验流程。
