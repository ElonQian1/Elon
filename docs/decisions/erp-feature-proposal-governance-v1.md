# ADR：ERP 通用功能提案治理 V1

- 状态：已接受
- 日期：2026-08-01

## 背景

AI 在帮助商户开发时最早看到功能缺口，但它不能仅凭一次对话决定修改所有商户共享的内核。需求中还可能含有经营数据、客户隐私、密钥或私有源码。

## 决策

1. 需求先与能力目录匹配，结论限定为已有能力、能力组合、私有扩展或通用候选。
2. 只有商户明确授权，AI 才可提交结构化需求信号。
3. 信号采用字段白名单，禁止原始数据、密钥、个人信息、源码和附件；平台保存脱敏摘要与计数证据。
4. 使用规范化 `need_key` 聚合，同一实例对同一需求只计一次。
5. 达到多个独立实例支持的阈值后，提案可进入 `candidate`，但仍不会自动接受。
6. 蓝图维护者可接受或拒绝提案；接受后才在蓝图项目的 AI 开发频道创建正式 Matter。
7. Matter 继续遵守既有分工、审查、合并和发布门禁。

## 非目标

- 不根据聊天频率自动改公共内核。
- 不让 AI 自动合并或发布。
- 不把商户原始经营数据作为提案证据上传。
