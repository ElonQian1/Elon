# ADR：ERP 商户实例初始化 Matter V1

- 状态：已接受
- 日期：2026-08-01

## 背景

创建商户实例后若直接复制公共仓库、自动执行迁移或发布，平台会混淆治理登记与真实工程执行，也可能覆盖商户已有项目。仅保存一条实例记录又无法让项目 AI 知道应按哪个版本、模块和扩展边界开始工作。

## 决策

1. 实例默认产生新的独立平台项目；也允许操作者通过明确的目标项目 ID，把自己有编辑权的现有项目纳入 ERP 治理。系统项目、蓝图自身和已绑定项目不得作为目标。
2. 同名项目不能被名称猜测复用。无论新建还是纳入现有项目，实例都只登记固定版本、配置和来源模式，不自动复制源码；登记失败不得清理现有项目。
3. 商户可显式创建初始化 Matter。Matter 包含蓝图标识、源 Git 提交、主题、公共模块、行业插件、私有扩展边界和验收条件。
4. Matter 与实例在同一事务中通过 `bootstrap_matter_id` 关联；重复请求返回同一 Matter。
5. API 从项目已授权节点选择 Bot 生成计划角色。商户批准并启动 Matter 后，现有群体 AI 流程再生成 Assignment。
6. Matter 继续要求人工合并和发布；没有可用 Bot 时只保存计划，不伪造已执行状态。
7. Matter 计划保存 `yilong.erp.materialization_contract.v1`，固定源提交、目标项目、配置修订、模块与扩展边界，以及要求的实例清单和证据格式。
8. 物化状态从现有 Matter、Assignment 和 Artifact 实时派生，不建立第二套任务状态表。失败沿原 Assignment 重试；实例修订或证据不一致必须显示为阻塞，不得伪造完成。
9. 商户配置修订导致合同漂移时，再次显式确认初始化会创建替代 Matter，并在新旧 Matter 记录审计事件；旧 Matter 正在执行或等待验收时禁止覆盖。
10. 带 `execution_contract` 的 Matter 启动前必须已有项目成员批准记录；自动派发和直接启动均不得绕过该门禁。未携带合同的既有 Matter 保持原兼容行为。
11. 对 `existing_project`，物化合同和 Matter 必须先要求盘点已有能力、迁移、测试与私有扩展，只补齐缺口，并明确禁止用空白模板覆盖现有代码。

## 结果

蓝图治理与真实工程执行通过现有 Matter/Assignment 流程衔接，同时保持项目、数据、代码和发布权属于商户。未来可替换具体的源码初始化器，但不得绕过实例修订、项目权限和人工发布门禁。
